# FlowCanvas — 中文产品与设计规范 v4

## 一、产品边界

FlowCanvas 由两个严格隔离的工作域组成：

1. **流程配置中心**：定义元数据字段、节点数据结构、内置驱动方案、节点默认驱动绑定和流程页面，最后发布不可变配置快照。
2. **流程执行页**：从已发布快照创建执行实例，独立打开并维护运行字段值、节点生命周期、关注状态和驱动器计算状态。

配置中心导航只包含“元数据、节点数据、驱动方案、流程页面”。执行实例不在配置导航中。执行页面也不能出现配置中心的四步导航，只能查看只读配置快照。

学习计划仅作为示例数据；底层模型必须适用于项目交付、内容生产、审批和巡检等其他场景。所有可见界面使用简体中文，只有稳定键、对象代码、版本和 JSON/YAML 保留英文。

## 二、完整数据模型

### 2.1 元数据字段 MetaField

元数据就是可复用字段定义，类似数据库字段：

- `fieldKey`：稳定唯一键，例如 `title`、`description`、`duration`、`documents`。
- 基础名称、数据类型、校验规则、默认值、输入组件和帮助文字。
- 数据类型包含文本、多行文本、数字、布尔、日期、日期时间、时长、枚举、链接、文件、对象和列表。
- 元数据只定义字段本身，不决定它属于哪个节点。

### 2.2 节点数据 NodeSchema

节点数据是元数据字段的集合，代表一种节点可以保存的数据结构：

- `nodeSchemaId`、名称、版本和说明。
- `fieldBindings[]` 引用一个或多个 MetaField。
- 每个字段绑定可覆盖展示名称、必填、默认值、字段顺序和执行时组件。
- 同一个 `title` 在学习任务节点可显示“任务名称”，在内容节点可显示“内容标题”，稳定键保持不变。
- `defaultDriverBinding` 可为空；为空代表该节点数据结构默认使用人工生命周期。

示例“学习任务”包含：任务名称 `title`、任务描述 `description`、在线文档 `documents`、预计时长 `duration`、任务列表 `taskItems`。

### 2.3 驱动方案 DriverDefinition

第一版提供三个内置、可配置但不可脚本扩展的主驱动方案：

- **时间驱动**：根据开始时间、持续时长和临期阈值计算等待开始、进行中、临期与超时。
- **条件驱动**：根据节点字段、比较符和目标值计算激活状态，并可显式配置自动完成。
- **事件驱动**：处理应用内事件与导入事件日志，不接收公网 Webhook。

DriverDefinition 声明：输入槽位、每个槽位的数据类型、允许来源、默认来源、输出状态以及是否支持自动完成。驱动方案本身不直接拥有节点字段。

### 2.4 驱动绑定 DriverBinding

每个 NodeSchema 最多有一个默认主驱动绑定，每个 FlowNode 运行时也最多解析出一个主驱动：

- `driverCode`：选中的 DriverDefinition。
- `inputBindings`：驱动输入槽位与具体来源的完整映射。
- 输入来源只能是 `field` 节点字段、`system` 系统上下文或 `constant` 固定值。
- 驱动器所有必需输入必须拥有来源并通过类型校验；有默认来源的槽位直接展示默认来源，不出现未解析空值。
- 选择了驱动器但必需输入缺失、字段类型不兼容或覆盖绑定不完整时，禁止保存和发布。
- `completionPolicy` 默认为人工完成；只有驱动器声明支持且用户显式选择时才能自动完成。

时间驱动默认绑定示例：

- `startAt ← system(previous.completedAt + 1 day)`。
- `duration ← field(duration)`。
- `dueSoonThreshold ← constant(24h)`。

三个必需输入均已解析，没有空映射。

### 2.5 流程节点 FlowNode 与流程定义 FlowDefinition

流程页面负责组合节点和连线，不保存执行状态：

- FlowNode 引用一个确定版本的 NodeSchema。
- `driverMode = inherit | override | none`。
- `inherit` 使用 NodeSchema 的完整默认绑定。
- `override` 整套替换 driverCode、inputBindings 和 completionPolicy，不进行部分合并。
- `none` 不使用驱动器，采用默认人工生命周期。
- 开始是内置元节点，始终为流程第一个节点。
- 流程支持必经、可选、参考、条件分支、子流程和异常路径。

### 2.6 发布快照 FlowVersion

点击“发布配置”生成不可变 FlowVersion，固化元数据版本、NodeSchema 版本、驱动定义版本、最终 DriverBinding、流程拓扑和默认值。后续配置修改不影响已有执行实例，配置工作到发布完成为止。

### 2.7 执行实例 FlowRun

FlowRun 从 FlowVersion 创建：

- 每个 NodeRun 保存字段实际值、生命周期、关注状态、时间线、执行证据和 DriverRunState。
- 生命周期：未开始、等待开始、进行中、受阻、已完成、已跳过。
- 关注状态：正常、即将到期、已超时；它不覆盖生命周期。
- 无驱动器节点在前序满足后进入进行中，由执行人手动完成。
- 驱动器控制激活和状态；完成默认人工，显式自动完成除外。
- 驱动配置结构完整但执行字段值为空时，节点进入受阻并指出缺失字段；补值后重新计算，禁止静默降级。
- 无服务端时，应用打开期间定时计算；关闭期间不驻留，重新打开后按当前时间和导入事件日志追算。

## 三、完整数据流

配置总览必须使用真实 SVG 箭头呈现以下非线性关系：

`MetaField → NodeSchema`；`DriverDefinition → DriverBinding ← NodeSchema`；`NodeSchema + DriverBinding → FlowNode → FlowDefinition → FlowVersion → FlowRun → NodeRun + DriverRunState`。

明确区分：

- **结构配置流**：元数据 → 节点数据；驱动方案 + 节点数据 → 默认驱动绑定；节点数据 + 最终驱动模式 → 流程定义 → 发布快照。
- **运行数据流**：发布快照 → 执行实例 → 节点字段值、生命周期、关注状态和驱动计算。
- FlowVersion 与 FlowRun 之间使用明显的“发布边界”；只有已发布快照能创建执行实例。

## 四、配置中心页面

### 4.1 配置数据流总览

首版核心稿，1600×1000：

- 顶部显示“FlowCanvas · 配置中心”、当前方案“学习计划示例”、导航“元数据 / 节点数据 / 驱动方案 / 流程页面”、校验配置和发布配置。
- 页面标题“配置数据流”，副标题“从字段定义到可执行快照”。
- 主区使用精确对象关系图，而不是线性步骤卡：MetaField、NodeSchema、DriverDefinition、DriverBinding、FlowNode、FlowDefinition、FlowVersion、FlowRun、NodeRun、DriverRunState。
- 配置域与运行域有可见分区，FlowVersion 与 FlowRun 之间有发布边界。
- 点击任意对象卡，下方关系详情更新为来源、产生的数据、校验规则和去向。
- DriverBinding 详情展示时间驱动真实映射：前序完成次日、`duration`、固定 24h，所有必需槽位均显示“已解析”。
- 底部完整性检查：字段引用、字段类型、驱动输入、覆盖完整性、孤立节点、流程入口和版本状态。
- 发布配置先打开校验结果；全部通过后显示“配置版本 v1.0 已发布”，并提供在新页面打开执行实例的次级操作。

### 4.2 节点数据页面

- 左侧为 NodeSchema 列表；中央为字段集合表；右侧为结构预览、版本和引用流程。
- 页签：字段结构、默认驱动、使用情况、版本记录。
- 默认驱动页签采用四步编辑：选择驱动方案 → 逐槽位选择来源 → 类型与完整性校验 → 人类可读规则预览。
- 不使用驱动器是合法选项；一旦选择驱动器，保存按钮在所有必需输入解析前保持禁用。
- 提供添加已有元数据、创建元数据、字段排序、展示名覆盖和保存新版本。

### 4.3 驱动方案页面

- 只展示和配置内置 DriverDefinition，不在这里绑定具体 NodeSchema。
- 展示时间、条件、事件三张方案卡以及输入契约、允许来源、默认来源、输出状态、自动完成能力和使用数量。
- 时间驱动详情展示 startAt、duration、dueSoonThreshold；条件驱动展示 operand、operator、target；事件驱动展示 eventType 和事件日志来源。
- 事件驱动明确标注“本地事件 + 导入日志”“关闭期间重开追算”“不支持公网 Webhook”。

### 4.4 流程页面

- 画布节点选择 NodeSchema，不复制字段定义。
- 节点检查器显示字段集合、默认驱动以及 `inherit / override / none` 三种模式。
- override 打开完整绑定编辑器；不允许只覆盖一个槽位后继承其他槽位。
- 校验缺失驱动输入、类型错误、孤立节点和入口错误；通过后才能发布。

## 五、独立执行页面

- 顶部只显示“FlowCanvas · 执行实例”、返回实例列表、实例名称、运行编号、生命周期、同步状态、查看配置快照和更多操作。
- 不显示元数据、节点数据、驱动方案和流程页面导航。
- 左侧为本实例节点列表或缩略流程；中央为运行流程图和当前任务；右侧为运行字段、驱动计算、生命周期时间线和执行证据。
- 查看配置快照以只读抽屉打开，不进入编辑状态。
- 完成开始元节点后：无延迟人工节点立即进行中；配置次日开始的时间节点先进入等待开始。
- 时间节点支持模拟正常、临期不足一天和已超时，生命周期与关注状态同时展示。
- 运行字段缺值时显示受阻、缺失字段和补值入口；补值后重新计算。

## 六、必须实现的原型交互

1. 数据流对象卡选择与关系详情更新。
2. 节点数据默认驱动选择、来源种类切换、必需输入校验、禁用保存和规则预览。
3. 流程节点在 inherit、override、none 之间切换；override 必须完整配置。
4. 发布前校验、发布成功和独立打开执行页。
5. 独立执行页完成开始节点、时间等待、临期/超时模拟、缺值受阻与补值重算。
6. 所有状态同时使用文字、图标和颜色。

## 七、视觉语言

- Neural Noir 工具型界面；背景 `#070807`，画布 `#090B0E`，面板 `rgba(13,16,20,.94)`。
- 默认边框 `rgba(255,255,255,.11)`，主金色 `#A78B71`，浅金 `#C9B8A0`。
- 当前/临期 `#F4B942`，完成 `#55D6A7`，可选 `#7FB6B2`，错误/超时 `#F36B6B`。
- 主文本 `#F4F1EB`，次文本 `#A5A7AE`，弱文本 `#6B7079`。
- 中文字体 `Inter`, `PingFang SC`, `Microsoft YaHei`, sans-serif；键、ID 和表达式使用 `IBM Plex Mono`, monospace。
- 控件圆角 10px，对象卡和节点 14px，浮层 18px；克制阴影和清晰 1px 边框。
- 禁止蓝紫渐变、装饰性衬线字体、库存图片和营销页面布局。

## 八、硬约束

- 元数据等于字段定义；节点数据等于字段集合。
- 节点可以没有驱动器；有驱动器时所有必需输入必须完整解析且类型兼容。
- 每个流程节点最多一个主驱动。
- 流程页面不保存运行状态；配置工作止于发布快照。
- 执行实例使用独立页面外壳，不属于配置导航。
- 完整数据流必须使用可见连线呈现，不能降级为纯说明卡片。
- 使用本文件规定的中文文案、字体、色彩、间距和组件风格。
