# 07 · UI 设计规范

> 文档状态：v0.2（2026-08-11 重写）——组件库选定 antd v6，规范本体收敛为「主题映射 + 偏离项 + 自定义组件」；外壳改左右布局；引入面板原语体系。逐页 UI 设计（§9）逐页补充。
> 依赖：[05-产品规格](05-产品规格.md)。分工：05 定义页面**有什么、能干什么**（功能规格），本文档定义**长什么样、怎么交互**（视觉与交互设计）。

## 1. 设计原则

- **仅浅色主题，不做明暗切换**（00 决策 19）；撞色语言全站统一：深色侧栏 × 浅色主区。
- 状态一律**文字 + 图标 + 颜色**三通道，色弱可用。
- 克制阴影、清晰 1px 边框；禁止蓝紫渐变、装饰性衬线字体、库存图片和营销页布局。
- 桌面优先：最优 1600+，最小支持宽度 1280（低于出横向滚动，不做布局降级）；移动端适配阶段三。
- **组件库优先**：能由 antd 主题 token 达成的一律走 token，不写自定义样式；偏离与自研组件必须在 §8 登记。

## 2. 组件库与主题

### 2.1 选型（00 决策 35）

- **Ant Design v6**（查证时最新 6.6.0，2026-08-10）+ `@ant-design/icons` 6.x（版本须与 antd 大版本一致）。
- v6 要求 React ≥ 18；默认 CSS 变量模式（仍有 CSS-in-JS 运行时，`zeroRuntime` 配置可去运行时、改手动引入 CSS，起骨架时评估）。
- 实施前按全局查证规约复核版本与 token 名（结论存记忆 `component-lib-research`，2026-08-11 官方文档核实）。

### 2.3 已知摩擦点与覆盖方案

1. **圆角三级分档**：Card / Modal / Popover / Dropdown / Drawer 共用 `borderRadiusLG`，且 seed=10 时派生为 12（源码 `genRadius.ts`：6 ≤ base < 16 时 LG = base + 2）。方案：`components.Card.borderRadiusLG = 14`、浮层类组件 `borderRadiusLG = 18` 逐组件作用域覆盖。
2. **手调色不命中派生值**：`colorPrimaryHover` / `colorPrimaryBg` / `colorErrorBg` 三个 map token 须显式写死（仍属纯 token 操作，不写自定义 CSS）。
3. **浮层阴影 token 变更**：v6 中 Popover 阴影已改为 `dropShadowPopover`（CSS filter），非 v5 的 `boxShadowSecondary`；定制阴影须按组件逐个核对。
4. **v6 DOM 与 API 变更**：v6 大改组件 DOM、弃用 100+ API。本项目从 v6 起步无迁移包袱，但任何针对内部节点的自定义 CSS 都须按 v6 结构编写。

- 中文字体 `Inter, PingFang SC, Microsoft YaHei, sans-serif`；字段键、ID、结构预览用 `IBM Plex Mono, monospace`。

## 5. 面板原语与组合规则（00 决策 36）

全站一切容器——侧边栏、主区、列表面板、编辑面板、执行页三栏、抽屉、模态——都是**同一原语的配置差异**，不存在「页面类型学」。

### 5.1 面板原语 Panel

- **高度撑满父容器**；纵向三段式：
  - **头部**：固定不滚，可省略；
  - **主体**：滚动区，**必有**；
  - **底部**：固定不滚，可省略。
- 头/底与主体之间以 1px `--border` 分隔线相隔，分隔线**横贯面板全宽**。
- 头、底高度不设全局定值，由内容物按 padding 规范撑开（外壳的侧栏头与右侧头部除外，见 §6）。
- **宽度模式**只有两种：固定值 或 flex 占满剩余。

### 5.2 皮肤三档

| 皮肤 | 规格 |
|---|---|
| `card` | 白底 `--surface` + 1px `--border` + radius 14 + 面板阴影（§6.5）+ 内 padding 16 |
| `dark` | 侧栏色系（§3 的 sidebar 三色） |
| `plain` | 无底色无边框的结构容器（如右侧主区） |

### 5.3 组合规则

- 横向组合**最多三栏**；相邻面板间距 **16**。
- 承载面板的容器 padding **16**。
- 允许嵌套（面板主体内再放横向面板组合），实践深度 **≤ 2**。

### 5.4 浮层同构

抽屉与模态是面板原语的**浮层形态**：继承三段式与头/底固定规范，差异仅在圆角档（18）、遮罩与定位。弹层四级分工（§7.4）只管**用途归属**，结构规范不再单写。

### 5.5 实例对照

| 实例 | 头部 | 主体（滚动） | 底部 | 宽度 / 皮肤 |
|---|---|---|---|---|
| 侧边栏 | logo + 应用名 | 菜单 | 收起/展开按钮 | 固定 240（收起 64）/ `dark` |
| 右侧主区 | 页面头部 | 页面内容 | 省略 | flex / `plain` |
| 元字段·列表面板 | 搜索 + 类型筛选 | 字段列表 | 新建按钮 | 固定 320 / `card` |
| 元字段·编辑面板 | 字段名 + 引用徽标 | 表单 | 保存 / 删除操作条 | flex / `card` |
| 画布页 | 页面头部 | 画布（不滚动，平移缩放；检查器为浮动 `card` 面板） | 省略 | flex / `plain` |
| 抽屉 / 模态 | 标题 + 关闭 | 内容 | 动作条（可省） | 浮层 / `card`（radius 18） |

## 6. 控制台外壳（00 决策 37）

### 6.1 结构

```
┌──────────┬─────────────────────────────────┐
│ 侧边栏    │ 右侧头部（固定，高 60）           │
│ 240 固定  ├─────────────────────────────────┤
│ 全高      │ 主内容区（--bg，padding 16）      │
│          │   面板组合置于其中，各自内滚        │
└──────────┴─────────────────────────────────┘
```

- 左右两栏：左侧栏**固定宽全高**，右侧 flex 占剩余。
- **页面级永不滚动**，一切滚动发生在面板主体内。

### 6.2 侧边栏（`dark` 面板）

| 段 | 规格 |
|---|---|
| 头部 | 高 **60**（与右侧头部同高，共享 y=60 水平线）；34px logo 方块 + 应用名「FlowCanvas」；padding 16 |
| 主体 | 六项菜单（图标 + 文字），内滚；激活态 `--sidebar-active` |
| 底部 | 高 **56**；仅放收起/展开按钮 |
| 右缘 | border-right 1px `--border` + 骨架阴影（§6.5） |

### 6.3 收起态（收起能力自阶段三提前入 MVP，修订 00 决策 17）

- 宽度 **240 ⇄ 64**，切换带 150ms 宽度过渡。
- 收起后：菜单仅留图标居中，hover 出 tooltip 显示名称；头部仅留 34px logo 居中，应用名隐去；底部按钮变为居中图标。
- 激活态左缘 3px `--primary` 两态都保留。
- **菜单图标**：六项各配一枚 `@ant-design/icons` 图标（收起态唯一辨识依据，展开态也显示）；具体图标名起骨架时选定并回填。
- 状态存 `appSettings` 跨会话记忆；**仅手动触发**，不做窄屏自动收起（最小支持宽 1280，无响应式需求）。

### 6.4 右侧头部与槽位规则

| 项 | 值 |
|---|---|
| 高度 | **60** 固定，白底 `--surface` |
| 内 padding | 左右 16 |
| 下缘 | border-bottom 1px `--border` + 骨架阴影（§6.5） |

槽位自左至右：

```
[页面标题区] ·············· [页面动作槽] │ [同步徽标] [⋯]
                                       ↑ 1px 分隔，高 20
```

- **页面标题区**、**页面动作槽**：内容逐页定义（§9）。
- **工作空间簇**永远钉在最右角，跨页位置恒定：同步状态徽标（[05 §9.6](05-产品规格.md) 九态映射）+ `⋯` 更多菜单（导出 `.flowpack` / 导入 `.flowpack`；后续工作空间级操作也归此菜单）。

### 6.5 间距 · 线条 · 阴影 · 滚动条

**间距**

| token | 值 | 用途 |
|---|---|---|
| `space/xs` | **4** | 图标与文字、徽章内 padding 等最小间隙 |
| `space/sm` | **8** | 控件内元素间距、紧凑行内间隙 |
| `space/md` | **12** | 输入框左右内 padding、按钮内 padding |
| `space/inner` | **16** | 主内容区 padding（即面板与侧栏、与头部的间距）、面板内 padding、头部左右 padding |
| `space/panel-gap` | **16** | 横向相邻面板之间 |
| `space/field-gap` | **16** | 表单字段行之间 |

> 后三者当前同值（`panel-gap` 于 2026-08-11 由 24 收窄为 16），保留独立 token 以便日后分化。
> **一切间距取自本表**，不得出现表外数值（7 / 10 / 18 / 20 / 22 之类）——2026-08-11 首轮 token 绑定即因稿中散落此类值而无法绑定。

**线条**：一切边框与分隔线 1px；默认 `--border`，hover / 强调 `--border-strong`；面板头/底分隔线横贯全宽。

**阴影（三级）**

| 级 | 值 | 用途 |
|---|---|---|
| 骨架级 | `0 2px 6px rgba(38,36,32,0.13)` | 右侧头部向下、侧栏向右 |
| 面板级 | `0 2px 8px rgba(38,36,32,0.13)` | `card` 皮肤面板 |
| 浮层级 | `0 8px 24px rgba(38,36,32,0.16)` | 模态 / 抽屉 / 下拉（antd 浮层阴影 token 按此覆盖，色相调暖） |

**focus 态**：边框转 `--primary` + 外圈 2px `rgba(138,111,82,0.18)` 光晕；错误态下 focus 光圈改用错误红，直至校验通过。

**滚动条**：宽 8px；滑块 `--scrollbar-thumb`（hover `--scrollbar-thumb-hover`）、radius 4；轨道透明；无箭头。`dark` 皮肤内滑块改 `--scrollbar-thumb-dark`。Firefox 走 `scrollbar-width: thin`。色值见 §3.2——**滑块取主色派生**，与暖色系统一。

## 7. 全局交互范式

### 7.1 保存模型（混合）

- **表单类显式保存**（元字段、节点模型、驱动绑定）：编辑产生脏标记，点保存落库；「必需槽位未解析禁止保存」由保存按钮禁用逻辑承载。
- **流程画布即时自动保存**：增删节点、连线、拖动位置即时写入草稿——草稿允许不完整，发布门全量校验兜底。
- 关闭带脏标记的表单页给未保存确认。

### 7.2 撤销/重做

画布结构操作支持 `Ctrl+Z / Ctrl+Y`（会话级内存栈，不持久化）；表单类不做 undo（显式保存天然可弃改）。

### 7.3 校验反馈三级

1. **字段级**：失焦即时标红（必填、正则、类型）。
2. **对象级**：点保存时汇总（驱动槽位完整性等）。
3. **流程级**：发布时全局校验面板（六层全跑）。

画布上节点校验问题实时显示角标（如缺驱动输入）。

### 7.4 弹层四级分工

| 载体 | 用途 |
|---|---|
| 整页 | 控制台六页、执行页 |
| 抽屉（右侧滑出） | 只读快照查看、节点详情速览、引用清单 / 影响提示 |
| 模态 | 发布校验与确认、冲突三选一、破坏性确认（删节点、删实例、断开云、导入替换工作空间）、新建实例 |
| Toast | 保存成功、同步完成等瞬时反馈，**不承载错误详情** |

判据：需要对照上下文看的用抽屉，需要打断决策的用模态。结构规范见 §5.4。

## 8. 组件规范

### 8.1 已拍板的控件约束

- boolean 运行字段用**三态控件**（未设置 / 是 / 否）；空输入保存 = 显式清空（[01 §2.5](01-领域模型与协议.md)）。
- 受阻补值表单**预填快照默认值**作建议（仅建议，保存才落日志）。
- `link` 仅 `https / http / mailto` 渲染为可点击链接，其余纯文本；helpText / description 一律纯文本（[01 §2.6](01-领域模型与协议.md)）。
- 完成度显示格式「完成 3/5 · 跳过 2」，分母不含跳过（[02 §8](02-状态引擎规范.md)）。
- 导入 = 替换工作空间的破坏性确认模态，含「已自动备份」提示（[04 §3](04-存储与同步规范.md)）。

### 8.2 按钮体系

### 9.1 元字段页（骨架定稿 2026-08-10，外壳与控件 2026-08-11 更新）

- **面板组合**：右侧主区内两个 `card` 面板——列表面板（固定 320）+ 编辑面板（flex）。
- **列表面板**：头 = 搜索 + 类型筛选；主体 = 字段列表（内滚）；底 = 「新建元字段」按钮。
- **编辑面板**：头 = 字段名 + 引用计数徽标（点击开引用清单抽屉）；主体 = 表单（720 宽居中，内滚）；底 = 「保存」+「删除」操作条。
- **页面头部槽位**：标题区 = 「元字段」；页面动作槽 = 空（新建入口在列表面板底部）。
- **编辑区字段序**：字段键 → 名称 → 数据类型 → 类型参数（enum 选项行 / list 子项类型 / number 精度与单位）→ 校验规则构建器 → 默认值 → 帮助文字。
- **精度与单位控件**（number 专属，[01 §2.7](01-领域模型与协议.md)）：精度 = 0–6 步进器（默认 0）；单位 = 三态选择「无 / 纯标注（文本框）/ 时间单位组（下拉选 分钟/小时/天/周）」。
- **字段键控件**：始终可编辑（mono 字体），保存时唯一性校验；改键不断引用（关联走生成 ID，00 决策 31），无锁定态。
- **数据类型控件**：随时可改；已被引用时修改后弹影响提示（复用引用清单抽屉）。
- **校验规则构建器**：规则行列表——「添加规则」下拉只给该类型的合法规则，每行 = 规则名 + 参数控件 + 删除。
- **默认值控件**：按类型渲染，皆含「未设置」态（boolean 即三态控件，01 §2.5）。
- **不做**：object / list(object) 内部结构编辑（在节点模型页子组装，00 决策 29）；`inputComponent` 暴露（MVP 按类型默认控件）。
- 待补：空态设计、列表项信息密度。

## 11. Figma 工作流

### 11.1 组件库：`Ant Design System - v6`（AntUIKit）

- 副本 fileKey `85BxV83FJxRMq32fLiP5bj`（社区源 file/1574139834768289607），kit v1.0.7 / antd 6.x，CC BY 4.0 + 可商用可改、禁转售。
- 89 页全解锁，347 个 Component Set；FlowCanvas 必需 28 项中 26 项可用。**缺口**：Grid 无组件（需自搭 24 栅格）、List 被标废弃（antd v6 已废弃）。

### 11.2 一次性准备

1. **移出 Drafts**：Drafts 里的文件无法发布为库，先把 kit 副本 Move to project（放进团队项目）。
2. **先改主题、再发布**：发布后再改，消费方要走一轮 library update，已放置的实例可能弹出 review changes。
3. **发布**：打开 kit 文件 → 主菜单 → Libraries → 当前文件那一栏 Publish → 勾选 Components / Text styles / Effect styles / Variables。
4. **启用**：打开 `FlowCanvas UI` → Libraries 面板 → 打开刚发布的库。
5. **验收**：Assets 面板出现该库分组；变量选择器里能选到它的集合。

### 11.3 用组件

- Assets 面板 → 展开库 → 按页名分组 → 拖 Component Set 入画布。
- 状态切换**一律走变体属性下拉**（Button：`Variant` / `Size` / `State` / `Shape` / `Disabled` / `Icon Only`），**不要手改颜色**。
- 文本与图标走组件属性（如 Button 的 `Text`、`Icon Placement Start/End`）。
- **禁止 Detach instance**——脱离后与库断联，改主题不再传播。

### 11.4 改主题变量

- **消费方无法编辑库变量**（教育版无 Extended collections，那是 Enterprise 功能）；在 `FlowCanvas UI` 里看到的 kit 变量是只读的。
- 改主题必须回 **kit 源文件**：右栏空选 → Local variables → 对应集合（`seed` / `map` / `alias` / `components`…）→ 改值 → Libraries 面板 Publish 更新 → 消费文件按提示更新。
- kit 每个集合都有 Light / Dark 两个 mode，本项目仅用 Light，改值时注意别改错列。

### 11.5 扩充自有变量

- FlowCanvas 独有语义**留在本地集合 `FlowCanvas Tokens`**（kit 完全没有这些）。
- **本地变量可别名到库变量，反向不行**：新建本地变量 → 点其值 → 在选择器切到库集合 → 选中目标。以此让 `color/primary` 指向 kit 种子色，做到单一真相源。
- 新增变量沿用既有规约：`/` 分组命名、设 WEB code syntax（`var(--xxx)`）、写中文描述、不用 `ALL_SCOPES`。

### 11.6 分工纪律

| 归属 | 内容 |
|---|---|
| **kit 变量** | antd 标准控件外观：主色与错误色派生、圆角、控件高、字体、控件内间距 |
| **`FlowCanvas Tokens`** | kit 没有的：侧栏三色、六组状态色、中性填充组、滚动条、侧栏宽度、头部高度、面板间距 |

### 11.7 换肤要点（依 kit 实测）

**四个杠杆点，各改一个变量即全局生效**：`seed/borderRadius` 6→10（4027 节点）、`map/borderRadiusLG` 8→14（5498 节点）、`seed/controlHeight` 32→36（803 节点）、`seed/fontFamily` "SF Pro"→"Inter"（2135 节点 + 全部 17 个文字样式）。

**约 43 个色变量须逐个手填**：kit 的 Primary / Error / Info 派生色在 `map` 层是扁平硬值、未接色阶（仅 Success / Warning 是别名）。

**两处无杠杆**：① 浮层圆角 18——kit 无独立浮层档（Tooltip/Popover 绑控件档、Modal/Drawer/Dropdown 绑面板档），需征用空置的 `map/borderRadiusXL` 并手动重绑组件四角，与 §2.3 摩擦点 1 同源；② `seed/fontFamilyCode` 节点绑定数为 0，IBM Plex Mono 只能逐处手动指定。
