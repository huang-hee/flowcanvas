### 1.3 已知摩擦点与覆盖方案

1. **圆角分档**：Card / Modal / Popover / Dropdown / Drawer 共用 `borderRadiusLG`，且 seed=10 时派生为 12（源码 `genRadius.ts`：6 ≤ base < 16 时 LG = base + 2）。方案：`components.Card.borderRadiusLG = 14`（面板档）、悬浮浮层类组件 `borderRadiusLG = 8`（浮层档）逐组件作用域覆盖。**抽屉是例外**——antd `Drawer` 源码不设任何 border-radius（整个 `drawer/style/index.ts` 中 border-radius 只出现一次，给关闭按钮的 `borderRadiusSM`），且单个 token 无法只圆两角，故需自定义样式，见 §6 偏离项 2。
2. **手调色不命中派生值——刻意偏离，非将就**（2026-08-11 用 `@ant-design/colors@8.0.1` 与 antd 6.6.0 `theme.getDesignToken()` 实证，ΔE 为 CIEDE2000）：

   | token | 算法输出 | 本规范 | ΔE | 结论 |
   |---|---|---|---|---|
   | `colorPrimary` | `#8A6F52` | `#8A6F52` | 0.00 | 种子原样透传，无修正 |
   | `colorPrimaryHover` | `#968671` | `#74593F` | **17.62** | 完全不同色 |
   | `colorPrimaryBg` | `#C9C6BD` | `#F1EAE0` | **8.69** | 完全不同色 |
   | `colorErrorBg` | `#FFF4F0` | `#FAE9E6` | 3.33 | 明显可辨 |

   两条根因：
   - **hover 方向相反**。antd 约定「悬停变浅、按下变深」——算法 hover 明度 +8.5pp；本规范为「悬停变深」，−8.0pp。交给算法会把全站主按钮的手感翻转。
   - **低饱和种子的浅阶会被算法去饱和成中性灰**。`#8A6F52` 饱和度仅 25.5%，经 `saturationStep` 递减并触发源码钳制后，第 1 阶落到 S=10% 的 `#C9C6BD`（近中性灰），而本规范要的是 S=37.8% 的暖米 `#F1EAE0`。

   故 **map token 一律显式写死**（仍是纯 token 操作，不写自定义 CSS）。

   > 附带事实：antd 的 `generateColorPalettes` 把 key 8/9/10 回折复用 idx 4/5/6，故 `colorPrimaryText*` 与 `colorPrimaryHover` / `colorPrimary` / `colorPrimaryActive` **同色**——10 个 map token 实际只需 **7 个不同色值**。依据 `themes/shared/genColorMapToken.ts` 与 `themes/default/colors.ts`（v6.6.0）。
3. **浮层阴影 token 变更**：v6 中 Popover 阴影已改为 `dropShadowPopover`（CSS filter），非 v5 的 `boxShadowSecondary`；定制阴影须按组件逐个核对。
4. **v6 DOM 与 API 变更**：v6 大改组件 DOM、弃用 100+ API。本项目从 v6 起步无迁移包袱，但任何针对内部节点的自定义 CSS 都须按 v6 结构编写。

### 1.4 token 单源纪律（00 决策 40）

**凡 antd / kit 已有的量，一律引用 antd token 名，本地不留同值副本**——避免改主题时两处不同步。

| 归属 | 内容 |
|---|---|
| **antd / kit 变量** | 圆角四档（徽章 / 控件 / 面板 / 浮层）、控件高、字体、主色与错误色派生、**遮罩 `colorBgMask`** |
| **`FlowCanvas Tokens`（本地）** | kit 没有**或无法绑定**的：**全部间距档**、胶囊圆角、侧栏三色、六套状态色阶、中性填充组、滚动条四色、侧栏宽度与收起宽度、头部与侧栏底部高度、面板间距 |

规范文本中提到几何量时写 antd token 名（`borderRadiusLG`、`controlHeight` 等）；提到本地语义量时写 `--xxx`。

> **间距为何留在本地**（2026-08-11 实测修正）：kit 的 `map/size*`（sizeXXS 4 / sizeXS 8 / sizeSM 12 / size 16）数值虽与 §4 间距表一一对上，但其 **scope 是 `WIDTH_HEIGHT`，绑不到 padding / itemSpacing 上**；kit 其余间距量（`inputPaddingHorizontal`、`buttonPaddingHorizontal`）是组件专属、语义不匹配。故 `space/*` 五档**全部保留本地**——本条推翻本表初稿把「控件内间距」划归 kit 的写法。
> **胶囊圆角同理**：kit `map/borderRadiusFull` = 9999、`static/borderRadiusMax` = 100，与本规范的 999 均不同值，保留本地 `radius/pill`。

**已完成的去重**（2026-08-11）：`radius/control` → `seed/borderRadius`、`radius/panel` → `map/borderRadiusLG`、`radius/overlay` → `map/borderRadiusXL`、`radius/badge` → `map/borderRadiusSM`、`size/control-height` → `seed/controlHeight` 五个本地变量已改绑并删除，共 **461 处绑定 / 108 个节点**，本地集合由 55 降至 50 个。

### 2.4 主色与错误色完整色阶

antd 的 10 个 `colorPrimary*` / `colorError*` map token 实际只落在 **7 个色值**上（§1.3），下表即 Figma kit 与代码 `theme.token` 的**填充真相源**。锚定项为既有 token，其余在 OKLCH 感知均匀空间补齐（相邻 ΔE2000 极差 ≤ 2%）。

| 序 | 主色 token | 值 | | 错误色 token | 值 |
|---|---|---|---|---|---|
| 1 | `colorPrimaryBg` | `#F1EAE0` ⚓ | | `colorErrorBg` | `#FAE9E6` ⚓ |
| 2 | `colorPrimaryBgHover` | `#D5C6B2` | | `colorErrorBgHover` | `#F0C5BD` |
| 3 | `colorPrimaryBorder` | `#BCA58A` | | `colorErrorBorder` | `#E29C90` |
| 4 | `colorPrimaryBorderHover` | `#A28869` | | `colorErrorBorderHover` | `#D27465` |
| 5 | `colorPrimaryHover` | `#74593F` ⚓ | | `colorErrorHover` | `#A5392C` |
| 6 | `colorPrimary` | `#8A6F52` ⚓ | | `colorError` | `#C24E3F` ⚓ |
| 7 | `colorPrimaryActive` | `#5B412A` | | `colorErrorActive` | `#82241A` |

- `colorPrimaryTextHover` / `colorPrimaryText` / `colorPrimaryTextActive` 分别**等于**第 5 / 6 / 7 阶（antd 回折复用）；错误色同理。
- **方向**：`Hover` 比基色**更深**、`Active` 更深（与 antd 默认的「悬停变浅」相反，§1.3）。两套色的「基色→Hover」ΔE 均为 8.3，按下手感一致。
- 彩度处理：主色浅阶加了中段彩度隆起（否则 HSL 饱和度掉到 20% 出头会发灰）；错误色用纯线性（其锚点彩度本就高，加隆起会推成糖果粉）。

**无障碍**：`colorPrimary` 对白底 4.69:1（AA 过）、对应用底 `#FAF8F5` **4.43:1**（差 0.07 未达 AA 正文）。故**链接色不用基色，用 `--primary-hover` `#74593F`**（对应用底 6.11:1，AA 稳过），即 antd 的 `colorLink` 系一律指向该值。`colorPrimaryActive` / `colorErrorActive` 对白底达 AAA。

同法构建，锚点取 §2.2 的 fg 与 tint。`info` **不挂主色**——主色是暖金棕、与琥珀同族，挂上去后 antd Alert 的 warning 与 info 底色 ΔE 仅 3.4，同组件内两种语义肉眼难辨；改走中性档后四型两两可辨。

|---|---|---|---|---|

| 2 BgHover | `#C1E1CF` | `#E3D0AC` | `#C6C2BB` | `#BFD8D5` |
| 3 Border | `#95CBAE` | `#D0B07D` | `#A49F97` | `#96BEBA` |
| 4 BorderHover | `#66B48B` | `#BF924E` | `#878279` | `#6EA6A1` |
| 5 Hover | `#008656` | `#956300` | `#59554C` | `#2E7973` |
| 6 基色 | `#2F9E6C` ⚓ | `#B07818` ⚓ | `#6F6A61` ⚓ | `#47908A` ⚓ |
| 7 Active | `#006942` | `#754C00` | `#423D35` | `#095F5A` |

- `info` 锚点取 `--fill-muted` 与 `--text-secondary`；基色对白底 5.37:1。
- 连同 §2.4 的主色与错误色，全系统共 **6 套 7 阶**；各套 tint 坡道相邻 ΔE2000 在 8.47–10.88 区间、等距偏差 ≤ 4.1%。
- **已知边际项**：warning 与 info 的 Bg 仍是六对里最低的 ΔE 5.1（两锚点色相同为 H84.6，是给定锚点下的数学上限）；但其 Border 阶 15.8、基色阶 23.8，加上图标与文字三通道，实际可辨。不为此调整既有 token。

### 7.5 扩充自有变量

- FlowCanvas 独有语义**留在本地集合 `FlowCanvas Tokens`**（kit 完全没有这些）。
- **本地变量可别名到库变量，反向不行**：新建本地变量 → 点其值 → 在选择器切到库集合 → 选中目标。
- 新增变量沿用既有规约：`/` 分组命名、设 WEB code syntax（`var(--xxx)`）、写中文描述、不用 `ALL_SCOPES`。

> **实测教训 · 改绑远端库变量**（2026-08-11）：必须在**每一次** `use_figma` 调用内重新 `importVariableByKeyAsync`。否则 `getVariableByIdAsync` 对远端库变量返回 `null`，而 `setBoundVariable(field, null)` 的语义是**解绑**——会静默掉光绑定，且因字面值不变、外观零异常而极难察觉（首轮改绑即因此掉了全部 461 处绑定，按值重建后逐页核对数量才发现）。改绑后务必按页复核绑定数。

> **实测教训 · 渐变色标绑不了带透明度的变量**（2026-08-12）：给渐变色标绑色变量时，Figma **连 alpha 一并取自变量**——空态插画的落影渐变绑定前 alpha 为 `[0.48, 0.12]`，绑上不透明的 kit 变量后变成 `[1, 1]`，透明度落差被抹平。故**带透明度落差的渐变色标只能保留字面值**，并在组件 description 里注明原因。纯色标（无 alpha 变化）不受影响，可正常绑定。

> **实测教训 · `setBoundVariableForPaint` 返回冻结对象**（2026-08-12，同日修正）：其返回的 paint 是冻结的，**直接赋 `opacity` 无效**（遮罩曾因此整块不透明）。正确做法是展开成新对象再写回整个 `fills` 数组，绑定后务必读回复核 opacity。
> **它对 `opacity` 的真实行为是「覆盖为变量色的 alpha」，不是「重置为 1」**——初次记录的「重置为 1」只是绑定了 alpha=1 变量时的特例。实证：给 `.Backdrop` 绑 alpha=.45 的 `colorBgMask` 时，显式写入的 `opacity=1` 被 Figma 改写成 `0.45`。**推论**：想保留 paint 自身的透明度落差，就不能绑带 alpha 的色变量（与「渐变色标」那条同源）。
> 另注：**kit 源文件内的变量是本地变量**（`remote: false`），上一条「每次 `importVariableByKeyAsync`」的教训只适用于**消费文件**引用远端库变量的场景，在 kit 内部不适用。

> **kit `Table` 组件集的真实限制**（2026-08-12 取证修正——**此前记的「宽度锁死、列宽拒绝覆盖」是误判**）：
> - **没有锁定**：所受检节点 `locked` 全为 `false`，6 个 `Table Column` 为 `layoutPositioning=AUTO` + `lsh=FIXED`，其 `.Header Cell` 与 10 个 `.Body Cell` 全为 `lsh=FILL`——**改列宽会自动带动该列表头与全部单元格**。
> - 「改了没反应」的真实成因是 **`header` / `first` 帧为 `HUG`**：宽度由子列算出，直接给帧设宽会被立刻重算回去（1255 = 48+162+248+267×3 减去列间距，是**算出来的**不是设定值）。**正确用法是逐列 resize，并同步把根节点宽度改为各列之和**，否则右侧留白。
> - 演示内容也不构成障碍：表头文案是 TEXT 属性 `Title#4653:181`；`NICE / DEVELOPER / DESIGNER` 只是 `Type=Tag` 列的产物，把该列 `Type` 切成 `Text` 即整体消失；`.Body Cell` 另有 `Content Type=Slot` 变体可 instance swap 装任意内容。
> - **真限制是数量**：**列数固定 6、每列行数固定 10**，只能 `visible=false` 隐藏、不能新增（实例不可 `appendChild`）。**仅当列数超过 6** 时才改用多个 `Table Column` 实例拼装。

**kit 结构性限制**（非缺陷，记录备查，不修）：

- `Menu - Dark` **无 collapsed 变体**，且菜单项数固定不可增删——收起态只能隐藏 `title-content` + 主轴改 CENTER 模拟；`Inline` 模式只有 5 项且第 2 项自带弹出子菜单，故取 `Mode=Vertical` + 每项 `Inline=True`。
