## 1. 组件库与主题

### 1.1 选型

- **Ant Design v6** + `@ant-design/icons` 6.x（版本须与 antd 大版本一致）。
- v6 要求 React ≥ 18；默认 CSS 变量模式（仍有 CSS-in-JS 运行时，`zeroRuntime` 配置可去运行时、改手动引入 CSS）。
- **组件库优先**：能由主题 token 达成的一律走 token，不写自定义样式；偏离必须登记进 §6。

### 1.3 必须显式覆盖的 map token

antd 的色板算法在两处不命中本规范，**map token 一律显式写死**（仍是纯 token 操作，不写自定义 CSS）：

| token | 算法输出 | 本规范 | ΔE2000 |
|---|---|---|---|
| `colorPrimary` | `#8A6F52` | `#8A6F52` | 0.00（种子原样透传） |
| `colorPrimaryHover` | `#968671` | `#74593F` | 17.62 |
| `colorPrimaryBg` | `#C9C6BD` | `#F1EAE0` | 8.69 |
| `colorErrorBg` | `#FFF4F0` | `#FAE9E6` | 3.33 |

两条根因：

- **hover 方向相反**。antd 约定「悬停变浅、按下变深」（算法 hover 明度 +8.5pp）；本规范为「悬停变深」（−8.0pp）。
- **低饱和种子的浅阶会被算法去饱和成中性灰**。`#8A6F52` 饱和度仅 25.5%，第 1 阶落到 S=10% 的近中性灰，而本规范要的是 S=37.8% 的暖米。

> antd 的 `generateColorPalettes` 把 key 8/9/10 回折复用 idx 4/5/6，故 `colorPrimaryText*` 与 `colorPrimaryHover` / `colorPrimary` / `colorPrimaryActive` **同色**——10 个 map token 实际只需 7 个不同色值。

### 1.4 token 归属（单源纪律）

**凡 antd 已有的量，一律引用 antd token 名，本地不留同值副本。**

| 归属 | 内容 |
|---|---|
| **antd / kit 变量** | 圆角三档、控件高、字体、主色与错误色派生、遮罩、**chrome 全部配色**（侧栏底、头部底、菜单四态、收起按钮） |
| **`FlowCanvas Tokens`（本地）** | 全部间距档、自有面板圆角 `radius/panel`、胶囊圆角 `radius/pill`、六套状态色阶、中性填充组、滚动条两色（浅色档 thumb 与 hover——深色档随决策 41 一并删除）、侧栏宽度与收起宽度、头部与侧栏底部高度、面板间距 |

> **chrome 配色全部由 antd token 承载**，本地不再持有 `--sidebar-*` 一族——浅色 chrome 的每一项都能在 `Layout/*` 与 `Menu/*`（浅色档）里找到对位。唯一的例外是「选中项左缘 3px」，antd 无此物，走 `--primary` + 自定义样式（§6 偏离项 1）。
> **antd 的 dark 主题本项目不使用**：`Menu/dark*` 与 `Layout/siderBg` 等 dark 档一律保持 antd 官方默认，不改不维护。

规范文本中提到几何量时写 antd token 名，提到本地语义量时写 `--xxx`。

> **间距为何在本地**：kit 的 `map/size*` 数值虽与 §4 一一对上，但 scope 是 `WIDTH_HEIGHT`，**绑不到 padding / itemSpacing**；其余间距量是组件专属、语义不匹配。
> **胶囊圆角同理**：kit `borderRadiusFull` = 9999、`static/borderRadiusMax` = 100，与本规范的 999 均不同值。

> **危险按钮 hover 描边不设本地 token**：它的值 `#D27465` 就是错误色阶第 4 阶 `colorErrorBorderHover`（§2.4），按 §1.4 单源纪律直接引用 antd token 名。此处曾误立过一个 `--danger-border-hover` 本地副本，已撤销。

### 2.4 主色与错误色完整色阶

antd 的 10 个 `colorPrimary*` / `colorError*` map token 实际只落在 **7 个色值**上。锚定项为既有 token，其余在 OKLCH 感知均匀空间补齐（相邻 ΔE2000 极差 ≤ 2%）。

| 序 | 主色 token | 值 | | 错误色 token | 值 |
|---|---|---|---|---|---|
| 1 | `colorPrimaryBg` | `#F1EAE0` ⚓ | | `colorErrorBg` | `#FAE9E6` ⚓ |
| 2 | `colorPrimaryBgHover` | `#D5C6B2` | | `colorErrorBgHover` | `#F0C5BD` |
| 3 | `colorPrimaryBorder` | `#BCA58A` | | `colorErrorBorder` | `#E29C90` |
| 4 | `colorPrimaryBorderHover` | `#A28869` | | `colorErrorBorderHover` | `#D27465` |
| 5 | `colorPrimaryHover` | `#74593F` ⚓ | | `colorErrorHover` | `#A5392C` |
| 6 | `colorPrimary` | `#8A6F52` ⚓ | | `colorError` | `#C24E3F` ⚓ |
| 7 | `colorPrimaryActive` | `#5B412A` | | `colorErrorActive` | `#82241A` |

- `colorPrimaryTextHover` / `colorPrimaryText` / `colorPrimaryTextActive` 分别**等于**第 5 / 6 / 7 阶（antd 回折复用）；错误色同理。
- **方向**：`Hover` 比基色更深、`Active` 更深（与 antd 默认相反）。两套色的「基色 → Hover」ΔE 均为 8.3，按下手感一致。
- 主色浅阶加了中段彩度隆起（否则饱和度掉到 20% 出头会发灰）；错误色用纯线性。

**无障碍**：`colorPrimary` 对白底 4.69:1、对应用底 `#FAF8F5` 仅 **4.43:1**（未达 AA 正文）。故**链接色不用基色，用 `--primary-hover` `#74593F`**（对应用底 6.11:1），antd 的 `colorLink` 系一律指向该值。

### 2.5 语义色阶（success / warning / info / optional）

同法构建，锚点取 §2.2 的 fg 与 tint。**`info` 不挂主色**——主色是暖金棕、与琥珀同族，挂上去后 Alert 的 warning 与 info 底色 ΔE 仅 3.4，同组件内肉眼难辨；改走中性档后四型两两可辨。

| 序 | success（已完成） | warning（进行中·临期） | info（中性通知） | optional（可选） |
|---|---|---|---|---|
| 1 Bg | `#E6F4EC` ⚓ | `#F8EFDD` ⚓ | `#F0EDE7` ⚓ | `#E7F1F0` ⚓ |
| 2 BgHover | `#C1E1CF` | `#E3D0AC` | `#C6C2BB` | `#BFD8D5` |
| 3 Border | `#95CBAE` | `#D0B07D` | `#A49F97` | `#96BEBA` |
| 4 BorderHover | `#66B48B` | `#BF924E` | `#878279` | `#6EA6A1` |
| 5 Hover | `#008656` | `#956300` | `#59554C` | `#2E7973` |
| 6 基色 | `#2F9E6C` ⚓ | `#B07818` ⚓ | `#6F6A61` ⚓ | `#47908A` ⚓ |
| 7 Active | `#006942` | `#754C00` | `#423D35` | `#095F5A` |

- 全系统共 **6 套 7 阶**；各套 tint 坡道相邻 ΔE2000 在 8.47–10.88 区间、等距偏差 ≤ 4.1%。
- **已知边际项**：warning 与 info 的 Bg 是六对里最低的 ΔE 5.1（两锚点色相同为 H84.6，给定锚点下的数学上限）；其 Border 阶 15.8、基色阶 23.8，加上图标与文字三通道实际可辨。

**状态语义的文字一律取色阶第 7 阶（Active）**——已完成 `#006942`、进行中 `#754C00`、受阻 `#82241A`、可选 `#095F5A`、中性 `#423D35`。基色（第 6 阶）留给图标、边框与实心填充；tint（第 1 阶）作底色。

> 依据：基色压在自身 tint 上一律不达 AA（2.94–4.01，12px 小字需 ≥ 4.5）；取 Active 阶后实测 5.97 / 6.59 / 8.06 / 6.52 / 9.21，**六种状态语义全部达标**，而色块与图标观感不变。

## 3. 排版与几何

### 3.1 字体与文字层级

中文字体 `Inter, PingFang SC, Microsoft YaHei, sans-serif`；字段键、ID、结构预览用 `IBM Plex Mono, monospace`。

文字样式**不含颜色**，配色按用途另取色板 token；行高为显式定值。

| 样式 | 字体 | 字重 | 字号 / 行高 | 用途 |
|---|---|---|---|---|
| `text/title-lg` | Inter | 600 | 18 / 26 | 编辑面板头部对象名 |
| `text/title` | Inter | 600 | 16 / 24 | 应用名、页面标题 |
| `text/body-strong` | Inter | 500 | 14 / 22 | 列表项主名、区块标题、分段选择器选中段 |
| `text/body` | Inter | 400 | 14 / 22 | 正文、输入框值、菜单项、下拉选项、占位符 |
| `text/label` | Inter | 400 | 12 / 18 | 表单标签、徽章文字（配 `--text-secondary`） |
| `text/help` | Inter | 400 | 12 / 18 | 帮助 / 错误文字（配 `--text-faint` 或错误红） |
| `text/mono` | IBM Plex Mono | 400 | 14 / 22 | 输入框内 mono 值（字段键、ID） |
| `text/mono-sm` | IBM Plex Mono | 400 | 13 / 20 | 下拉内类型名、规则行参数 |
| `text/mono-xs` | IBM Plex Mono | 400 | 12 / 18 | 列表行副标题、结构预览 |
| `text/mono-badge` | IBM Plex Mono | 400 | 11 / 16 | 类型徽章 |

### 3.2 圆角

**antd 三档是 size 阶梯**，谁吃哪一档由 antd 自己接线，**不按语义指派、不做覆盖**：

| 用途 | 值 | 来源 |
|---|---|---|
| 小号控件 / 徽章 | **4** | `borderRadiusSM` |
| 控件（按钮 / 输入框 / 下拉框） | **6** | `borderRadius`（seed） |
| 大号控件 / antd `Card` | **10** | `borderRadiusLG` |

**不吃 antd 阶梯的三档**：

| 用途 | 值 | 来源 |
|---|---|---|
| FlowCanvas 自有 `card` 皮肤面板 | **12** | 本地 `radius/panel` |
| 悬浮浮层（模态 / 下拉面板 / 气泡 / 通知） | **8** | `borderRadiusXL` |
| 抽屉 | **左侧两角 8，右侧两角 0** | 同上 + 自定义样式（§6 偏离项 2） |
| 胶囊（引用计数徽标） | **999** | 本地 `radius/pill` |

> **一切徽章 / 徽标一律取徽章档 4**——类型徽章、节点状态徽章（已完成 / 进行中 / 受阻 / 可选 / 未开始）、同步状态徽标全都是。**胶囊 999 只留给引用计数徽标**：它是纯数字计数，圆形感成立；带文字的徽章做成药丸会跟按钮抢视觉重量。

> **档位不按大小递进是刻意的**：浮层 8 比自有面板 12 更方——浮层是「压在页面之上的一张纸」，收敛的圆角让它读起来更规整。

**浮层档在代码里的落地方式因组件而异**（antd 各组件读的 token 不同，写错不生效）：

| 组件 | 落地写法 |
|---|---|
| Modal / Select 下拉 / Dropdown / Popover / Popconfirm / Message / Notification / DatePicker 面板 | `components.X.borderRadiusLG = 8` |
| **Tooltip** | **`components.Tooltip.borderRadius = 8`** —— antd Tooltip 读的是 `borderRadius`（`tooltipBorderRadius: borderRadius`），**不读 `borderRadiusLG`**，写 LG 不生效 |
| **Drawer** | **只能自定义 CSS** —— antd `Drawer` 源码不设任何 border-radius（§6 偏离项 2） |

> antd 支持逐组件覆盖 `borderRadiusLG`：`ComponentsConfig` 类型为 `ComponentToken & AliasToken & { algorithm }`，`AliasToken` 含 `borderRadiusLG` / `controlHeight`，TS 合法无需 `as any`。
> **待实证的机制风险**：组件级覆盖走 CSS 变量作用域、变量挂在组件根类上，按级联规则**嵌套在内部的组件会继承**——模态内的 `Card` 可能拿到 8 而非 10。起骨架时须运行时实测。

### 3.3 控件高

控件高 **32**（`controlHeight` seed），派生 `controlHeightXS` 16 / `SM` 24 / `LG` 40——按钮、输入框、下拉框等基础控件。

## 4. 间距 · 线条 · 阴影 · focus · 滚动条

**间距**

| token | 值 | 用途 |
|---|---|---|
| `space/xs` | **4** | 图标与文字、徽章内 padding 等最小间隙 |
| `space/sm` | **8** | 控件内元素间距、紧凑行内间隙、筛选表单行间距 |
| `space/md` | **12** | 输入框左右内 padding、按钮内 padding、筛选表单列间距 |
| `space/inner` | **16** | 主内容区 padding、面板内 padding、头部左右 padding |
| `space/panel-gap` | **16** | 相邻面板之间（横向与纵向） |
| `space/field-gap` | **16** | 表单字段行之间 |

> **一切间距取自本表**，不得出现表外数值（7 / 10 / 18 / 20 / 22 之类）——表外值无法绑定 token。

**线条**：一切边框与分隔线 1px；默认 `--border`，hover / 强调 `--border-strong`；面板头 / 底分隔线横贯全宽。

> **画在 chrome 底上的线一律取 `--border-strong`**——`--border` `#E6E1D8` 是照内容区底 `#FAF8F5` 定的，压到更深的 chrome 底 `#F0EDE7` 上只剩 1.09:1，1:1 下几乎不可见；`--border-strong` `#D5CEC2` 约 1.24:1，读得出且不抢戏。侧栏右缘与底部分隔线都归此例。

**阴影（三级）**

| 级 | 值 | 用途 |
|---|---|---|
| 骨架级 | `0 2px 6px rgba(38,36,32,0.13)` | chrome 向内容区投影，见下 |
| 面板级 | `0 2px 8px rgba(38,36,32,0.13)` | `card` 皮肤面板 |
| 浮层级 | `0 8px 24px rgba(38,36,32,0.16)` | 模态 / 抽屉 / 下拉 |

**chrome 投影的方向与范围**（骨架级）——三者构成单向 z 序「侧栏 > 头部 > 内容」：

| 投影 | 范围 |
|---|---|
| 侧栏向右 | **贯穿全高**（含头部所在的顶部区段）——侧栏压在头部之上 |
| 头部向下 | **仅侧栏右侧那一段**，不越过侧栏 |
| 侧栏内部 | **不投影**；头部与主体之间不画线（避免与右侧头部读成一体），**仅底部与主体之间 1px `--border-strong`**——底部工具条常驻不随主体滚动，须与滚动区断开（[08 §2.2](08-交互规范.md)） |

**focus 态**：边框转 `--primary` + 外圈 2px `rgba(138,111,82,0.18)` 光晕；错误态下 focus 光圈改用错误红，直至校验通过。

**滚动条**：宽 8px；滑块 `--scrollbar-thumb`（hover `--scrollbar-thumb-hover`）、radius 4；轨道透明；无箭头。`dark` 皮肤内滑块改 `--scrollbar-thumb-dark`。Firefox 走 `scrollbar-width: thin`。

## 5. 按钮体系

尺寸单一档：高 `controlHeight`、圆角控件档、文字 `text/body`（400，对齐 antd 的 `fontWeightNormal`）。

|---|---|---|
| 主按钮 Primary | 底 `--primary`、字 `--text-on-primary`、无描边 | 底 `--primary-hover` |

## 6. antd 偏离项清单

| # | 偏离 | 说明 |
|---|---|---|
| 1 | **侧栏选中项左缘 3px 主色** | 外壳用 `<Layout.Sider theme="light">` + `<Menu theme="light">`；左缘 3px 非 antd Menu 标准样式，须叠加图层实现 |

| 4 | **按钮 hover 变深** | 全站「悬停变深」，与 antd「悬停变浅」相反——由 map token 显式写死实现，非自定义 CSS |

## 7. Figma 资产使用

### 7.1 组件库

**`Ant Design System - v6`（AntUIKit）** —— 副本 fileKey `85BxV83FJxRMq32fLiP5bj`，kit v1.0.7 / antd 6.x，CC BY 4.0 + 可商用可改、禁转售。89 页全解锁，347 个 Component Set。

**缺口与结构性限制**（使用时必须知道）：

- **无 `Grid`** 组件（需自搭 24 栅格）；`List` 被标废弃。
- **无 `Form` 组件集**——表单级布局（栅格、标签列宽）在 Figma 里只能自拼。可用的是 `Form Item` 系列：标签走 `Form Item Label.Text`、必填星号走 `Form Item Label.Required`（渲染为 `.Required Mark`）、错误文案走 `.Form Item Help.ValidateStatus=error`（经 `.Form Item Footer.Extra` 露出）。**`Form Item` 自身没有 `required` / `validateStatus` 变体**，必填与校验态分处两地。
- **`Table`**：列数固定 6、每列行数固定 10，只能隐藏不能新增。**放进 `Table` 实例后列宽不可逐列自定义**——内层 `Table Column` 是 instance sublayer，`resize()` 静默无效、`minWidth`/`maxWidth` 直接报「cannot be overridden in an instance」。唯一可行解是**全列 `layoutSizingHorizontal='FILL'` 等宽均分**（只设部分列会让未设的列停在组件原宽 `48/162/248/267/267/267`，首列 48px 无法承载业务列）。要自定义列宽只能退回**散装 `Table Column`** 拼装（列 FIXED、单元格 FILL、`header`/`first` 帧 HUG 故须改列宽而非帧宽），代价是失去 `Table` 根组件语义。表头 `Title` 组件属性对 `Size=middle` 变体不生效（绑的是另一个节点），须直接写 `Header` 文本节点。单元格自带示例内容（`Content Type=Tag` 内置 3 个 Tag、`=Link` 内置 2 个 Link + 1 个 Dropdown Trigger），需逐格隐藏多余项；`Link` 无 disabled 变体，禁用态只能覆写文字色。
- **`Menu - Dark`** 无 collapsed 变体、菜单项数固定；`Current=True` 只改文字色无背景，激活底色须叠矩形。
- **`Pagination`** 无「`More=False` + `Changer/Jumper=True`」组合变体，取 `More=True` 后隐藏多余页码。
- **`Drawer Mask`** 自带一个 Drawer 实例，用作纯遮罩时需隐藏内嵌 Drawer。
- **`Tag`** 无胶囊 Shape 变体，胶囊形须在实例上把四角绑 `radius/pill`。
- **`Link`** 无 hover 下划线（`State=hover` 只改文字色，`textDecoration` 仍是 `NONE`）、也无 disabled 变体。稿子里下划线与禁用色都靠实例覆写表达，**不是变体能力**。另：`Table Column` 的 `Type=Link` 列只能内置 `Link` 实例，而代码里操作列是 antd `Button type="link"`——**同一个东西在稿子里由两个组件承担**，是 kit 与代码的语义错位。
- **实例不能 `appendChild`**——浮层内容一律经 `.Slot [Swap Me]` 做 instance swap 装入，这是扩展点，不算 Detach。

### 7.2 发布与启用

**前置**：kit 文件必须在**团队项目**下——Drafts 里的文件无法发布为库（消费文件在 Drafts 无妨）。
**顺序**：先改主题、再发布。

**发布端**（kit 文件）：

```
左上角 Figma 图标（主菜单）→ Libraries
  → 「Manage libraries」→「This file」标签页
  → 「Assets created in this file」右侧「Publish...」
  → 填 Description of changes（可选）→ 右下角「Publish」
```

对话框里**没有** Components / Variables / Styles 独立复选框，而是一个 `Changes (N of N)` 总开关 + 按资源类型分节，**默认全选**。

**发布是异步长任务**，toast 消失即结束、**没有成功弹窗**。唯一可靠判据：重开 Publish 对话框，`Changes` 分节消失、只剩 `Unchanged` 且按钮置灰。也可用 `getPublishStatusAsync()` 程序化复核是否全转 `CURRENT`。

**消费端**（`FlowCanvas UI`）：

```
主菜单 → Libraries →「Manage libraries」→「This file」
  → 「Libraries added to this file」：未启用的从左侧「Teams」找到后点「Add」
  → 「Updates」标签页 →（开「Show updates for all pages」）→ Update all
```

> 变量是**文件级**的，`Show updates for all pages` 只影响**组件实例**的列举范围。
> **未接受更新前，消费文件缓存的仍是旧值**——绑定正确但画布不变，属正常，不是改错了。

### 7.3 用组件

- Assets 面板 → 展开库 → 按页名分组 → 拖 Component Set 入画布。
- 状态切换**一律走变体属性下拉**，**不要手改颜色**；文本与图标走组件属性。
- **禁止 Detach instance**——脱离后与库断联，改主题不再传播。

### 7.4 改主题

- **消费方无法编辑库变量**；在 `FlowCanvas UI` 里看到的 kit 变量是只读的。
- 改主题必须回 **kit 源文件**：右栏空选 → Local variables → 对应集合（`seed` / `map` / `alias` / `components`…）→ 改值 → Publish → 消费文件接受更新。
- kit 每个集合都有 Light / Dark 两个 mode，**本项目仅用 Light**，改值时注意别改错列。

> ### ⛔ 只改值，不改接线
>
> **真实项目的主题是一份自定义 token 的 JSON 喂给 antd——只能改值，不能改接线。** 组件读哪个 token 由 **antd 源码**决定，配置层无从更改。
>
> **绝对禁止为了达成某个视觉值，把 kit 组件内部节点从 token A 改绑到 token B。** 后果：① 设计稿与代码渲染分道扬镳——Figma 里这个节点读 B，代码里 antd 仍读 A；② 组件被拉进本地项目后绑定关系全乱。
>
> **允许的三种动作**：
>
> 1. **改变量的值**——换肤的正途，也是主题工作的主要手段。
> 2. **纠正 kit 与 antd 不一致的接线**——kit 里某节点是裸值或绑错，而 antd 源码实际读某 token 时，把它绑上去是**让 Figma 对齐 antd**。判据：**能举出 antd 源码依据**。
> 3. **需要「同一 token 在不同组件取不同值」时，走 `components/*` 层变量**——对应代码里的 `theme.components.X.*` 覆盖。这是**值**的覆盖，接线没变。
>
> **配套流程**：改任何样式变量之前，**先报出「该变量影响哪些组件」**（依据 §8）。影响面不清楚就不动手——一个变量常常横跨十几个组件。
>
> **唯一已接受的破例**：浮层圆角 8 征用 `borderRadiusXL`（66 个节点，§6 偏离项 5）。记在案，不作为先例。

### 7.5 扩充自有变量

- FlowCanvas 独有语义留在本地集合 `FlowCanvas Tokens`。
- **本地变量可别名到库变量，反向不行**。
- 新增变量规约：`/` 分组命名、设 WEB code syntax（`var(--xxx)`）、写中文描述、**不用 `ALL_SCOPES`**（按用途设具体 scope）。

**三条实操约束**（违反会静默出错，外观无异常极难察觉）：

1. **改绑远端库变量时，必须在每一次脚本调用内重新 `importVariableByKeyAsync`**——否则 `getVariableByIdAsync` 返回 `null`，而 `setBoundVariable(field, null)` 的语义是**解绑**。改绑后务必按页复核绑定数。（kit 源文件内的变量是本地变量，此条只适用于消费文件。）
2. **`setBoundVariableForPaint` 返回冻结对象**，直接赋 `opacity` 无效；须展开成新对象再写回整个 `fills` 数组。它会把 `paint.opacity` **覆盖为变量色的 alpha**——想保留 paint 自身的透明度落差，就不能绑带 alpha 的色变量。
3. **渐变色标绑色变量时，alpha 一并取自变量**——带透明度落差的渐变色标只能保留字面值。
4. **INSTANCE 的 `children` 不枚举已隐藏的子节点**——一旦 `visible=false`，就无法再按索引找回。按索引批量隐藏会逐步错位误伤（实测把分页器的「跳至 / 页」一并隐藏了）。正解是**先取快照拿到全部子节点引用，再一次性隐藏**；已经错了用 `resetOverrides()` 复位。
5. **kit 私有组件（名字以 `.` 开头，如 `.Form Item Footer` / `.Form Item Help`）没有独立 library key**，`importComponentSetByKeyAsync` 报 not found。取用法：先建一个公开的 `Form Item` 实例 → 对其子实例 `getMainComponentAsync()` 拿到本地化的 COMPONENT → `createInstance()`。
6. **`setBoundVariableForPaint` 不会修正 paint 的字面色**——传 `{0,0,0}` 占位再绑变量，读回的字面色仍是 0（实测渲染成黑）。必须**同时写正确字面值再绑变量**。

> 上述 3–6 条与 §7.4 的绑定坑同属「静默出错、外观无异常」类，动手前先读一遍。
