# 04 · 存储与同步规范

> 文档状态：正式方案 v1.0（2026-08-09 评审定稿）
> 依赖：[01-领域模型与协议](01-领域模型与协议.md)、[03-发布与快照规范](03-发布与快照规范.md)

## 1. 分层架构

```text
packages/core（零浏览器依赖）
    │  只依赖接口，不知道 IndexedDB / Drive 的存在
    ▼
StorageAdapter 接口 ──► IndexedDBAdapter（apps/web，MVP）
                    ──► （未来）桥接适配器（webview 壳 / 原生存储）
SyncProvider 接口   ──► GoogleDriveProvider（阶段二）
                    ──► （未来）OneDrive / Dropbox / WebDAV
```

原则：**本地先落盘，云端后同步**。网络或授权失败不得导致本地修改丢失；换云平台只换 Provider，不动协议。

## 2. 本地存储 StorageAdapter

```ts
interface StorageAdapter {
  loadProject(projectId: string): Promise<ProjectAggregate | null>;
  saveObject(store: StoreName, value: unknown): Promise<void>;
  deleteObject(store: StoreName, key: string): Promise<void>;
  appendEvents(runId: string, events: EventEntry[]): Promise<void>;  // 只追加
  listEvents(runId: string, fromSeq?: number): Promise<EventEntry[]>;
}
```

### 2.1 IndexedDB 结构（apps/web）

数据库 `flowcanvas`，对象仓库：

| store | 主键 | 内容 |
|---|---|---|
| `project` | projectId | 项目元信息、默认设置（单项目应用：恒为一条记录，协议保留多项目兼容） |
| `metaField` | metaFieldId | 元字段 |
| `nodeSchema` | nodeSchemaId | 节点模型 |
| `flow` | flowId | 流程定义（草稿） |
| `flowVersion` | flowVersionId | 已发布快照（不可变） |
| `run` | runId | 实例元信息 + 物化投影缓存（可丢弃重建） |
| `runEvent` | [runId, seq] | 事件日志，只追加 |
| `viewState` | [flowId, viewId] | 画布节点位置、视口、折叠状态（表现层数据，不影响语义） |
| `syncBaseline` | projectId | 同步基线（§5.3） |
| `appSettings` | key | 应用设置、云连接状态（不含凭证明文，见 §6） |

驱动方案为内置常量，随代码发布，不入库。

## 3. `.flowpack` 导出与导入

**单 JSON 信封文件**（浏览器零 zip 依赖，人类可读），扩展名 `.flowpack.json`：

```jsonc
{
  "formatVersion": "1",             // 容器格式版本；未来含附件时升级为 zip 容器，靠此字段区分
  "exportedAt": "2026-08-09T12:00:00Z",
  "project": { "projectId": "…", "name": "…" },
  "metaFields": [ /* MetaField[] */ ],
  "nodeSchemas": [ /* NodeSchema[] */ ],
  "flows": [ /* FlowDefinition[]（草稿） */ ],
  "flowVersions": [ /* FlowVersion[]（已发布快照） */ ],
  "viewStates": [ /* 画布位置与视口，键 flowId+viewId */ ],
  "runs": [
    { "runId": "…", "flowVersionId": "…", "name": "…", "createdAt": "…",
      "eventLog": [ /* EventEntry[] */ ] }
  ]
}
```

规则：

- 导入即完整恢复项目（配置 + 快照 + 实例 + 日志），走全量 zod 校验后写入。
- **导入 = 整包替换当前工作空间**（单项目应用，00 决策 16；无论信封 `projectId` 是否与本地一致）：确认框（[08 §4.3](08-交互规范.md) 确认型）明示「将替换当前全部数据」，确认后**先自动把当前工作空间导出为备份 `.flowpack` 下载到本地**，再执行替换；「另存为副本」随未来多项目形态再议。
- **凭证、OAuth 令牌、本机路径等秘密永不进入信封**。
- YAML 仅作为配置的手写导入格式（元字段/节点模型/流程定义），转对象后同一校验；导出与同步一律 JSON。

## 4. 云同步模型（阶段二）

- **平台**：Google Drive，`appDataFolder`（应用专属隐藏目录），只申请 `drive.appdata` 最小权限。
- **同步单位**：快照模式——每项目一个文件 `project-<projectId>.flowpack.json`，整包上传/下载。
- **触发**：本地保存后防抖延迟上传；打开项目时检查远端；手动「上传 / 从云端恢复」；网络恢复提示继续。纯 Web 页面关闭后不保证后台同步。

### 4.1 SyncProvider 接口

```ts
interface SyncProvider {
  readonly providerId: string;
  connect(): Promise<void>;                     // OAuth 授权流程
  disconnect(): Promise<void>;
  getState(): Promise<"connected" | "disconnected" | "auth_expired">;
  download(path: string): Promise<{ content: Blob; revision?: string } | null>;
  upload(path: string, content: Blob, options: {
    expectedRevision?: string;                  // 条件写入：远端版本不符则失败
  }): Promise<{ revision?: string }>;
  stat(path: string): Promise<{ revision?: string; modifiedAt?: string } | null>;
}
```

## 5. 同步安全线（两级方案）

底线：**永不静默覆盖任何一方**。

### 5.1 一级：平台条件写入（待实测）

上传时携带 `expectedRevision`，由服务端在写入瞬间原子判断（HTTP 语义即 `If-Match` → 版本不符返回 412），彻底杜绝两台设备互相覆盖。

> ⚠️ **未确认**：Drive API v3 官方文档（v2/v3 对比页、`files.update` 参考页）中查不到条件写入参数，v2 时代的 etag 机制在 v3 未见对应物。实施前必须真实 API 实测；结论已存记忆（`gdrive-v3-conditional-write`）。

### 5.2 二级：读-比-写降级

平台不支持条件写入时：上传前 `stat` 远端 → 与基线比对 → 一致才上传。读与写之间存在小竞态窗口（单人多设备场景风险极低）；即使窗口内被覆盖，**下次同步必然发现分叉**并进入冲突处理，数据仍在（对方设备本地 + 冲突副本机制）。

### 5.3 同步基线与状态机

```ts
interface SyncBaseline {
  projectId: string;
  providerId: string;
  remotePath: string;
  remoteRevision?: string;          // 平台版本标识（若有）
  localContentHash: string;         // 上次同步时本地内容摘要
  remoteContentHash?: string;
  syncedAt: string;
}

type SyncStatus =
  | "disconnected" | "idle" | "dirty" | "syncing" | "synced"
  | "offline" | "conflict" | "auth_expired" | "error";
```

分叉判定：本地内容 ≠ 基线 **且** 远端内容 ≠ 基线 → `conflict`。

## 6. 冲突处理（MVP 三选一）

进入 `conflict` 后 UI 提供，且**系统不得超时自动选择**：

1. **保留本地**：本地覆盖远端，远端旧版另存为 `…(远端备份 <时间>)` 副本。
2. **保留远端**：远端覆盖本地，本地旧版另存为备份副本。
3. **双副本**：两个版本各保留为独立项目，用户手工取舍。

> 备注：单项目应用（00 决策 16）下「双副本 → 两个独立项目」不成立，阶段二实现时需降级方案（如远端版本导出为下载文件后由用户手工处理），届时定稿。

不做自动合并。基于事件日志的字段级/日志级智能合并是后期增强（事件溯源模型已为此留好地基）。

## 7. 认证与隐私边界

- OAuth 走浏览器授权流程，直连 Google，无自建服务端中转。
- 凭证只保存在本地受控存储；**永不进入** `.flowpack`、同步内容、日志或导出物。
- 授权过期 → `auth_expired` 状态，由用户重新连接；同步失败不影响本地读写。
- 用户可随时断开云连接并删除远端数据（提供入口）。
