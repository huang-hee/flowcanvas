### 1.3 kit 上游缺陷（本项目不修，记录备查）

- **13 个变体高度是裸字面值、完全未绑定**：`Input` 1 个、`Search` 9 个、`Input Addon` 3 个，内嵌 `Input` 实例卡在 35/39/42/46/51/52/59 上。这些值既不等于 36 也不等于 32，**改动前就是错的**。修它们要动 kit 组件节点接线，违反 07 §7.4，故不碰。
- **`.Number Action`** 的 small/large 是死变体——`Input Number` 所有 spinner 变体都固定引用其 `Size=Default`，给它绑高度会把 small spinner 从 27 撑到 36。
- `alias/fontStyle/reqularItalic` 变量名带 kit 原始拼写错误（`reqular`），集合里另有正名的 `regularItalic`，两者值相同，属上游冗余。
- `alias/colorWarningOutline` 仍是 antd 默认琥珀 `#faad14 α.1`，未跟随重配的 warning 色阶——日后要做 warning focus 态时这里是断点。
- `Drawer` 的 8 个 `Inline=True` 变体四角为 0 且未绑变量。inline 抽屉指 `getContainer` 指向父容器、只在局部区域滑出的形态；本项目抽屉一律浮层型全高，该变体不使用。
- kit 内存在一个名为 `" "`（单个空格）的已发布组件，发布后会以空白名进入资产面板。
- `.Slot [Swap Me]` 占位绑 `magenta/2`（填充）/ `4`（描边）/ `6`（文字与图标）。**刻意保留**——刺眼本身是「这里还没换内容」的提示。

## 2. kit 主题改动记录

### 2.1 已改动清单

**颜色**（值见 07 §2）：`map` 层主色 10、错误色 12、成功色 10、警告色 10、信息色 10——其中 success / warning 原为 `colors/green|gold` 色阶别名，已断开为扁平值。中性 8 项：`colorText` 四档、`colorBorder` 与 `colorBorderDisabled`、`colorBorderSecondary`、`colorBgLayout`。

## 3. 取证结论

### 3.1 antd 源码事实

| 事实 | 依据 |
|---|---|
| `Drawer` 面板**不设任何 border-radius** | `drawer/style/index.ts` 中 border-radius 仅出现一次，是关闭按钮的 `borderRadiusSM` |
| `Modal` 容器取 `borderRadiusLG`，header 顶部两角同档，footer 非 wireframe 模式为 0 | `modal/style/index.ts` |
| `Card` / `Modal` / `Popover` / `Dropdown` 共用 `borderRadiusLG` | `genRadius.ts`：6 ≤ base < 16 时 LG = base + 2 |
| `Empty.image` 类型为 `ReactNode`，`imageStyle` 已废弃（改用 `styles.image`） | Empty 组件文档 |
| `ConfigProvider.renderEmpty(componentName) => ReactNode` 可全局接管空态 | ConfigProvider 文档 |
| `Select.prefix` 类型 `ReactNode`，自 5.22.0 提供 | Select 组件文档 |
| `Modal.confirm` 原生布局 = 图标 + 标题一行、内容另起一行；默认宽 416、`closable: false`、`okType: primary`；`footer` 可定制 | Modal 组件文档 |
| `Table.size` 取值 `large / medium / small`，默认 `large`；`bordered` 默认 `false` | Table 组件文档 |
| `Drawer.getContainer` 默认 `body`，传 DOM 节点时须手动设 `rootStyle: {position:'absolute'}` | Drawer 组件文档 |

### 3.2 Figma 平台行为

- **改绑远端库变量必须每次重新 `importVariableByKeyAsync`**——否则 `getVariableByIdAsync` 返回 `null`，而 `setBoundVariable(field, null)` 的语义是**解绑**，会静默掉光绑定且外观无异常。曾因此掉光 461 处绑定。kit 源文件内的变量是本地变量，此条不适用。
- **`setBoundVariableForPaint` 返回冻结对象**，直接赋 `opacity` 无效；且它会把 `paint.opacity` **覆盖为变量色的 alpha**（不是「重置为 1」）。想保留 paint 自身的透明度落差，就不能绑带 alpha 的色变量。
- **渐变色标绑色变量时，alpha 一并取自变量**——带透明度落差的渐变只能保留字面值。
- **发布与接受更新只能走 Figma UI**，Plugin API 只有只读的 `getPublishStatusAsync`。
- **改变量值不会把组件标记为 `CHANGED`**——只有节点级编辑才会。判据：`Button` 吃了 `controlHeight` / `borderRadius` / `colorPrimary` 三项改动却仍是 `CURRENT`。
- Figma 变量 API 无阴影 / 排版类型——阴影与文字层级只能走**样式**，字号行高无法绑 token；圆角绑定须逐角设置。

### 3.3 kit `Table` 的真实限制

早期判断「宽度锁死、列宽拒绝覆盖」**是误判**。取证：所受检节点 `locked` 全为 `false`，6 个 `Table Column` 为 `AUTO` 定位 + `FIXED` 宽度，其 `.Header Cell` 与 10 个 `.Body Cell` 全为 `FILL`——改列宽会自动带动该列表头与全部单元格。

「改了没反应」的成因是 `header` / `first` 帧为 **HUG**：宽度由子列算出，直接给帧设宽会被重算回去（1255 是各列宽之和减列间距**算出来的**）。正确用法是**逐列 resize 并同步根节点宽度**。

演示内容也非障碍：表头文案是 TEXT 属性；`NICE / DEVELOPER / DESIGNER` 只是 `Type=Tag` 列的产物，切 `Type=Text` 即消失。

**真限制是数量**：列数固定 6、每列行数固定 10，只能隐藏不能新增。

## 4. 演进要点

- **UI 规范于 2026-08-11 拆为两册**：原《07-UI设计规范》按「值 vs 结构行为」拆为 07 与 08。
- **外壳几经反复**：全宽顶栏 → 左右布局（侧栏全高 + 右列头部）。侧栏收起态由阶段三提前进 MVP。
- **配置页范式几经反复**：master-detail（列表面板 + 编辑面板）→ 列表 + 抽屉 / 二级页。编辑载体按对象重量分档：元字段等轻对象走抽屉，节点模型等重对象走整页二级页。
- **圆角与控件高几经反复**：控件高 32 → 36 → 32；圆角三档 6/10/14 → 4/6/10；自有面板由「覆盖 `borderRadiusLG` 为 14」改为本地 `radius/panel` = 12；浮层 18 → 8。
- **引用清单载体几经反复**：抽屉 → 就地展开 → **模态**（现行）；入口由抽屉徽标改为表格「被引用」单元格。
- **空态插画**：弹窗卡片造型 → 卷纸造型（现行）；高度 240 → 160。
