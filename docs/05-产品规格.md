# 05 · 产品规格

> 文档状态：正式方案 v1.0（2026-08-09 评审定稿）
> 依赖：[01](01-领域模型与协议.md)–[04](04-存储与同步规范.md)；视觉语言承接 v4 设计规范（archive/design-system-v4.md）并按新术语更新。

## 1. 信息架构

两个严格隔离的页面外壳：

- **配置中心**：导航 = `总览 / 元字段 / 节点模型 / 驱动方案 / 流程页面`，顶部含当前项目名、校验配置、发布配置。执行实例不出现在配置导航。
- **执行实例页**：独立外壳，顶部只有「FlowCanvas · 执行实例」、返回实例列表、实例名、运行编号、生命周期、同步状态、查看配置快照、更多操作。**不出现**配置中心导航；配置快照以只读抽屉打开，不可进入编辑。

所有可见界面使用简体中文；稳定键、对象 ID、版本号与 JSON/YAML 保留英文。

## 2. 配置总览页

- 页面标题「配置数据流」，副标题「从字段定义到可执行快照」。
- 主区为**精确对象关系图**（真实 SVG 箭头，非线性步骤卡，不得降级为纯说明卡片）：`MetaField、NodeSchema、DriverDefinition、DriverBinding、FlowNode、FlowDefinition、FlowVersion、FlowRun、NodeRun`。
- 配置域与执行域有可见分区，FlowVersion 与 FlowRun 之间有明显**发布边界**。
- 点击任意对象卡 → 下方关系详情更新：来源、产生的数据、校验规则、去向。
- DriverBinding 详情展示时间驱动真实映射：`startAt ← system(previous.readyAt, +1 day)`、`duration ← field(duration)`、`dueSoonThreshold ← constant(24h)`，所有必需槽位显示「已解析」。
- 底部完整性检查：字段引用、字段类型、驱动输入、覆盖完整性、孤立节点、流程入口、发布状态。
- 「发布配置」先打开校验结果；全部通过后显示「配置版本 vN 已发布」，并提供在新页面打开执行实例的次级操作。

## 3. 元字段页

- 左侧元字段列表（按类型筛选）；中央编辑区：稳定键（创建后锁定）、名称、数据类型、枚举选项/列表子结构、校验规则构建器（[01 §2.1](01-领域模型与协议.md) 的声明式规则，表单化）、默认值、帮助文字。
- 右侧「使用情况」：引用本字段的节点模型与流程草稿清单（活引用影响提示的入口）。
- **被引用禁删**：删除按钮在存在引用时禁用并展示引用清单。

## 4. 节点模型页

- 左侧 NodeSchema 列表；中央字段集合表（引用元字段、覆盖展示名/必填/默认值、拖拽排序）；右侧结构预览与引用流程。
- 页签：**字段结构 / 默认驱动 / 使用情况**（v4 的「版本记录」页签按决策 10 移除）。
- 默认驱动页签四步编辑：
  1. 选择驱动方案（时间/条件/事件/不使用——不使用是合法选项）；
  2. 逐槽位选择来源（field / system / constant；system 为受限枚举 + 偏移表单，无手写表达式）；
  3. 类型与完整性校验（必需槽位未全部解析时**保存按钮保持禁用**）；
  4. 人类可读规则预览（如「前序组就绪次日开始，持续 3 天，提前 24 小时提示临期」）。
- 完成策略选择器 MVP 只展示「人工完成」；confirm/auto 以「阶段三开放」置灰示意。

## 5. 驱动方案页

- 只展示与配置内置 DriverDefinition，**不在此绑定具体节点模型**。
- 三张方案卡：输入契约（槽位、类型、允许来源、默认来源）、输出契约（能产出的生命周期与关注状态）、auto 完成能力（标注阶段三）、使用数量。
- 时间驱动详情：`startAt / duration / dueSoonThreshold`；条件驱动：条件树示例与比较符矩阵摘要；事件驱动明确标注「应用内事件 + 手动记录」「外部日志导入（阶段三）」「关闭期间重开追算」「不支持公网 Webhook」。

## 6. 流程页面

- 画布基于 React Flow 封装；节点从节点模型创建，**不复制字段定义**（活引用）。
- 节点检查器：字段集合预览、驱动解析结果、`inherit / override / none` 切换；**override 打开完整绑定编辑器**，不允许只覆盖一个槽位后继承其余。
- 连线三关系：必经（实线主色）/ 可选（虚线）/ 参考（弱化关联线）——同时以文字与图例表达，不只靠线型。
- 多前序汇聚显示 joinPolicy 徽标（MVP 固定 all）。
- 校验面板：缺失驱动输入、类型错误、孤立节点、入口错误、必经环；全绿才能发布。
- 子流程（阶段二）：节点绑定另一流程，画布上显示下钻入口徽标。

## 7. 条件组构建器

条件树编辑的交互规格（数据结构见 [01 §6](01-领域模型与协议.md)）：

- 根为一个条件组；组内可「添加条件」「添加条件组」；组运算符 `且 / 或` 一键切换，作用于整组直接子项。
- 组以缩进 + 括号色块呈现层级；支持拖拽把条件移入/移出组；深度不设硬限制，超过三层给出可读性提示。
- 每个条件行 = 字段选择器（按类型过滤合法比较符）→ 比较符 → 目标值输入（组件随字段类型变化）；列表字段选择聚合模式（全部满足/任一满足/满足数≥n）后进入子谓词编辑。
- 底部实时人类可读预览：如「(标题包含 “周报” 或 优先级 = 高) 且 (子任务全部满足：已完成 = 是)」。
- 缺字段、非法比较符、空组即时标红，阻止保存。

## 8. 执行实例页

- 左侧：本实例节点列表或缩略流程；中央：运行流程图与当前任务；右侧：运行字段、驱动计算、生命周期时间线、执行证据。
- 状态呈现**必须同时使用文字、图标和颜色**三通道；生命周期与关注状态并列展示，互不覆盖。
- 核心行为：
  - 完成开始元节点后：无延迟人工节点立即进行中；配置次日开始的时间节点进入等待开始。
  - 时间节点支持模拟正常 / 临期不足一天 / 已超时（虚拟 now，纯展示，不写日志）。
  - 运行字段缺值 → 受阻 + 缺失字段清单 + 补值入口；补值后重算恢复。
  - 完成 / 跳过 / 撤销完成 / 撤销跳过入口（撤销是新事实，见 [02 §2.2](02-状态引擎规范.md)）。
  - 手动记录事件入口：选择事件类型 + 可选备注，供事件驱动节点感知。
  - 主线完成度与可选完成度分开展示。
- 同步状态徽标（阶段二）：idle / dirty / syncing / synced / conflict / auth_expired；冲突进入三选一界面（[04 §6](04-存储与同步规范.md)）。

## 9. 视图协议

- 视图 = 数据的展示形式；**内核输出与视图解耦**：执行页视图消费 `RunProjection`，编辑画布消费 `FlowDefinition`，两者都不反向写入语义。
- 视图不得：改写边关系语义、改写参与类别、保存运行状态、执行完成动作以外的状态变更。
- MVP 内置两个视图：**编辑画布**（配置中心流程页）与**默认执行视图**（执行页运行图）。多视图切换不进 MVP；将来「加一种视图 = 实现一个 ViewRenderer」，接口形态：

```ts
interface ViewRenderer {
  viewId: string;
  name: string;
  capabilities: { manualPositioning: boolean; subflowDrilldown: boolean };
  // 渲染入口由 apps/web 定义，core 不感知具体 UI 框架
}
```

- 节点位置、视口、折叠状态等**视图状态**独立保存，不写入流程定义与快照。

## 10. 视觉语言（承接 v4，全文有效）

- Neural Noir 工具型界面；背景 `#070807`，画布 `#090B0E`，面板 `rgba(13,16,20,.94)`。
- 默认边框 `rgba(255,255,255,.11)`，主金色 `#A78B71`，浅金 `#C9B8A0`。
- 当前/临期 `#F4B942`，完成 `#55D6A7`，可选 `#7FB6B2`，错误/超时 `#F36B6B`。
- 主文本 `#F4F1EB`，次文本 `#A5A7AE`，弱文本 `#6B7079`。
- 中文字体 `Inter, PingFang SC, Microsoft YaHei, sans-serif`；稳定键、ID 和结构预览使用 `IBM Plex Mono, monospace`。
- 控件圆角 10px，对象卡与节点 14px，浮层 18px；克制阴影与清晰 1px 边框。
- 禁止蓝紫渐变、装饰性衬线字体、库存图片和营销页布局。

## 11. 硬约束

1. 元字段 = 字段定义；节点模型 = 字段集合；术语全站统一（[00 §2](00-术语表与总览.md)）。
2. 节点可以没有驱动器；有驱动器时所有必需输入必须完整解析且类型兼容，否则禁存禁发。
3. 每个流程节点最多一个主驱动。
4. 流程页面不保存运行状态；配置工作止于发布快照。
5. 执行实例使用独立页面外壳，不属于配置导航。
6. 配置总览的完整数据流必须用可见连线呈现。
7. 状态永远由重算得出，UI 不直接改状态字段；一切用户操作落为事件日志事实。
8. MVP 完成一律人工；`confirm` / `auto` 置灰示意，阶段三开放。
