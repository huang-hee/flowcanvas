## 2. 元字段页

**采用通用表格页布局 A · 完整型**（[08 §5.1](08-交互规范.md)）。

**PageHeader**：标题「元字段」由 `menus` 配置按 path 匹配得出（[08 §2.1](08-交互规范.md)），页面不参与；新建入口在表格面板工具条。

### 2.1 筛选面板

三项，按 [08 §7](08-交互规范.md) 的栅格与控件规约，label 走控件 `prefix`：

| 项 | 控件 | placeholder | 选项 |
|---|---|---|---|
| 名称 / 字段键 | Input | 请输入名称或字段键查询 | — |
| 数据类型 | Select | 请选择数据类型 | 各数据类型 |
| 引用状态 | Select | 请选择引用状态 | 全部 / 已被引用 / 未引用 |

三项占第 1 行前 3 列，按钮块 `[重置] [查询]` 占**第 1 行第 4 列**（3 项形态）。

### 2.2 表格面板

**工具条**：左「元字段列表」，右主按钮「新增元字段」。

**列与列宽**（`Table` 的 `column.width`，单位 px）：

| 列 | 宽 | 内容 |
|---|---|---|
| 名称 | **弹性**（吃剩余宽） | 纯文本 |
| 字段键 | 200 | `text/mono` |
| 数据类型 | 140 | Tag 型徽章 |
| 被引用 | 120 | **可点单元格**，打开引用清单模态 |
| 更新时间 | 180 | `YYYY-MM-DD HH:mm` |
| 操作 | **160** | `[编辑] [规则] [删除]` |

**只有「名称」不写 `width`**，其余五列固定——名称最长且长度不可预期，让它吃剩余宽，窗口变窄时先压它。全部列文本左对齐（[08 §5.2](08-交互规范.md)）。

> **操作列 120 → 160**（00 决策 49）：新增「规则」入口。固定列合计 800，1280 视口下名称列约 176（表格可用宽 = 视口 − 240 侧栏 − 32 内容区 padding − 32 面板 padding）。**不另设「规则」列**——列表不显示某字段配没配规则，要看得点进去；理由是再加一列只能继续压唯一的弹性列。

> Figma 稿里六列是等宽 217，那是 kit `Table` 不能逐列改宽的限制（[07 §7.1](07-主题与设计系统.md)），**不是本表的列宽真相**。

**行为**：

- **「被引用」为可点单元格**（[08 §5.2](08-交互规范.md) 链接态）：有引用时显示「3 个模型」并可点，**这是引用清单的唯一入口**；「未引用」为纯展示不可点。
- **操作列** `[编辑] [规则] [删除]`：「规则」跳二级页 `/#/meta-fields/<metaFieldId>/rules`（§2.6），**这是规则配置的唯一入口**——抽屉里不放；删除走确认框（§2.5），被引用时禁用 + Tooltip 说明原因（[08 §8.4](08-交互规范.md)）。
- **整行可点**进入编辑抽屉。「被引用」单元格与操作列按钮的点击**须 `stopPropagation`**，不触发行点击；行 hover 反馈保持整行，单元格不另加 hover 底。
- **不开排序、不开筛选**（筛选走上方筛选面板）。
- 分页按 [08 §6](08-交互规范.md) 通则，无页面级差异。

**空态文案**：「暂无元字段数据，刷新列表」（呈现走 [08 §5.4](08-交互规范.md)）。

### 2.3 编辑抽屉

- 宽 **560**，全高，左侧两角取浮层圆角档（[08 §4.1](08-交互规范.md)）。
- **头**：字段名（`text/title-lg`）+ 引用计数徽标——**纯展示不可点**（引用清单入口只在表格「被引用」列）。
- **主体**（滚动）用 `Form` + `Form.Item`，字段序**六段**：
  **字段键 → 名称 → 数据类型 → 类型参数（enum 选项行 / list 子项类型 / number 精度与单位）→ 默认值 → 帮助文字**
  > **校验规则构建器已移出抽屉**（00 决策 49），与筛选配置一并落在规则配置二级页（§2.6）。字段序由七段减到六段——这是「抽屉表单太杂」的正解，不靠折叠。
- **必填项**（带必填标记、校验不过禁止保存）：**字段键、名称、数据类型、精度、单位模式**；单位模式选「时间单位组」时，**具体单位**同为必填。默认值、帮助文字为选填。
- **控件宽度不逐项写死**：跟随 `Form.Item` 撑满（精度步进器等短控件在代码里可给 `style.width`，但**不进规范**）。Figma 稿里 kit 的 `Form Item` 内控件宽不可逐项覆盖，稿子取 320——**不是本表的宽度真相**。（2026-08-18 更正：「只能取 528 或 320」**只在 `Form Item` 自身宽度固定时成立**；设 `layoutSizingHorizontal=FILL` 时控件宽会跟随父宽，执行页实测 368。）
- **底**：动作条左槽为空，右按钮组 `[取消] [保存]`（[08 §4.2](08-交互规范.md)）。**抽屉内无删除按钮**——删除入口在表格操作列；**也无「去配置规则」按钮**——规则入口只在表格操作列（00 决策 49）。
- **新建**走同一抽屉的空白态，标题「新增元字段」。**保存成功后**弹确认框询问是否配置规则（§2.5），**仅新建时弹**，编辑保存后直接关闭。
- **改 `dataType` 时**：若已配的规则会因此失效，**保存前**弹影响提示列出失效项，确认后保存并一并清理（§2.5）。**失效面横跨三处**：本字段的校验规则、本字段的筛选配置、**各节点模型里的字段覆盖**。用户在抽屉里既看不到二级页的内容、更看不到别的节点模型，因此这个提示是必需的，不能静默保存。

### 2.4 控件级规格

| 控件 | 规格 |
|---|---|
| **精度与单位**（number 专属，[01 §2.7](01-领域模型与协议.md)） | 精度 = 0–6 步进器（默认 0）；单位 = 三态选择「无 / 纯标注（文本框）/ 时间单位组（下拉选 分钟 / 小时 / 天 / 周）」 |
| **字段键** | 始终可编辑（mono 字体），保存时唯一性校验，**无锁定态** |
| **数据类型** | 随时可改；已被引用时修改后弹影响提示（即引用清单模态，§2.5）；规则失效提示见 §2.3 |
| **默认值** | 按类型渲染，皆含「未设置」态（boolean 即三态控件） |

**不做**：object / list(object) 内部结构编辑（在节点模型页子组装）；`inputComponent` 暴露（按类型默认控件）；`domain` 暴露（[01 §2](01-领域模型与协议.md) 协议预留，MVP 无入口）。

### 2.5 浮层

| 浮层 | 规格 |
|---|---|
| **引用清单模态** | 装表格的模态（[08 §4.4](08-交互规范.md)）：列 = 引用方名称 / 类型（节点模型 / 流程草稿）/ 位置说明；只读，不承载破坏性动作。底部仅一个「关闭」，取主按钮。**入口一** = 表格「被引用」可点单元格（主入口）；**入口二** = 编辑抽屉内改「数据类型」时的影响提示 |
| **删除确认** | 确认框**确认型**（[08 §4.3](08-交互规范.md)）：图标 `ExclamationCircleFilled` 取 `colorError`，标题「确认删除元字段」，内容「删除后不可恢复。该元字段当前未被引用，可安全删除。」，`[取消] [确认]`。确认后删除并刷新列表，**页码按 [08 §6](08-交互规范.md)「删除后的页码」处理**（删的是当前页唯一一条且页码 > 1 时回上一页） |
| **被引用时的删除** | 按钮禁用 + Tooltip「被 N 个节点模型引用，解除引用后方可删除」，**点不开确认框**（[08 §8.4](08-交互规范.md)） |
| **新建后的规则询问** | 确认框（00 决策 49）：**信息型**（图标取信息色，非破坏性操作），标题「元字段已创建」，内容「现在配置校验规则与筛选配置？」，`[稍后] [去配置]`——「去配置」属「完成」性质取主按钮（[08 §4.2](08-交互规范.md) 判据），点击跳 §2.6；「稍后」关闭回列表。**仅新建时弹**，编辑保存后不弹 |
| **改类型的规则失效提示** | 复用**引用清单模态**（[08 §4.4](08-交互规范.md) 全站唯一载体）：表格列出将失效的全部配置，列 = **配置项 / 所在位置 / 失效原因**。「所在位置」区分三类：`本字段 · 校验规则`、`本字段 · 筛选配置`、`〈某某〉模型 · 字段覆盖`——第三类**每个受影响的节点模型单独一行**，不合并计数，因为确认后会写这些模型，用户有权知道动了谁。与只读的引用清单不同，此处**标题为「确认修改数据类型」**（点明用户正在确认的动作，而非把后果写进标题——他此刻仍可取消），底部为 `[取消] [确认保存]`，确认后保存元字段并清理失效项。**无失效项时不弹** |

### 2.6 规则配置二级页

`/#/meta-fields/<metaFieldId>/rules`（00 决策 49）。装元字段的两个伴生对象——**校验规则集**与**筛选配置**（[01 §2.1 / §2.8](01-领域模型与协议.md)）。

**入口唯一**：列表操作列的「规则」按钮（§2.2）。抽屉里不设入口。

#### 页面骨架

外壳走控制台外壳（[08 §2](08-交互规范.md)）。`PageBody` 内单面板，**纵排两个分区，不用页签、不分步**——两个分区之间没有依赖（依赖的是 `dataType`，那已在上一层抽屉里满足），分步无先后可表达。

```
面板头   面包屑：元字段 / <字段名> / 规则配置        ← 内容区顶部，不进 PageHeader（决策 38）
面板主体 ┌ 分区一 · 校验规则 ────────────┐
        └ 分区二 · 筛选配置 ────────────┘
面板底   [取消] [保存]                              ← 底部操作条（决策 38）
```

一次保存写两个对象，落在同一个 IndexedDB 事务里。

**内容宽度 528，水平居中于面板主体**——与编辑抽屉的表单内容同宽（§2.3），用户从抽屉跳过来不会觉得换了个东西；面板本身 1296 宽，表单控件撑满会让开关与其 label 拉开一米远。

#### 分区一 · 校验规则

从原 §2.4 抽屉迁入，规格不变：

| 控件 | 规格 |
|---|---|
| **校验规则构建器** | 规则行列表——「添加规则」下拉只给该 `dataType` 的合法规则，每行 = 规则名 + 参数控件 + 删除；行内文字取 `text/mono-sm`。**自研组件**（[08 §9.2](08-交互规范.md)） |

**「必填」不在此处**（00 决策 45）：必填的唯一出处是节点模型页的字段绑定，本页的规则下拉里没有这一项。

#### 分区二 · 筛选配置

三层渐进展开——未启用只有一行，启用后三行，选「自定义」才有第四行：

```
启用筛选        [ Switch ]                              ← 默认关
──────────────── 以下启用后才出现 ────────────────
默认关系        [ Select ]                              ← 选项 = 该 dataType 的关系全集，带预选值
候选值          ( ) 不配   ( ) 使用字段选项   ( ) 自定义   ← Radio.Group
自定义选项      [ TextArea ]  逗号隔开，可多行             ← 选「自定义」才出现
```

| 控件 | 规格 |
|---|---|
| **启用筛选** | `Switch`，默认关。关闭时其余三项不渲染 |
| **默认关系** | `Select`，选项取 [01 §6.1](01-领域模型与协议.md) 该 `dataType` 的关系全集（含通用关系），预选值取内置默认（[01 §2.8.1](01-领域模型与协议.md)） |
| **候选值** | `Radio.Group` 三态。**整个「候选值」行仅在 `dataType` 为 text / multiline / enum 时渲染**；「使用字段选项」仅 enum 可选，其余类型该项禁用 + Tooltip「仅枚举字段可用」 |
| **自定义选项** | **`TextArea`**（非 `Input`），逗号隔开纯文本、可多行；保存时切分、去空格、去重、去空项后存为数组（[01 §2.8](01-领域模型与协议.md)）。选项多时单行输入框看不全也难编辑，换行不参与切分、只作排版 |

**不做**（消费端，00 决策 47）：筛选栏、「添加筛选项」组装、自定义条件构建器、相对时间控件。本页只声明「这个字段怎么被筛」。

#### 状态

- **enum 字段的 enum 选项为空**时，「使用字段选项」仍可选，候选值随之为空——待用户回抽屉补全选项后自动生效，不阻塞保存。
- **空态**：新字段进入本页时校验规则为空列表、筛选未启用，这是正常初始态，不走空态插画。

## 3. 节点模型页

**一级列表 + 整页二级页**（00 决策 38）。功能规格见 [05 §5](05-产品规格.md)。

### 3.1 一级列表页

采用**通用表格页布局 A · 完整型**（[08 §5.1](08-交互规范.md)），与元字段页同构。

**筛选面板**（四项，按 [08 §7](08-交互规范.md) 栅格，label 走控件 `prefix`）：

| 项 | 控件 | placeholder | 选项 |
|---|---|---|---|
| 名称 | Input | 请输入名称查询 | — |
| 默认驱动 | Select | 请选择默认驱动 | 全部 / 时间 / 条件 / 事件 / 无 |
| 引用状态 | Select | 请选择引用状态 | 全部 / 已被引用 / 未引用 |
| 元字段 | Select **多选** | 请选择元字段 | 全部元字段 |

- **「元字段」筛选的语义是「包含任一」（OR）**：选了 `title` 和 `duration`，用了其中任意一个的模型都列出。这一项的真实用途是「我要改这个元字段，谁在用它」，一次问一个是常态。
- 四项**正好填满第 1 行**，故 `[重置] [查询]` 按 [08 §7](08-交互规范.md) 的落位规则**另起第 2 行占满 4 列**并右对齐。

**表格面板** —— 工具条：左「节点模型列表」，右主按钮「新增节点模型」。

| 列 | 宽 | 内容 |
|---|---|---|
| 名称 | **弹性** | 纯文本 |
| 字段数 | 100 | 数字 |
| 默认驱动 | 140 | Tag 型徽章（时间 / 条件 / 事件 / 无） |
| 被引用 | 120 | **可点单元格**，打开引用清单模态 |
| 更新时间 | 180 | `YYYY-MM-DD HH:mm` |
| 操作 | 160 | `[编辑] [查看] [⋯]` |

固定列合计 **700**，1280 视口下名称列约 276（算法同 §2.2）。

**操作列的三个位置**：

| 元素 | 行为 |
|---|---|
| `[编辑]` | 跳二级页。与整行可点是同一动作——保留显式入口是因为不是每个用户都会去试整行，成本为零 |
| `[查看]` | 开**快速浮层**列出该模型的字段清单，**不跳页**。用途是在列表上确认「是不是我要找的那个」 |
| `[⋯]` | `Dropdown` 菜单，装 **复制 / 预览 / 删除** |

- **删除进菜单是合规的**：[08 §8](08-交互规范.md) 只要求破坏性动作**一律经确认型**、[§4.2](08-交互规范.md) 只禁止它进浮层底部动作条，均未禁止进操作菜单。删除点开后照常走确认框。
- **「预览」**打开运行时表单预览抽屉（§3.5），与二级页底部的「预览」是同一个抽屉。

**空态**：「暂无节点模型数据，新建一个」（走 [08 §5.4](08-交互规范.md)）。

### 3.2 二级页骨架

`/#/node-schemas/<nodeSchemaId>`。`PageBody` 内**单面板**，主体纵排三个分区、整体滚动。

```
面板头   面包屑：节点模型 / <模型名>        引用徽标 →引用清单模态
面板主体 ┌ 基本信息 ────────────────────┐
        │ ─────────────────────────── │ ← 分区标题 + 分隔线
        │ 字段结构（区内两栏）           │
        │ ─────────────────────────── │
        │ 默认驱动                      │
        └──────────────────────────────┘
面板底   [预览]                    [取消] [保存]
```

- **分区间用「标题 + 分隔线」分隔**，不做标题 sticky——本页无表格吸顶（§3.3 是自研行列表），引入 sticky 就要按 [08 §5.5](08-交互规范.md) 处理吸附态的间距归属，为「知道自己在哪个分区」这点收益不划算。
- **底部操作条**按 [08 §4.2](08-交互规范.md)：**左槽放「预览」**（它既不提交也不放弃，正是左槽的用途），右组 `[取消] [保存]`。三个按钮挤在右组会让预览与取消相邻，点错就丢改动。
- **最小宽度约 1180**：左栏字段行至少 524（手柄 24 + 字段键 100 + 中文名 120 + 标签 160 + 按钮 120）+ 右栏 300 + 栏间距 16 + 面板 padding 32 + 内容区 padding 32 + 侧栏 240。窄于此由面板内部横向滚动，**不做布局降级**（[08 §2](08-交互规范.md)）。
- **纵向不追求首屏看全，滚动是预期行为**：Figma 实测三分区内容高约 **962**，而 1600×1000 视口下面板主体只有 **788**，差 174。**不为此压缩基本信息、不折叠默认驱动、不压间距**——`description` 是多行文本压不得，默认驱动是本页最重的内容之一折叠等于藏核心功能，而间距体系归 [07 §4](07-主题与设计系统.md) 统一管。配置页本就不需要首屏看全（元字段抽屉同样是滚动的）。

### 3.3 分区 · 基本信息

名称（`Input`，必填）+ 描述（`TextArea`，选填）两项。**引用徽标不在本区**——它在面板头的面包屑那一行（决策 38）。

两项内容占一个分区不算浪费：它在最上面，滚两下就过去了；而 `description` 是多行文本，塞不进面板头。

**内容宽度 528**，与编辑抽屉（§2.3）、规则配置二级页（§2.6）一致——全站表单内容统一取此值。

### 3.4 分区 · 字段结构（区内两栏）

```
┌──────────────────────────────────────────────┬──── 300 ────┐
│ ⠿ title  任务名称 [必填][3 条规则] [编辑][删除] │ 元字段库       │
│ ⠿ desc   描述                    [编辑][删除] │ [搜索______]  │
│ ⠿ taskItems 子任务 [必填] ▸子组装 [编辑][删除] │ [类型 ▾]     │
│                                              │ ⠿ title   text│
│                                              │ ⠿ desc multiline│
│                                              │ ⠿ duration number│
└──────────────────────────────────────────────┴──────────────┘
```

**字段行是一行七件，行高 40**（`controlHeightLG`）：拖拽手柄 → 字段键(mono) → 中文名 → `[必填]` → `[N 条规则]` → `[编辑]` → `[删除]`。右栏类型名用**英文 token**（`text` / `multiline` / `number`），与 §2.2 数据类型列及元字段页稿子一致，**不用中文**。

**左栏 · 字段绑定行列表**（**自研组件**，非 `Table`，登记于 [08 §9.2](08-交互规范.md)）：

`Table` 的列宽约束装不下这一行要放的东西——尤其「校验规则」本身是个规则列表，塞进单元格必崩。行内元素依次为：拖拽手柄、字段键（mono）、中文名、`[必填]` 标签、`[N 条规则]` 标签、`[编辑]`、`[删除]`。

| 项 | 规格 |
|---|---|
| **`[必填]` 标签** | 独立标签，**不算进规则数**——它是 `FieldBinding.required`，决策 45 已把它从 `ValidationRule` 里删掉，协议上就不是一条规则；更实际的是它是扫列表时最常查的信息 |
| **`[N 条规则]` 标签** | N 是**合并后**的结果（字段层 + 本模型覆盖，[01 §3.1](01-领域模型与协议.md)），不是本层覆盖数——否则继承了 3 条却没改过的字段会显示「0 条」，读起来像没约束。**点击弹 `Popover`** 看详情（[08 §4.4](08-交互规范.md)），列内标注哪几条来自本模型 |
| **排序** | 拖拽手柄，列表内排序 |
| **子组装** | object / list(object) 行显示 `▸ 子组装`，**行内嵌套展开**同一套交互（[01 §3](01-领域模型与协议.md) 限深两层，嵌套不会失控）。展开时**右栏自动过滤掉 object / list 类型**——子组装只能引用基础类型，不过滤等于让用户拖进去再被校验拦下 |

**右栏 · 元字段库**（固定 **300**，左栏吃剩余宽）：

- 每项显示 `字段键 · 中文名 · 类型徽章`；顶部**搜索框 + 数据类型下拉**。宽度按内容算：手柄 24 + 字段键 100 + 中文名 80 + 徽章 48 + padding 32 = 284。
- **已在本层用过的置灰不可拖**（见下「同层唯一」）。
- **右栏宽度固定而非弹性**：它的内容宽度需求是稳定的，弹性只会拉出空白；真需要宽度的是左栏。

**添加字段**：**拖拽与点击追加都支持**（[01 §3](01-领域模型与协议.md)）。

- 拖拽时显示**插入线**（两行之间一条高亮横线）——不做「推开占位」，长列表里会让整页跳动。
- 保留点击追加是因为纯拖拽有两个实际问题：一次加十个字段要拖十次；列表长了之后把右栏底部的字段拖到左栏顶部要一边拖一边等自动滚。

**同层唯一，跨层不限**（回填于 [01 §3](01-领域模型与协议.md)）：同一层内不得重复引用同一元字段，否则发布展平会物化出两个相同的 `fieldKey`，条件树路径无法确定指谁；但顶层用了 `title`，子组装里仍可再用（路径分别是 `title` 与 `taskItems.title`，天然无歧义）。

**编辑弹窗**（宽 **640**）：装展示名 / 必填 / 默认值 / 校验规则构建器四项，**子组装不在此**（它在行内展开）。

- 640 而非 520：校验规则构建器每行是「规则名 + 参数控件 + 删除」三段，520 会把参数框挤到很窄。
- **继承来的规则分组只读显示**：分「继承自元字段（灰色不可编辑，标注去元字段页改）」+「本模型覆盖（可增删）」两组。不显示的话，弹窗里数出 1 条、行内标签显示 3 条，对不上；混在一起可编辑则会让用户以为改的是通用规则，且 [01 §3.1](01-领域模型与协议.md) 的合并语义完全不可见。

**空态**：

| 位置 | 文案 |
|---|---|
| 左栏无字段 | 「从右侧拖入元字段，或点击添加」，**不用空态插画**（区域小，插画会撑高） |
| 右栏无元字段 | 「还没有元字段」+ **跳转元字段页的内联链接**——项目里一个元字段都没有时本页完全没法用，必须给出口（[08 §5.4](08-交互规范.md) 的「引导动作」首个用例） |

### 3.5 分区 · 默认驱动

**渐进展开**，不用页签也不用步骤条（[05 §5](05-产品规格.md)）：四项里只有前两项是真输入，第三项是持续的校验状态、第四项是结果，做成 Steps 会出现「点到第 3 步没东西可填」。

**驱动方案选择** —— `Radio.Group` 四选一（时间 / 条件 / 事件 / 不使用），选完在下方展开对应槽位。不用 `Select`（要点开才知道有哪几种），不用卡片（驱动方案页已有一整页详解，[05 §6](05-产品规格.md)）。

**槽位表单** —— **一槽位一行**，来源选择器在前，后续控件按来源动态变：

```
startAt           来源[系统▾]   [前序组就绪时刻▾]  偏移[+1][天▾]
duration          来源[字段▾]   [预计时长▾]        单位[分钟▾]
dueSoonThreshold  来源[固定▾]   [24][小时▾]
```

槽位最多三个，一行装得下，横排让「来源 → 值」的因果关系一眼可见。**槽位名列宽 150**（最长的 `dueSoonThreshold` 配 mono 字体的实测下限）。**例外**：`conditionTree` 槽位装不进一行，单独占一整块（见下）。

**条件树构建器**（**自研组件**，双场景共用，[08 §9.2](08-交互规范.md)）—— **缩进 + 左侧竖线**的嵌套行列表：

```
┌ 且 ▾  [+条件] [+组]
│  price      大于 ▾   [100]           🗑
│  taskItems  全部满足 ▾
│  └─ ┌ 且 ▾                        ← 聚合子条件，同一组件，字段源换成子字段
│     │  done   等于 ▾  [是 ▾]      🗑
│     └
└
```

| 规则 | 说明 |
|---|---|
| **字段范围** | **外层只列顶层字段**，不出现 `taskItems.done` 这种扁平路径；进子层**必须经聚合谓词** —— 否则 `taskItems.done = true` 无法判断是「全部」还是「任一」，而聚合谓词强制说清楚 |
| **聚合子条件** | 嵌套一个**同构的子构建器**，字段源换成该 list 的子组装字段。协议里 `item: ConditionNode` 本就是递归的，UI 不单方面砍 |
| **改了字段** | 关系与 `target` **自动重置**为新类型的默认，不标红 —— 二者是纯选择项，没有值得保护的用户输入；标红等于让用户对着自己刚制造的错误发愣 |
| **空组** | **禁止保存**，标红「组内至少要有一个条件」。不定义空组语义 —— 它不是数据而是没配完，任何语义都反直觉（对照决策 23 的空列表聚合，那次空列表是**合法数据**才需要定语义） |
| **嵌套深度** | 协议不设上限（[01 §6](01-领域模型与协议.md)），竖线加缩进在三四层仍读得懂 |

**校验状态** —— 必需槽位未全部解析时**保存按钮保持禁用**并就地标红，不占步骤位。

**规则预览** —— 固定在**本区底部**，每个驱动方案一份**句式模板**，槽位按**来源**分支取词：

```
startAt  system(previous.readyAt, +1天)  → 「前序组就绪次日」
         field(开始日期)                  → 「〈开始日期〉字段的值」
         constant(2026-01-01)            → 「2026 年 1 月 1 日」
```

成本要认：时间驱动是 3 槽位 × 3 来源 = 9 个词条。值得付，因为配完四个槽位后一句自然语言能立刻暴露「配反了」，而逐项罗列还得在脑子里拼一遍。

**完成策略** —— 位置在**槽位表单与规则预览之间**（它是驱动绑定的一部分但不属于槽位；放预览之后会被那段总结性文字隔开）。MVP 只开放「人工完成」，confirm / auto 置灰并标注「阶段三开放」（[05 §5](05-产品规格.md)）。

**运行时表单预览抽屉**：

- 走**右侧抽屉**而非模态 —— 执行页的运行字段渲染在**右栏的节点详情**里（[05 §9.2](05-产品规格.md)），宽度受限；抽屉的位置与宽度最接近它真实的样子，预览才有意义。模态是居中宽块，预览出的排版与实际不符，反而误导。

## 4. 驱动方案页（只读）

功能规格见 [05 §6](05-产品规格.md)，协议见 [01 §4](01-领域模型与协议.md)。

**这一页的性质是「说明书」不是「操作台」**——内容是内置常量，永远不变，用户来这里是查「时间驱动有哪些槽位」。因此按**可读性优先**设计，而非操作效率。

### 4.1 页面骨架

`PageBody` 内**单面板**，主体纵排**三张全宽方案卡**，整体滚动。

- **PageHeader 只有标题，无动作槽**——这一页没有任何可执行的操作。
- **不设筛选面板**——一共三张卡。
- **不做横排**：三张卡的内容量严重不均（时间驱动 3 个槽位、条件与事件各 1 个），横排会让时间驱动那张 3×5 的表挤到换行、另两张大片留白。**卡片高度本来就不必相等**。
- 三者装在一个面板而非三个并列面板：它们是**同一类东西的三个实例**，一个容器更能表达「这是一份清单」。

### 4.2 方案卡

```
┌──────────────────────────────────────────────────────────┐
│ 时间驱动  time                    3 个节点模型 · 7 个流程节点 │ ← 卡头，右侧可点
├──────────────────────────────────────────────────────────┤
│ 输入契约                                                   │
│  槽位              类型      必需  允许来源         默认来源  │
│  startAt          datetime  是   field·system·…  system(…) │
│  duration         duration  是   field·constant    —       │
│  dueSoonThreshold duration  是   field·constant   24 小时   │
│                                                           │
│ 输出契约                                                   │
│  生命周期  [等待开始] [进行中]                               │
│  关注状态  [正常] [即将到期] [已超时]                         │
│                                                           │
│ 自动完成   支持 · 阶段三开放                                 │
│                                                           │
│ 边界与限制                                                 │
│  · 关闭期间不驻留，重开后追算                                 │
│  · 临期阈值按分钟归一后比较                                   │
└──────────────────────────────────────────────────────────┘
```

**区块顺序**：输入契约 → 输出契约 → 自动完成 → 边界与限制。对应查阅的自然次序——「我要配什么」最常查，「它能产出什么」次之，后两块是补充。

| 区块 | 规格 |
|---|---|
| **卡头** | 驱动中文名 + `driverCode`（mono）；右侧**使用数量**，见 §4.3 |
| **输入契约** | **表格**，五列：槽位 / 类型 / 必需 / 允许来源 / 默认来源。纯展示，**不开排序不开筛选**。选表格是因为三个槽位并排时用户真正要看的是**它们之间的差异**（哪个有默认来源、哪个不能绑字段），对齐是唯一能让差异一眼可见的形态 |
| **输出契约** | **状态徽章平铺**，用执行页同一套状态色（[07 §2.5](07-主题与设计系统.md)）。理由不是好看而是**认知一致**：生命周期与关注状态在执行页是文字 + 图标 + 颜色三通道（[05 §9.5](05-产品规格.md)），说明书上看到的样子与实际跑起来一模一样，用纯文字反而要求用户自己做一次映射 |
| **自动完成** | 一行，写「**支持 · 阶段三开放**」。三个驱动的 `supportsAutoCompletion` 都是 `true` 但 MVP 一律 `manual`（决策 6），如实呈现「协议全量、校验限阶段」这个模式，与节点模型页把 confirm / auto 置灰标注的做法一致 |
| **边界与限制** | **三张卡都有这一块**，内容按驱动不同，没有的就不渲染。只写给事件驱动会让人误以为只有它有限制——而「关闭期间不驻留、重开后追算」对三个驱动都成立（[02](02-状态引擎规范.md) 的追算是全局机制） |

**事件驱动卡的边界四条**（[01 §4.1](01-领域模型与协议.md)）：应用内事件 + 手动记录（MVP）／外部日志导入（阶段三）／关闭期间不驻留、重开后追算／**不接收公网 Webhook**。最后一条是否定性说明，防止误解，必须写。

### 4.3 使用数量

**分开显示两个数**：`3 个节点模型 · 7 个流程节点`。

驱动绑定有两个出处——节点模型的 `defaultDriverBinding` 与流程节点的 `override`（[01 §7.1](01-领域模型与协议.md)）。只统计前者会漏掉 override；只统计后者会重复计数（一个节点模型被 5 个节点 `inherit`，那 5 个都算）。两个数各自意义明确，且正好对应「配置在哪一层」。

**可点，打开引用清单模态**（[08 §4.4](08-交互规范.md) 只读态），列出用了这个驱动的节点模型与流程节点。

这是本页唯一有价值的交互：「哪些地方在用事件驱动」是排查时的真问题，而这个答案在别处拼不出来——节点模型列表能看到「默认驱动」列，但流程节点的 `override` 散在各个画布里，没有任何地方能汇总。

### 4.4 状态

无空态（三张卡是内置常量，永远存在）。加载态走面板主体遮罩。

### 4.5 antd 组件映射

| 用途 | 组件 |
|---|---|
| 方案卡 | 面板原语 `card` 皮肤（[08 §3](08-交互规范.md)），非 antd `Card` |
| 输入契约 | `Table`，`pagination={false}`、不开排序筛选 |
| 输出契约徽章 | `Tag`，取状态色阶 |

## 5. 流程页面（画布）

> **页面名以「流程页面」为准**：左菜单第 5 项、[00 决策 17](00-术语表与总览.md) 的六项菜单、[05 §7](05-产品规格.md) 用的都是这个名字，而 [08 §2.1](08-交互规范.md) 规定页面标题**由 `menus` 配置按 path 匹配得出**——菜单名与页面标题必须同名，否则标题会与菜单对不上。「流程画布」只用于指称页面内那块画布区域。

功能规格见 [05 §7](05-产品规格.md)。这一页是全站两个**三栏页**之一（另一个是执行实例页 §7），共用 [08 §2.5](08-交互规范.md) 的侧栏折叠通则。

### 5.1 页面骨架

```
┌─ 240 ─┬──────────────────────────────────────┬─ 320 ─┐
│ 节点   │                                      │ 检查器 │
│ 模型库 │            画  布                     │       │
│       │                                      │       │
│  ◂    │                                      │   ▸   │ ← 折叠钮
├───────┴──────────────────────────────────────┴───────┤
│ 校验面板（可收起横条）  ⛔ 3 错误  ⚠ 1 警告            │
└──────────────────────────────────────────────────────┘
```

**三栏而非「画布全屏 + 浮动面板」**：节点模型库与检查器都是**高频往返**的东西——拖一个节点、立刻配它的驱动、再拖下一个；做成浮层意味着每次配置都开关一次。[08 §3](08-交互规范.md) 的横向组合上限正好是三栏。

**两侧栏可折叠**（[08 §2.5](08-交互规范.md)）：编排阶段要宽画布、配置阶段要检查器，两个阶段交替出现。折叠态存 `viewState`。

**画布可用宽**在 1280 视口下约 700（1280 − 240 侧栏 − 240 库 − 320 检查器 − 间距），折叠两侧后约 1000。

### 5.2 节点模型库（左栏 240）

列出全部节点模型，可搜索。**拖拽入画布**建节点；也支持点击追加到画布中心（同 §3.4 的双通道理由：一次建十个节点拖十次太累）。

### 5.3 画布

**节点卡**（自研，[08 §9.2](08-交互规范.md)，`mode: "edit"`）显示四样：

| 元素 | 为什么上卡 |
|---|---|
| 节点名 `label` | — |
| 节点模型名 | 一眼看出这个节点是什么类型 |
| 驱动徽标 | 时间 / 条件 / 事件 / 无——编排时要判断「这个节点由什么驱动」 |
| **参与类别** | 必经 / 可选 / 参考。它是推导字段（[01 §7.2](01-领域模型与协议.md)），不占存储但**决定完成度分母**，是编排时最容易搞错的东西 |

**字段清单不上卡**——那是检查器的事，卡上放不下，也没人在画布上读字段。

**边的三种关系**：**线型三档 + 画布角落的静态图例**（必经实线 / 可选虚线 / 参考点线）。

> **不在边上自动写关系名**：`FlowEdge.label` 已经是用户自定义边标签的字段（[01 §7](01-领域模型与协议.md)），自动写关系名会与它打架；而 [05 §7](05-产品规格.md) 定的原本就是「线型 + 文字**图例**」。具体某条边是什么关系，靠选中后在检查器里看与改。

**视图控制**：右下角浮动控件——缩放 `+` / `−` · 适应视口 · 当前比例。**不做小地图**：目标规模 ≤ 300 节点（[06 §5](06-实施计划.md)）下它价值有限，而常驻占角遮挡内容；「适应视口」已覆盖其主要用途。

**不做自动布局**：布局效果高度依赖算法与图形态，做不好会破坏用户手工摆的位置——而位置是存进 `viewState` 的用户资产。MVP 先让用户自己摆。

**撤销范围**：会话级撤销（决策 20）覆盖**结构操作**（建/删节点、连/断线、改关系），**不覆盖位置拖动**。位置是纯视图状态，拖错了直接拖回来；纳入撤销栈会让栈被大量位移淹没，真正想撤销的结构操作反而翻不到。

**空态**：新建流程时画布上只有一个**开始元节点**（`nodeId: start`，[01 §7.3](01-领域模型与协议.md) 规定它始终是第一个节点），配一句引导「从左侧拖入节点模型开始编排」。完全空白的画布不知从何下手，而开始元节点本来就必然存在，让它一开始就在，用户能立刻从它拉线。

**加载失败**：整页错误态，走 [08 §5.4](08-交互规范.md) 形态，文案「流程数据加载失败，重新加载」。

### 5.4 检查器（右栏 320）

**选中节点时**：字段集合预览 · 驱动解析结果 · `inherit / override / none` 三模式切换（`override` 打开完整绑定编辑器，不允许部分覆盖）。

**选中边时**：关系切换（必经 / 可选 / 参考）+ 自定义标签。

**未选中任何东西时**：显示**流程级信息**——节点数、边数、校验摘要。空面板浪费一整栏，而流程级信息本来就没有别的容身之处。

### 5.5 校验面板

**画布底部可收起的横条**，常驻显示错误 / 警告计数，展开后列出诊断条目，点某条**聚焦到画布上对应节点**。发布入口在此。

> **为什么不放进右栏检查器**：校验结果是**全流程级**的，而检查器是**当前选中节点**的上下文，两者混在一起会让「这条错误说的是哪个节点」变模糊。做成面板的 `footer` 段（[08 §3](08-交互规范.md) 三段式），不新增结构。
>
> **这条把握不高**：它多占一条横向空间，而校验只在发布前才真正需要。若改为「点『校验』开模态」，不影响本页其他决策。
>
> **画稿实测**（2026-08-18，标注 `531:14770`，1600×1000 视口）——代价是可量化的：
>
> | 形态 | 横条占高 | 画布净高 |
> |---|---|---|
> | 无横条 | 0 | 908 |
> | **收起态**（常驻计数） | 56 + 16 间距 = **72**（≈ 8%） | **836** |
> | 展开态（列 4 条诊断） | 约 252 | **656**（−28%） |
>
> 画布净宽实测 **736**（两侧栏都展开），够摆 3 列 180 宽的节点卡——**横向不紧张，紧张的是纵向**。
>
> **取舍待拍板**：收起态那 8% 是「随时能看见还有几个错」的常驻成本，展开态的 28% 才是真痛点。折中路线是**保留收起态横条、把展开改为开模态**——计数常驻，诊断清单不吃画布高度。

**发布模态**四步（[05 §7](05-产品规格.md) 已定）：校验运行 → 结果列表（错误阻断 / 警告放行）→ 确认 + 可选版本说明 → 成功态（「打开实例列表 / 创建实例」CTA）。

## 6. 实例列表页

功能规格见 [05 §8](05-产品规格.md)。

### 6.1 页面骨架

**表格页布局 B 型**（[08 §5.1](08-交互规范.md) 的退化形态，无筛选面板）——只有一个表格面板。

**不设独立筛选面板**：实例的筛选维度（按流程、按状态）已经被**分组**和**过滤页签**吃掉了，再加筛选面板会出现三套并存的过滤机制。工具条右侧放一个按实例名的搜索框即可。

> **这条把握不高**：若实例会积累到几百个，该给完整筛选面板，那时 B 型退回 A 型即可，不影响其他决策。

### 6.2 表格面板

**工具条**：左 = 过滤页签 `[进行中] [已归档]`（[08 §5.1](08-交互规范.md) 允许页签占标题位），右 = `[搜索框] [+ 新建实例]`。

**按流程快照分组**（**自研分组表格**，[08 §9.2](08-交互规范.md)）：

```
▾ 学习计划 · v3   「补充了复盘节点」
    实例名        生命周期       必经完成度        警示    最近活动   创建时间  操作
    2026 春季     进行中 2·受阻 1  ▰▰▰▱▱ 必经3/5·跳过2  ⚠1·⛔0  2 小时前   08-01   [打开][⋯]
▾ 学习计划 · v2
    …
```

**为什么是分组表格而不是卡片或平铺**：实例的核心信息（完成度、警示、最近活动）**多列对齐才好比较**，卡片做不到；平铺则丢掉「按快照看」这个组织方式——同一流程 v1 和 v2 的实例混在一起排序毫无意义。分组默认全展开，组头可点收起。

| 列 | 宽 | 内容 |
|---|---|---|
| 实例名 | **弹性** | 纯文本 |
| 生命周期汇总 | 160 | `进行中 2 · 受阻 1` |
| 必经完成度 | 180 | **进度条 + 文字**，格式 `必经 3/5 · 跳过 2` |
| 警示 | 120 | 临期 / 超时计数，色 + 图标 + 数字 |
| 最近活动 | 160 | 相对时间（`2 小时前`） |
| 创建时间 | 160 | `YYYY-MM-DD HH:mm` |
| 操作 | 120 | `[打开] [⋯]` |

- **最近活动排在创建时间之前**：它回答「这个实例还活着吗」，比创建时间重要得多。
- **「最近活动」是派生值**，取**事件日志最后一条的时间戳**——`FlowRun` 上没有这个字段（[03 §5](03-发布与快照规范.md)），实现时别去那儿找。
- **完成度用进度条 + 文字**：纯文字扫不出「哪个实例快完了」；纯进度条丢掉跳过计数，而[决策 25](00-术语表与总览.md) 特意规定跳过要单独标注、不进分母。**可选完成度不上列表**——执行页里展示就够，列表挤不下第二个进度条。
- **操作列**只放 `[打开] [⋯]`：归档 / 恢复 / 永久删除都低频且带确认，进菜单（同 §3.1 手法）。

**排序**：组内按**最近活动倒序**，组间按**快照发布时间倒序**（新版本在上）。**不开列排序**——分组表格里的列排序语义混乱（组内排还是全局排？），而默认序已覆盖主要需求。

**性能**：每行的生命周期汇总、完成度、警示**都要跑 `recompute`**，且**不能吃缓存**——临期/超时是时间驱动的，缓存必然过期（[06 §5](06-实施计划.md) 批量重算预算）。

### 6.3 浮层

| 浮层 | 规格 |
|---|---|
| **新建实例模态** | 选流程快照（默认最新版）→ 命名 → 创建并**在新标签页打开** |
| **归档 / 恢复确认** | `Modal.confirm` 确认型 |
| **永久删除** | **普通 `Modal`**（非 `Modal.confirm`）装表单：红色警示文案 + 「请输入实例名 `xxx` 以确认」输入框 + `[取消] [永久删除]`，**输入不匹配时删除按钮禁用**。`Modal.confirm` 的 `content` 虽接受 `ReactNode`，但没有「按输入内容控制按钮禁用」的状态口子，必须用普通 `Modal` 自管（[05 §8](05-产品规格.md) 已定「需输入实例名」） |

### 6.4 状态

**两级空态**：

| 情况 | 呈现 |
|---|---|
| 完全没有实例 | 插画 + 「还没有执行实例，新建一个」 |
| 当前页签下没有（如已归档为空） | **单行文案**「没有已归档的实例」，**不用插画** |

后者是正常状态不是异常——已归档为空配一张大插画像是出了问题。

## 7. 执行实例页

功能规格见 [05 §9](05-产品规格.md)。**独立外壳**（独立标签 + URL，不出现控制台菜单）。这是第二个三栏页，共用 [08 §2.5](08-交互规范.md) 的侧栏折叠通则。

### 7.1 页面骨架

```
┌────────────────────────────────────────────────────────────┐
│ [标识][实例名][流程名·v3]  [必经3/7][⚠1·⛔0][同步][控制台][⋯] │ ← 顶栏
├─ 280 ─┬────────────────────────────────┬───── 400 ─────────┤
│ 节点   │                                │ ┌ 当前任务卡 ───┐ │
│ 列表   │      运行流程图（只读画布）      │ └──────────────┘ │
│       │                                │   节点详情        │
│  ◂    │                                │        ▸         │
└───────┴────────────────────────────────┴──────────────────┘
```

**三栏比例：左 280 固定 · 中 flex · 右 400 固定。**

- 左栏是节点列表，内容宽度需求稳定（同元字段库的 300 逻辑）。
- 右栏 400 是运行字段表单的可用下限——对照元字段抽屉 560 / 其中表单 528，右栏更窄是因为不含长 label 左对齐的表单。

**画稿实测**（2026-08-18，标注 `531:14769`，1600×1000 视口）——三个宽度全部成立，**但右栏高度不成立**：

| 栏 | 实测 | 结论 |
|---|---|---|
| 左 280 | 节点名 + **单个**生命周期徽标刚好；再挂关注徽标就换行 | 够用。**双徽标只放节点卡上**，左栏行只挂生命周期一枚——这也是 §7.2 双徽标写在节点卡而非左栏的实测依据 |
| 中 flex = 856 | 6 个 `200×98` 的 run 节点卡 + 三种边排得开，余量充足 | 够用 |
| 右 400 | 宽度够——运行字段的 kit `Form Item` 在 `FILL` 下实测 **368**（[07 §7.1](07-主题与设计系统.md)）。**高度不够**：当前任务卡（header 段，固定不滚）178 + 节点详情四区块 946 = 1124，而 body 段可视仅 728，**溢出 218** | **「执行证据」整块落在首屏之外** |

> **右栏高度是本页唯一未决的结构问题**。宽度 400 不必动，要动的是纵向组织。两条路，**待拍板**：
>
> | 方案 | 得 | 失 |
> |---|---|---|
> | **当前任务卡可收起** | 改动最小，收起后让出 178，执行证据勉强进首屏 | 与 §7.3「不管你在看哪儿，最紧迫的事永远在这儿」直接冲突——可收起就意味着它可以不在 |
> | **节点详情改分段**（页签 / 折叠面板） | 四区块各自独立，永不溢出；`Tabs` kit 有（[07 §7.1](07-主题与设计系统.md)） | 多一次点击才能看到驱动计算与证据；「运行字段 → 驱动计算 → 时间线 → 证据」的阅读顺序被打散 |
>
> 时间模拟态（`531:8412`）会再吃掉 48px，把生命周期时间线压到只剩一行，**该状态下无论选哪条都溢出**——这是倾向「详情改分段」的一个理由。

**左栏装节点列表，不做缩略流程**：[05 §9.2](05-产品规格.md) 原文是「节点列表（状态徽标）**或**缩略流程」，二选一。选列表因为——① 280 宽里缩略图看不清，列表能显示状态徽标和节点名；② 中央已有完整流程图，再来一个缩略版是重复；③ 列表天然支持滚动与点击定位，缩略图要做视口同步。

### 7.2 中央 · 只读画布

**复用编排画布的节点卡与边样式**（[08 §9.2](08-交互规范.md)，`mode: "run"`），但**禁用一切编辑**——不能拖动、不能连线、不能删除，只保留缩放、适应视口、点击选中。

依据是 [05 §10](05-产品规格.md) 的视图协议：视图不得改写边关系语义、不得保存运行状态。而复用同一套节点卡意味着**用户在配置域看到的形状，跑起来还是那个形状**。

`run` 模式的节点卡额外挂**生命周期 + 关注状态双徽标**，二者并列不互相覆盖（[05 §9.5](05-产品规格.md)：状态必须文字 + 图标 + 颜色三通道）。

### 7.3 右栏 · 当前任务卡 + 节点详情

**当前任务卡固定在右栏顶部**，聚焦规则见 [05 §9.3](05-产品规格.md)（受阻 → 超时/临期 → 最早激活的进行中 → 下一个等待开始）。

**联动规则**：点画布或左栏选中某节点 → **下方详情切到该节点**；**当前任务卡不跟着变**。

> 当前任务卡的价值是「不管你在看哪儿，最紧迫的事永远在这儿」，跟着选中变就退化成第二个详情面板了。代价是两者可能指向不同节点——用卡片标题明确标注「当前任务」来消歧。

**节点详情**区块顺序（[05 §9.4](05-产品规格.md) 已定）：运行字段 → 驱动计算（只读解释）→ 生命周期时间线 → 执行证据。

**执行证据**：列表 + 「添加证据」按钮，点击**行内展开**表单（文本备注 + 链接，二者至少其一，[决策 21](00-术语表与总览.md)）。不开浮层——证据是**追加型**数据（`evidence.attached` 事实），不需要编辑和删除；行内展开比浮层轻，而右栏本就纵向滚动。

### 7.4 关键交互

**完成 / 跳过入口有三处**：当前任务卡的主操作、节点详情的操作条、画布节点卡的右键菜单。

> 这是执行域最高频的动作，而用户可能从三个不同地方发现「这个该完成了」；强行收敛到一处会制造「看到了但点不了，得先切到别处」的挫败。三处走同一个事实写入（[02 §2](02-状态引擎规范.md) `node.completed`），不存在语义分叉。

**受阻状态三处同步**：节点卡加受阻徽标、左栏该行标红、当前任务卡自动聚焦到它。详情里列出 `missingFields` 并给内联补值入口。

> 受阻是唯一「用户不动手就永远卡住」的状态，而 [02 §5.1](02-状态引擎规范.md) 规定「禁止静默降级」——它必须在用户看向的任何一处都可见。

**时间模拟**：入口在顶栏 `⋯` 菜单；开启后顶栏出现一条**明显的模拟状态条**（琥珀底 + 「模拟时间：xxx」+ 退出按钮，自研组件）。

> 它是调试性质的功能（[05 §9.5](05-产品规格.md) 明确「纯展示，不写日志」），不该占常驻位置；但一旦开启必须极其显眼，否则用户会以为看到的是真实状态。**把握不高**——若它是演示/验收的高频操作，该提到顶栏常驻。

### 7.5 状态

- **加载失败**（快照丢失、日志损坏）：整页错误态，走 [08 §5.4](08-交互规范.md)，文案「实例数据加载失败，重新加载」。
- **无空态**：一个实例必然有节点（至少有开始元节点）。

## 8. 仪表盘

功能规格见 [05 §3](05-产品规格.md)。**首屏**。

### 8.1 页面骨架

纵向三段：

```
┌─ 执行概况 ─────────────────────────────────┐
│  进行中 3      ⚠ 临期 2      ⛔ 超时 1      │ ← 三个指标块，后两个可点穿透
└────────────────────────────────────────────┘
┌─ 流程卡片区 ───────────────────────────────┐
│  ┌────────┐ ┌────────┐ ┌────────┐          │ ← 网格
│  │学习计划 │ │内容生产 │ │审批流程 │          │
│  └────────┘ └────────┘ └────────┘          │
└────────────────────────────────────────────┘
  [新建流程]  [新建元字段]  [导入 .flowpack]     ← 快捷操作
```

**执行概况提到最前**（修订 [05 §3](05-产品规格.md) 原顺序）：它回答「现在有什么需要我管」，流程卡片回答「我有哪些流程」——前者才是每天打开时最先要看的。

**同步状态不单独占模块**：[08 §2](08-交互规范.md) 已把同步徽标钉死在右侧头部最右角、跨页不动，仪表盘再放一份是同一信息两处维护。

### 8.2 执行概况

三个指标块：进行中实例数 · 临期计数 · 超时计数，**后两个可点穿透**到实例列表页对应筛选。

**不列「最近活跃实例」**（原 05 §3 有）：那是实例列表页的职责，仪表盘再列一遍等于两处维护同一份排序逻辑。

**性能**：三个数都要对**每个实例**跑 `recompute`，且不能吃缓存（[06 §5](06-实施计划.md)）。

**画稿实测**（2026-08-18，标注 `531:14771`）——**这一段观感偏空，是本页最弱的地方**：

- 三个指标块 `FILL` 后各 **432 宽**，而块内只有一行标签 + 一个数字，右侧大片留白；块与块之间原本没有任何边界，已插两根 kit `Divider`（vertical）划分。
- **数字字号只能取 18**（`text/title-lg`，[07 §3.1](07-主题与设计系统.md) 的字阶上限）。仪表盘的核心指标用 18 撑不起来——**设计系统缺一档大号数字**，缺口已登记进 07 §3.1，**取值待拍板**。

> 三条候选改法，**待拍板**：① 只补大号数字字阶，块宽不动；② 指标块改为 hug 宽度靠左排布，不再均分 432；③ 每块加一枚状态图标（临期琥珀 ⚠ / 超时红 ⛔ 已有，进行中缺一枚），补足视觉重量。三者可叠加。

### 8.3 流程卡片区

每条流程一张卡，网格排布。卡内：名称 · 节点数 · **校验状态徽标** · 最近发布 vN + `note` 摘要 · `[编辑] [发布]`。

**校验状态徽标是这张卡最有价值的信息**——它让用户不进画布就知道哪条流程还发布不了。代价是要对每条流程跑六层校验（同上，纳入批量计算预算）。

### 8.4 快捷操作

底部一行三个**次级按钮**：新建流程 / 新建元字段 / 导入 `.flowpack`。

用次级不用主按钮：它们是入口不是主行动，用主按钮会与流程卡片上的 `[发布]` 抢焦点。放底部是因为熟练用户走左菜单更快，快捷操作主要服务新用户。

### 8.5 首次使用引导态

**全新工作空间**（无流程、无实例、无元字段）时，仪表盘**整页替换为引导态**：插画 + 「从创建第一个元字段开始」+ 三步说明（元字段 → 节点模型 → 流程）+ 主按钮直达元字段页。

> **理由**：这是全站唯一一个「用户第一次打开」必然看到的页面，而本系统的概念链条（元字段 → 节点模型 → 驱动 → 流程 → 发布 → 实例）对新用户完全陌生；不给引导，他会在六个空页面之间打转。
>
> **把握最低的一条**：[05 §3](05-产品规格.md) 完全没有这个东西，是本次评审自行添加。若认为 MVP 不该做引导，砍掉即可，不影响其他决策。
>
> **画稿实测**（2026-08-18，标注 `531:14771`）——画出来之后，两个问题都指向「要么补投入，要么砍掉」：
>
> 1. **插画语义不对**。稿子借用了 `illustration/empty-state`（`166:7`），那张画的语义是「**数据卷走了**」，用在「第一次打开、什么都还没有」上不对味。[08 §9.2](08-交互规范.md) 只登记了一张全站共用的空态插画，**没有为引导态定义插画**——要留引导态，就得再画一张。
> 2. **一整屏只承载了 360 高的内容**，居中后上下各余约 274。三行字 + 一个按钮撑一屏，观感偏空。
>
> **待拍板**：留（则须补一张引导专用插画 + 把内容做厚，例如三步各配小图或直接内嵌「新建元字段」表单）／ 砍（回到 §8.1 三段式，零实例时三个指标显示 0 即可）。**倾向砍**——它是评审自行添加的，不在 05 规格内，而补齐它要额外画一张插画并重新设计版式，投入不小；MVP 阶段左菜单六项已经把概念链条摆在明面上了。

**零实例但有流程**时不做特殊态——三个指标显示 0 即可。
