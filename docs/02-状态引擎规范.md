# 02 · 状态引擎规范

> 文档状态：正式方案 v1.0（2026-08-09 评审定稿）
> 依赖：[01-领域模型与协议](01-领域模型与协议.md)

## 1. 设计原则

1. **事实是唯一真相**：事件日志只记录「客观发生过、不可推导」的事实；一切派生结论（条件满足、临期、超时、自动完成）由重算得出，**永不写入日志**——否则日志与计算形成双重真相，必然打架。
2. **状态零存储**：生命周期、关注状态、完成建议都是纯函数输出，不作为可信数据落盘（允许作为缓存物化，但缓存可随时丢弃重建）。
3. **确定性**：同一份（流程快照, 事件日志, now）输入必须得到完全相同的输出。引擎内部**禁止读取系统时钟与随机数**，`now` 只能作为参数传入。这是「关闭重开后追算 = 持续在线」的保证。

## 2. 事件模型

```ts
interface EventEntry {
  id: string;                       // 事件唯一 ID
  seq: number;                      // 实例内单调递增追加序
  type: string;                     // 事实类型，见 §2.1
  payload: Record<string, unknown>;
  occurredAt: string;               // 事实发生时刻（ISO），手动记录可补记过去时间
  recordedAt: string;               // 写入日志时刻（ISO）
  source: "user" | "system" | "import";
}
```

### 2.1 内置事实类型

| type | source | payload | 说明 |
|---|---|---|---|
| `run.created` | system | `{ flowVersionId, runName }` | 实例创建，日志首条 |
| `node.completed` | user | `{ nodeId }` | 人工完成节点（含开始元节点） |
| `node.skipped` | user | `{ nodeId }` | 人工跳过节点 |
| `node.reopened` | user | `{ nodeId }` | 撤销完成 |
| `node.unskipped` | user | `{ nodeId }` | 撤销跳过 |
| `field.valueSet` | user | `{ nodeId, fieldKey, value }` | 运行字段赋值（保存粒度，非键击粒度）；`value: null` = 显式清空 |
| `custom.recorded` | user | `{ eventType, data? }` | 执行页手动记录的自定义事件，供事件驱动匹配 |
| `evidence.attached` | user | `{ nodeId, note?, url? }` | 执行证据：文本备注 + 链接，二者至少其一；文件附件延后 |
| `run.archived` / `run.unarchived` | user | `{}` | 实例归档与恢复 |
| （阶段三）`imported.*` | import | 按导入格式 | 外部事件日志导入 |

**运行字段值的真相 = 日志中该 `(nodeId, fieldKey)` 最后一条 `field.valueSet`**：`value` 非 null 即当前值；`value` 为 null 即显式清空（缺值，默认值不兜底）；从未写过 → 回落快照默认值（不写日志）→ 无默认值即缺值（求值细则见 §5.1 步骤 4）。`NodeRun.fieldValues` 只是物化缓存。

### 2.2 日志规则

- **只追加，不修改，不删除**。「撤销」也是新事实（`reopened` / `unskipped`），不是删除旧事实。
- 处理顺序以 `seq` 为准；时间语义（如完成时刻）以 `occurredAt` 为准；同刻并列以 `id` 字典序稳定决胜。

## 3. 重算函数

```ts
function recompute(
  version: FlowVersion,             // 不可变流程快照
  log: EventEntry[],                // 实例事件日志（按 seq 有序）
  now: string                       // 重算时刻，唯一的时间入口
): RunProjection;

interface RunProjection {
  runStartedAt?: string;            // 开始元节点完成时刻
  nodes: Record<string, NodeProjection>;
  completion: CompletionSummary;
}

interface NodeProjection {
  lifecycle: Lifecycle;
  attention: Attention;
  missingFields: string[];          // 受阻时缺失的字段
  suggestedCompletion: boolean;     // 完成建议标志（阶段三 confirm 模式使用）
  readyAt?: string;                 // 前序组就绪时刻
  activatedAt?: string;             // 进入进行中的时刻
  completedAt?: string;
  timeline: TimelineItem[];         // 由日志派生的节点时间线
}

interface TimelineItem {
  at: string;                       // 时间点（UTC ISO）
  kind: string;                     // 条目类型：completed / skipped / fieldSet / …
  label: string;                    // 人类可读描述
  refEventId?: string;              // 溯源的事件 ID
}
```

### 3.1 触发时机

- 任何写操作（追加事实）之后立即重算。
- 打开实例时重算（即追算：关闭期间发生的时间推移一次算清）。
- 应用打开期间周期 tick（默认 60s）以当前时间重算，供时间驱动感知临期/超时。

### 3.2 性能与 checkpoint 扩展点

单人本地规模（百级节点、千级日志）全量重算为内存遍历，毫秒级，MVP 直接全量重算。协议预留 checkpoint 扩展：物化某 `seq` 时刻的投影 + 之后增量重放，接口形态为 `recomputeFrom(checkpoint, logTail, now)`，MVP 不实现。

## 4. 三权分立

| 权力 | 归属 | 判定内容 |
|---|---|---|
| 就绪权 | 拓扑 | 前序组是否满足（`joinPolicy`），决定「轮没轮到」 |
| 激活与关注权 | 驱动器 | 何时从等待开始进入进行中；正常/临期/超时 |
| 完成权 | `completionPolicy` | `manual` 人工（MVP 唯一）；`confirm` 达成后人工确认；`auto` 达成即完成（阶段三） |

事件溯源下三种完成模式自洽：`manual` 与 `confirm` 的完成动作是**事实**入日志；`auto` 的完成是**派生结论**不入日志，`completedAt` 由达成时刻确定性推出。

## 5. 生命周期与关注状态

```ts
type Lifecycle =
  | "not_started"   // 未开始：前序组未就绪
  | "waiting"       // 等待开始：已就绪，驱动器激活条件未达
  | "active"        // 进行中
  | "blocked"       // 受阻：驱动结构就绪但必需运行字段缺值
  | "completed"     // 已完成
  | "skipped";      // 已跳过

type Attention = "normal" | "due_soon" | "overdue";   // 关注状态，正交于生命周期，不覆盖生命周期
```

### 5.1 节点生命周期推导算法（按序判定，先命中先出）

1. 存在有效完成（`node.completed` 未被之后的 `node.reopened` 抵销；或阶段三 auto 达成）→ **已完成**。
2. 存在有效跳过（`node.skipped` 未被 `node.unskipped` 抵销）→ **已跳过**。
3. 前序组未就绪（见 §7）→ **未开始**。
4. 驱动器必需输入解析到的运行字段缺值（含条件树引用的字段）→ **受阻**，`missingFields` 列出缺失字段。缺值判定（显式空值语义）：最后一条 `field.valueSet` 为 null（显式清空）→ 缺值，**即使快照有默认值**；从未写过 → 有快照默认值则取默认值（不缺值、不写日志），无默认值 → 缺值。补值后本条自动解除，重算恢复，**禁止静默降级**；补值表单可预填快照默认值作建议（[05 §9.4](05-产品规格.md)）。
5. 有驱动器且激活条件未达（时间未到 / 条件为假 / 事件未至）→ **等待开始**。
6. 其余 → **进行中**（无驱动器节点就绪后直接进行中，由执行人手动完成）。

### 5.2 状态转换表

| 当前态 | 触发 | 目标态 |
|---|---|---|
| 未开始 | 前序组就绪 | 等待开始 / 进行中 / 受阻（按 §5.1 步骤 4–6 判定） |
| 等待开始 | startAt 到达 / 条件转真 / 匹配事件到达 | 进行中 |
| 等待开始 / 进行中 | 必需运行字段被清空 | 受阻 |
| 受阻 | 缺失字段补值 | 重新按 §5.1 判定（等待开始或进行中） |
| 未开始 / 等待开始 / 进行中 / 受阻 | 人工跳过 | 已跳过 |
| 已跳过 | 撤销跳过 | 重新按 §5.1 判定 |
| 进行中 | 人工完成（MVP）；达成 + auto（阶段三） | 已完成 |
| 已完成 | 撤销完成 | 重新按 §5.1 判定 |

> 撤销与前序传播：撤销一个已完成节点后，其后继的前序组可能回到未就绪，后继节点随重算回退到未开始——这是纯函数模型的自然结果，无需专门实现「级联回退」。

### 5.3 关注状态推导

仅时间驱动产出非 normal 值：`due = startAt + duration`；`now > due` → `overdue`；`due - now ≤ dueSoonThreshold` → `due_soon`；其余 → `normal`。已完成/已跳过节点恒为 `normal`。

## 6. 驱动器计算规范

驱动器计算是重算的子过程，输入为「解析后的槽位值 + 日志 + now」，输出为「激活判定 + 关注状态 +（阶段三）达成判定」。

### 6.1 时间驱动 time

1. 解析 `startAt`（field / system / constant 来源，system 见 §7）。
2. `now < startAt` → 等待开始；`now ≥ startAt` → 激活（进行中）。
3. 关注状态按 §5.3。
4. 达成判定（阶段三 confirm/auto 用）：`now ≥ due`。

### 6.2 条件驱动 condition

1. 以当前运行字段值求值条件树（结构见 [01 §6](01-领域模型与协议.md)）。
2. 条件树引用的字段缺值 → 受阻（§5.1 步骤 4），**不参与求值**。
3. 求值为假 → 等待开始；为真 → 激活。
4. 达成判定（阶段三）：即求值结果本身。

### 6.3 事件驱动 event

1. `activateOn` 匹配器：`{ eventTypes: string[]; nodeId?: string }`——`eventTypes` 匹配日志中 `custom.recorded` 的 `eventType`（**MVP 唯一放行**）或内置事实类型（阶段三开放）；`nodeId` 为可选 payload 过滤，随内置事实匹配一起在阶段三开放（[01 §4.1](01-领域模型与协议.md)）。
2. 日志中存在匹配事实 → 激活，`activatedAt` = 首条匹配事实的 `occurredAt`；否则等待开始。
3. MVP 事件来源 = 应用内系统事实 + 手动记录事件；外部导入阶段三。

## 7. 前序组与 previous 语义

- **前序组** = 节点全部 `sequence` 入边的源节点集合；`optional` / `reference` 边不参与。
- 组成员的「满足」= 已完成或已跳过（跳过视为满足前序，否则流程死锁）。
- 就绪判定按 `joinPolicy`：
  - `all`（MVP 唯一开放值）：全部成员满足才就绪；**组就绪时刻 `readyAt` = 组内最晚的 `completedAt | skippedAt`**。
  - `any`（协议预留）：任一成员满足即就绪；`readyAt` = 最早满足者的时刻。
- `system(previous.readyAt)` 即解析为该组就绪时刻；入口节点（前序仅开始元节点）解析为 `run.startedAt`。
- 嵌套布尔汇聚（如「(A 且 B) 或 C」）为后期扩展形态（显式汇聚组对象），本期协议不含。

## 8. 完成度统计

```ts
interface CompletionSummary {
  required: { completed: number; total: number; skipped: number; percent: number };
  optional: { completed: number; total: number; skipped: number; percent: number };
}
```

参与类别按边关系推导（[01 §7.2](01-领域模型与协议.md)）；**必经完成度不得因可选节点未完成而降低**；参考节点不入任何完成度。**已跳过节点不计入 total**（分母排除），以 `skipped` 单独计数供视图标注（如「完成 3/5 · 跳过 2」）；`total = 0` 时 `percent = 100`——全部跳过视为走完，与「跳过视为满足前序」自洽（视图在 total 与 skipped 均为 0 时可隐藏该组）。

## 9. 时间模拟

执行页的「模拟正常 / 临期 / 已超时」通过传入**虚拟 now** 重算实现，是纯展示行为，**不写任何日志**，关闭模拟即回到真实 now。
