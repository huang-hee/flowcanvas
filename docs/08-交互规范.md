## 1. 设计原则

- **仅浅色主题，不做明暗切换**；全站为暖色浅底体系，靠明度分层而非撞色——chrome（侧栏）最深、内容区居中、面板最亮。
- 状态一律**文字 + 图标 + 颜色**三通道，色弱可用。
- 克制阴影、清晰 1px 边框；禁止蓝紫渐变、装饰性衬线字体、库存图片和营销页布局。
- 桌面优先：最优 1600+，参考宽度 1280；**最小宽度按页定义**，窄于该页下限时由**面板内部自行滚动**（横向亦然，如宽表格在表格面板内横滚），不做布局降级；移动端适配阶段三。
- **组件库优先**：能由 antd 主题 token 达成的一律走 token，不写自定义样式；偏离登记进 [07 §6](07-主题与设计系统.md)，自研组件登记进 [§9.2](#92-自研组件清单)。

## 2. 外壳 Shell

> Figma：Section `规范 · 外壳`

### 2.1 结构与区域命名

外壳只有**两种**：**控制台外壳**（六页共用，本节）与**执行页外壳**（独立标签，[05 §9](05-产品规格.md)）。404 / 加载失败等以控制台外壳的空 PageBody 表达，不另立外壳。

> **执行页外壳继承本册全部通则**——面板原语（§3）、色板与文字层级（07）、浮层规则（§4）、「页面级不滚、只在面板主体内滚」、区域命名术语。它不是另一套设计语言，只是**槽位内容与栏位比例不同**。差异部分（顶栏槽位构成、三栏宽度、节点列表形态）与页面内容强耦合——执行页左栏装的是本实例节点列表，属**内容**而非导航，与控制台的 `Sidebar` 性质不同，故取 `card` 皮肤而非 chrome 底——具体随该页评审时定义（09）。

```
┌───────────────────────────────────────────────────────────┐ Shell
│ ┌───────────┬───────────────────────────────────────────┐ │
│ │ Sidebar   │ PageHeader            高 60 固定           │ │
│ │ 240 ⇄ 64  ├───────────────────────────────────────────┤ │
│ │ 全高       │ PageBody              padding 16          │ │
│ │           │   面板组合置于其中，各自内滚                │ │
│ │ Header 60 │                                           │ │
│ │ Body 菜单 │              ← 内容区，逐页定义             │ │
│ │ Footer 56 │                                           │ │
│ └───────────┴───────────────────────────────────────────┘ │
│   Overlays  抽屉 / 模态 / Toast（§4）                      │
└───────────────────────────────────────────────────────────┘
```

**区域命名为规范术语**，09 与各页规范一律使用下表词汇，不得另造说法：

| 术语 | 指代 |
|---|---|
| `Shell` | 整个外壳（含以下全部） |
| `Sidebar` / `Sidebar.Header` / `Sidebar.Body` / `Sidebar.Footer` | 左侧栏及其三段 |
| `MainColumn` | 右列（PageHeader + PageBody） |
| `PageHeader` | 右列顶部固定条 |
| `PageBody` | 右列内容区 —— **逐页定义的就是这里** |
| `Overlays` | 抽屉 / 模态 / Toast 层 |

- 左右两栏：`Sidebar` **固定宽全高**，`MainColumn` flex 占剩余。
- **页面级永不滚动**，一切滚动（纵向与横向）发生在面板主体内。
- 代码实现：`Sidebar` 用 **`<Layout.Sider theme="light">`**（`collapsedWidth` 承载展开 ⇄ 收起），菜单用 **`<Menu theme="light">`**——**必须是 `light`**，chrome 配色填的是 antd 的浅色档；选中项左缘 3px 为登记偏离（[07 §6](07-主题与设计系统.md)）。

**头部标题来自 menus 配置，按当前 path 匹配得出**——不是页面塞给外壳的。一份 `menus` 配置（`{ path, title, icon }`）同时供给**侧栏菜单**与**头部标题**，外壳读的是自己的配置，无跨层通信，菜单与标题也永不失同步。

> 推论：**页面不参与头部渲染，禁止任何形式的回写**。若日后头部需要显示实体名（如某个节点模型的名称），同样由外壳读 store 派生，而不是页面写上去。

### 2.2 侧边栏

| 段 | 规格 |
|---|---|
| 头部 | 高 `size/header-h`（与右侧头部同高，共享同一水平线）；logo 方块 + 应用名「FlowCanvas」；padding `space/inner` |
| 主体 | 六项菜单（图标 + 文字），内滚；四态见下 |
| 底部 | 高 `size/sidebar-footer-h`；仅放收起 / 展开按钮，**图标居中**；**顶缘 1px `--border-strong` 分隔线，与主体断开** |
| 右缘 | border-right 1px `--border-strong` + 骨架级阴影，**投影贯穿全高**（[07 §4](07-主题与设计系统.md)） |

**三段中只有底部与主体之间画线**——`FlowCanvas` 标题下方**不加分隔线**（头部与主体靠底色连续读作整体，也避免与右侧头部读成一体）；底部工具条是常驻功能条、不随主体滚动，**须有一根 1px `--border-strong` 与滚动区断开**（chrome 底上用强边框，理由见 [07 §4](07-主题与设计系统.md)）。三段之间一律不投影。

**菜单四态**（配色全部由 antd 浅色档承载，见 [07 §1.2](07-主题与设计系统.md)）：

| 态 | 底 | 文字 |
|---|---|---|
| 默认 | 无（透出 chrome 底） | `Menu/itemColor` |
| hover | `Menu/itemHoverBg`（半白） | 同默认 |
| **选中** | `Menu/itemSelectedBg`（**纯白**）+ **左缘 3px `--primary`** | `Menu/itemSelectedColor` |
| 禁用 | 无 | antd 默认 |

> 选中态靠「**变亮**」浮起（白底药丸），不靠变深——浅色 chrome 上变深会与 hover 混淆。左缘 3px 位于**侧栏最左边**（非药丸左侧），是登记偏离（[07 §6](07-主题与设计系统.md) 偏离项 1）。

### 2.3 收起态

- 宽度 `size/sidebar-w` ⇄ `size/sidebar-w-collapsed`，切换带 150ms 宽度过渡。
- 收起后：菜单仅留图标居中，hover 出 tooltip 显示名称；头部仅留 logo 居中，应用名隐去；底部按钮变为居中图标。
- 激活态左缘 3px `--primary` 两态都保留。
- **菜单图标**：六项各配一枚 `@ant-design/icons` 图标（收起态唯一辨识依据，展开态也显示）。
- **收起 / 展开按钮**：图标居中，展开态用 `MenuFoldOutlined`、收起态用 `MenuUnfoldOutlined`。
- 状态存 `appSettings` 跨会话记忆；**仅手动触发**，不做窄屏自动收起。

### 2.4 右侧头部与槽位规则

| 项 | 值 |
|---|---|
| 高度 | `size/header-h` 固定 |
| 底色 | **`Layout/headerBg` = 白**，与内容面板同色（侧栏比它深一档，形成 chrome / 内容的分层） |
| 内 padding | 左右 `space/inner` |
| 下缘 | border-bottom 1px `--border` + 骨架级阴影，**仅侧栏右侧那一段**——不越过侧栏（[07 §4](07-主题与设计系统.md)） |

槽位自左至右，**只有两个**：

```
[页面标题] ···························· [同步徽标] [⋯]
                                        └ 工作空间簇
```

- **页面标题**：由 `menus` 配置按当前 path 匹配得出（§2.1），页面不参与。
- **工作空间簇**永远钉在最右角，跨页位置恒定：同步状态徽标（[05 §9.6](05-产品规格.md) 九态映射）+ `⋯` 更多菜单（导出 / 导入 `.flowpack`；后续工作空间级操作也归此菜单）。
- **不设「页面动作槽」**——头部属 **layout 层**，只放全局之物；页面级操作一律下沉：新建进表格面板工具条、保存与取消进面板底部操作条、面包屑进详情面板头部。标题之所以是例外，是因为它来自 layout 自己的 `menus` 配置，而非页面。
- **标题区不单独抽组件**：头部左槽直接收 `ReactNode`（antd v6 核心包无 `PageHeader`，此处自研），将来要塞徽标不必改签名。

## 3. 面板 Panel

> Figma：Section `规范 · 设计系统 · 组件`（面板皮肤部分）

全站一切容器——侧边栏、主区、列表面板、编辑面板、执行页三栏、抽屉、模态——都是**同一原语的配置差异**，不存在「页面类型学」。

### 3.1 面板原语

- **高度撑满父容器**；纵向三段式：
  - **头部**：固定不滚，可省略；
  - **主体**：滚动区，**必有**；
  - **底部**：固定不滚，可省略。
- 头 / 底与主体之间以 1px `--border` 分隔线相隔，分隔线**横贯面板全宽**。
  > **模态是例外，不画这两条线。** antd 自 v5 起移除了 `Modal` 的头 / 底边框，kit 与之一致——跟随，不补回。判据：模态矮、主体很少滚，线是多余的分割；抽屉全高、主体必滚，线才起「固定段 vs 滚动区」的指示作用。故**抽屉有线、模态无线**（含 `Modal.confirm` 确认框），零自定义 CSS、零偏离登记。
- 头、底高度不设全局定值，由内容物按 padding 规范撑开（外壳的侧栏头与右侧头部除外，见 §2）。
- **宽度模式**只有两种：固定值 或 flex 占满剩余。

### 3.2 皮肤两档

| 皮肤 | 规格 |
|---|---|
| `card` | 白底 `--surface` + 1px `--border` + 自有面板圆角 `radius/panel` + 面板级阴影 + 内 padding `space/inner` |
| `plain` | 无底色无边框的结构容器（如右侧主区） |

### 3.3 组合规则

- 横向组合**最多三栏**；相邻面板间距 `space/panel-gap`。
- 承载面板的容器 padding `space/inner`。
- 允许嵌套（面板主体内再放横向面板组合），实践深度 **≤ 2**。
- 纵向堆叠时：高度按内容的面板取 hug，主面板取 flex 撑满剩余，间距同 `space/panel-gap`。

### 3.4 实例对照

| 实例 | 头部 | 主体（滚动） | 底部 | 宽度 / 皮肤 |
|---|---|---|---|---|
| 侧边栏 | logo + 应用名 | 菜单 | 收起 / 展开按钮 | 固定 `size/sidebar-w`（收起 `size/sidebar-w-collapsed`）/ chrome 底（§2.2） |
| 右侧主区 | 页面头部 | 页面内容 | 省略 | flex / `plain` |
| 列表页 · 筛选面板 | 省略 | 筛选表单 | 省略 | flex · 高 hug / `card` |
| 列表页 · 表格面板 | 省略 | 工具条 + 表格 + 分页（§5.1） | 省略 | flex · 高撑满 / `card` |
| 编辑抽屉 | 对象名 + 引用徽标 | 表单 | 动作条 | 全高浮层 · 宽逐页定 / `card` |
| 详情二级页 | 面包屑 + 引用徽标 | 分区内容 | 操作条 | flex · 撑满 / `card` |
| 画布页 | 页面头部 | 画布（不滚动，平移缩放；检查器为浮动 `card` 面板） | 省略 | flex / `plain` |

## 4. 浮层 Overlay

> Figma：Section `规范 · 浮层`

### 4.1 同构、尺寸与定位

抽屉与模态是面板原语的**浮层形态**：继承三段式与头 / 底固定规范，差异仅在圆角档、遮罩与定位。

| 浮层 | 尺寸 | 定位 |
|---|---|---|
| 抽屉 Drawer | **一律全高**（贴视口右缘，自 y=0 至底，覆盖 Sidebar 与 PageHeader）；宽度逐页自定义 | 右侧滑出 |
| 模态 Modal | 宽高均可逐页自定义，但不得超出视口可用尺寸 | 见下方定位规则 |

**模态定位规则**：模态高度 **≤ 视口高度 50%** 时，距视口上边界 **20%**（高位置，视线焦点处）；**其余情况一律垂直居中**。

**圆角**：见 [07 §3.2](07-主题与设计系统.md)——悬浮浮层四角取浮层档；**抽屉仅左侧两角取浮层档，贴视口边一侧为直角**（贴边角做圆会在视口边缘露出缺口）。

**遮罩**：色值取 antd `colorBgMask`；范围与层级不另立规范，按 antd 默认行为，逐页只声明尺寸。

### 4.2 三段式与底部动作条

**结构通则**（抽屉与模态共用）：

- **三段式**：头部（标题 + 关闭）与底部（动作条）固定，**中间区域滚动**。
- **尺寸不写死在规范里**：宽高一律由组件 prop 传入（`Drawer width` / `Modal width`），逐页声明。
- **按钮配置与文案走 prop**；两个按钮都显示时布局为 **`[取消] [确定]`**（取消在左、主操作在右），右对齐。
- **底部变体 · 分页型**：当浮层主体装的是表格时，底部为 **flex 两端对齐**——左侧分页控件、右侧动作按钮。
- 头 / 底分隔线按 §3.1 的例外：**抽屉有、模态无**。

**显示哪个按钮、按钮什么型，规范不定死，由页面按语义传入**（`okButtonProps` / `cancelButtonProps` / `footer`）。判据：动作是「完成 / 知道了」性质 → 取 **ok**（主按钮 solid）；是「退出 / 我不做了」性质 → 取 **cancel**（次级 outlined）。

### 4.3 确认框

**不是我们设计的模态，而是 antd `Modal` 的方法函数**。布局由 antd 提供（图标与标题同处第一行、内容另起一行、底部动作条），我们**只配置参数**：

```tsx
const [modal, contextHolder] = Modal.useModal()   // ⚠️ 必须用 hook 版

modal.confirm({
  icon: <ExclamationCircleFilled />,              // 破坏性操作用错误色
  title: '确认删除元字段',
  content: '删除后不可恢复。该元字段当前未被引用，可安全删除。',
})
```

> ⛔ **必须用 `Modal.useModal()` + `contextHolder`，不能用静态的 `Modal.confirm()`**——静态方法通过 `ReactDOM.render` 另起实体，**拿不到 `ConfigProvider` 的上下文**，确认框会渲染成 antd 默认主题，与全站配色脱节。

**按用途分三型，按钮显示随之不同**：

| 型 | 何时用 | 按钮 | 落地 |
|---|---|---|---|
| **确认型** | 确认之后**有后续操作**（发请求、落库、跳转） | `[取消] [确认]` | `modal.confirm({...})` |
| **告知型** | 只**告知结果**，用户无分支可选 | **只有确认按钮** | `modal.info` / `success` / `error` / `warning` —— 这四个方法不渲染取消按钮（antd 文档中 `cancelText` 标注为「Text of the Cancel button **with `Modal.confirm`**」） |
| **卡口型** | 操作**被拦住**，用户做不了、只能退出 | **只有取消按钮** | `modal.confirm({ footer: (_, { CancelBtn }) => <CancelBtn /> })` |

卡口型走 `footer` 的**渲染函数**形态，只渲染取消按钮——不要用 `display: none` 藏按钮：

```tsx
modal.confirm({
  icon: <ExclamationCircleFilled />,
  title: '无法导入该工作空间包',
  content: '该 .flowpack 由更高版本导出，当前版本无法读取。升级后重试。',
  footer: (_, { CancelBtn }) => <CancelBtn />,
})
```

> ⚠️ **卡口型不是「禁用按钮」的替代品**，判据见 §8.4：**能提前判定的拦截一律用禁用 + Tooltip**（如被引用禁删），卡口型只用于**动作发起后才知道被拦**的情形（导入包版本不兼容、云端不可达、落库时才暴露的冲突）。

> `Modal.method()` 的 `footer` 类型为 `ReactNode | (originNode: ReactNode, extra: { OkBtn: React.FC, CancelBtn: React.FC }) => ReactNode`，渲染函数形态自 **antd 5.9.0** 起提供（本项目 6.x，可用）。`footer: null` 则完全不要默认按钮。
> 查证：[ant.design/components/modal](https://ant.design/components/modal/#modalmethod) 的 Modal.method() 属性表，2026-08-12 核实。

- 文案用 `okText` / `cancelText` 改；`icon` 逐型给（破坏性用 `colorError`，见 [07 §6](07-主题与设计系统.md) 偏离项 9）。
- 其余一律走 antd 默认：宽 416、`closable: false`、`okType: primary`。
- 破坏性动作（删除元字段 / 删节点 / 删实例 / 断开云 / 导入替换工作空间）**一律经确认型**，不做无确认的直接删除。

### 4.4 弹层四级分工

| 载体 | 用途 |
|---|---|
| 整页 | 控制台六页、执行页 |
| 抽屉（右侧滑出） | 轻对象编辑表单、只读快照查看、节点详情速览 |
| 模态 | **引用清单 / 影响提示**、发布校验与确认、冲突三选一、破坏性确认、新建实例 |
| Toast | 保存成功、同步完成等瞬时反馈，**不承载错误详情** |

判据：需要对照上下文看的用抽屉，需要打断决策的用模态。结构规范见 §4.1–§4.2。

**引用清单统一为模态**：一个装表格的模态，列出引用方（哪些节点模型 / 流程草稿在用），底部**仅一个「关闭」按钮**（按 §4.2 判据属「知道了」性质，取主按钮）。全站唯一载体——元字段、节点模型、流程的引用清单与改动影响提示都走它，**不做抽屉、不做就地展开、不做 Popover**。

## 5. 表格 Table

> Figma：Section `规范 · 表格`

### 5.1 通用表格页布局

配置对象的列表页一律采用本型；**筛选面板与分页两部分皆可省**，没有筛选项或不分页的表格页由本型退化而来。

```
PageBody（padding space/inner）
┌─ 筛选面板 card · flex · 高 hug ──────────────────────────────┐
│ [名称 🔍] [数据类型 ▾] [引用状态 ▾]           [重置] [查询] │
└──────────────────────────────────────────────────────────────┘
                    ↕ space/panel-gap
┌─ 表格面板 card · flex · 高撑满 ──────────────────────────────┐
│ 元字段列表                                   [+ 新增元字段]  │ ← body 顶部工具条
│  ─────────────────────────────────────────────────────────   │   （随内容滚走）
│ │名称    字段键    类型   被引用   更新时间   操作         │ │ ← thead sticky
│ │…                                          （滚动区）     │ │
│  ─────────────────────────────────────────────────────────   │
│ 共 6 条                [20/页 ▾] ‹ 1 2 › 跳至 [ ] 页        │ ← sticky bottom
└──────────────────────────────────────────────────────────────┘
```

**表格面板既无 `panel.header` 也无 `panel.footer`**——工具条、表格、分页器全部位于面板 `body` 内：

| 段 | 规格 |
|---|---|
| 工具条 | 位于 body 顶部；左 = 列表标题（`text/body-strong`），右 = 主按钮。**随内容滚走**，不吸顶 |
| 表格 | 见 §5.2–§5.3 |
| 分页器 | 见 §6 |

**布局三变体**（Figma 帧 `279:357`）：

| 变体 | 构成 | 适用 |
|---|---|---|
| **A · 完整型** | 筛选面板 + 表格面板（工具条 + 表格 + 分页） | 数据量会增长、且有可筛项的配置对象列表页——**默认型** |
| **B · 无筛选** | 只有表格面板，顶边直接贴 PageBody 的 padding | 无可筛维度、或条目本就少到不必筛的列表 |
| **C · 无分页** | 保留筛选面板，表格面板内无分页器，滚动区直抵面板 padding 内边界 | 条目数有天然上限、一屏可滚完的列表 |

- 省略的是**段**，不是**结构**——三型共用同一套面板原语与皮肤。
- B 型不出现 `space/panel-gap`（面板只有一块）。
- 三型的 PageBody padding 恒为 `space/inner`；表格面板恒为 flex 撑满剩余高度，**不按内容 hug**。

### 5.2 单元格与列类型

> Figma：帧 `279:347`

| 形态 | 规格 | 用在 |
|---|---|---|
| 纯文本 | `--text` + `text/body` | 「名称」等纯展示文本列 |
| 等宽 mono | `text/mono` + `--text` | 字段键 / ID / 结构预览 |
| Tag 型 | kit `Tag`（`Variant=filled` / `Color=default`）：底 `--fill-muted`、字 `--fill-muted-fg`、文字 `text/mono-badge`、圆角 `borderRadiusSM` | 数据类型等枚举列。中性填充一律用 `--fill-muted` 组，**不借用「未开始 / 已跳过」状态色**（[07 §2.3](07-主题与设计系统.md)） |
| **可点链接态** | 文字 `--primary-hover`、**hover 出下划线**、鼠标 pointer | 仅用于承载「跳转 / 打开浮层」语义的单元格（如「被引用」列点开引用清单模态） |
| 时间 | `--text` + `text/body`，格式 `YYYY-MM-DD HH:mm` | 更新时间等 |
| 操作列 | 固定 `[编辑] [删除]` 两个**文字按钮**，不用 `⋯` 折叠菜单 | 恒为最后一列 |

- **纯展示单元格保持 `--text`，不得与链接态混用**——颜色是「这里可点」的唯一提示，混用即失效。
- **列对齐**：**全部列文本左对齐**（含表头与操作列），不做数值右对齐。
- **操作列恒为最后一列**，其余列序由该页规范（09）声明。
- 删除**一律走确认框**（§4.3 确认型）；被引用时删除按钮**禁用** + Tooltip 说明原因（§8.4）。

### 5.3 行与表头

> Figma：帧 `279:352`

| 项 | 规格 |
|---|---|
| 表头底 | `Table/headerBg` → `colorFillTertiary`（暖）——由组件自身接线承载，本地不另设 token |
| **表头 sticky** | 开启。滚动时表头吸到**表格面板顶部**，**不是视口顶部**（页面级永不滚动，一切滚动发生在面板主体内，§2.1） |
| 行 hover | 底取 `Table/rowHoverBg`（暖），**行文字色不随 hover 变化** |
| 行点击 | 整行是否可点由该页规范声明；可点时 hover 反馈作用于整行而非单个单元格 |
| **默认配置** | `size="medium"`、`bordered={false}`、**列不带 `sorter` 与 `filters`**——确有需要的列由该页规范**显式声明**，不声明即不开 |

- **筛选归属**：筛选一律走上方独立的筛选面板（§7），**不用表头 filters 漏斗**。
- **实现注意**：`Table/headerBg` 解析到 `colorFillTertiary`，是**带透明度的填充**。表头 `sticky` 时靠表格自身 `--surface` 白底兜住才不透出滚动行——**日后若把 `headerBg` 改成半透明自定义色、或让表格坐在非白底上，sticky 表头会穿帮**。

### 5.4 空态 / 错误态 / 加载态

> Figma：Section `规范 · 空态`

三态都发生在**表格区内部**——工具条、筛选面板、表头**保持可见**（否则用户无从重置筛选或新建）。

| 态 | 呈现 |
|---|---|
| 空数据 | 空态插画（§9.2，高 160，与文案间距 `space/inner`）+ **单行**文案「暂无〈对象名〉数据，刷新列表」，「刷新列表」为文案内的**内联链接**（`--primary-hover`），点击**重新发起请求** |
| 请求异常 | **同一张插画** + 单行文案「请求出错，重新请求」，「重新请求」同为内联链接，点击重新发起请求 |
| 加载中 | `Table` 的 `loading` prop（表格区遮罩 + 转圈），遮罩只盖表格区 |

- 文案**一律单行不换行**，动作是文案里的内联链接，**不做独立按钮**。
- **「筛选后无结果」不单独区分**，与空数据同一呈现与文案。

## 6. 分页器 Pagination

> Figma：Section `规范 · 分页器`

**归属**：分页器属 `Table` 的 `pagination`，位于表格面板 `body` 内，**不是面板底部段**（表格面板既无 `panel.header` 也无 `panel.footer`）。

**参数**：`total` 传总条数（「共 N 条」由此渲染）；`showSizeChanger` 与 `showQuickJumper` **均开启**；默认每页 **20**，档位 `10 / 20 / 50 / 100`。

**排布**：**总数在最左、分页控件在最右**（两端对齐）——antd 把 `showTotal` 渲染在分页控件行内、整块右对齐，故需一处**全站复用**的自定义样式（[07 §6](07-主题与设计系统.md) 偏离项 6），不逐页写。

**sticky bottom 两形态**：CSS `position: sticky; bottom: 0`——

| 形态 | 条件 | 表现 |
|---|---|---|
| A | 表格高 **<** 面板可视高 | 分页器**跟在表格后面，不吸底**；下方留白正常，不拉伸 |
| B | 表格高 **>** 面板可视高 | 分页器**贴住面板底边**；此时表头同时 sticky 在面板顶部 |

**留白与遮挡**（贴底时的关键，四条缺一不可）：

| 要点 | 规格 |
|---|---|
| 上留白 | 分页条**上 padding `space/inner`(16)**——贴底时数据行不得紧贴分页控件 |
| **下不设** | **底部留白由表格面板自身的 `space/inner` padding 提供，不重复设置**——分页条 `padding-bottom: 0` |
| 底色 | 分页条底为**不透明 `--surface`**——半透明会让滚动中的数据行透出来，读成脏底 |
| 不遮挡 | sticky **保留文档流占位**，占位高 = 控件高 32 + 上 padding 16 = **48**。故滚到最底部时**最后一行完整落在分页条上方**，不被压住 |

> 四条是一体的：只加 padding 不给不透明底，滚动行会从留白里透出来；只给底不加 padding，数据行会紧贴分页控件；占位高算漏 padding，最后一行仍会被遮住。

> **不与 `space/panel-gap` 叠加**：分页条紧跟表格，表格与分页控件之间的留白**就是分页条自己的上 padding**（16），不另加面板间距。`space/panel-gap` 管的是**面板与面板之间**（如筛选面板 ↔ 表格面板），分页器与表格同处一个面板内，不适用。

## 7. 筛选表单 FilterForm

> Figma：帧 `321:3900`

**归属**：住在独立的**筛选面板**里（`card` 皮肤、宽 flex、高 hug、内 padding `space/inner`），与表格面板之间 `space/panel-gap`。**筛选面板可省**——没有筛选项的表格页走 §5.1 的 B 型。

**栅格**：grid + 自适应，默认**一行四列**，各列等宽；**行间距 `space/sm`、列间距 `space/md`**。列宽是自适应均分的结果，**不写死定值**。

**按钮块落位三形态**——`[重置] [查询]` **永远位于最后一行最右侧，占据该行剩余列**：

| 筛选项数 | 按钮块落位 |
|---|---|
| 3 项 | 第 1 行第 4 列（占 1 列） |
| **4 项**（正好填满整行） | **另起第 2 行，占满 4 列**并右对齐 |
| 5 项 | 第 2 行第 1 列是第 5 个筛选项，按钮占第 2 行后 3 列 |

> 规则一句话：按钮块永远在最后一行最右，占据剩余列；剩余列为 0（筛选项数是 4 的整数倍）时另起一行占满 4 列。

**控件规约**：

- **内联 label 用控件的 `prefix` 属性实现**，不另起独立 label 元素——antd v6 的 `Input` 与 `Select` 均支持 `prefix`。标签文字取 `text/label` + `--text-secondary`。
- **每一项必须有 placeholder**：输入类为「请输入〈标签〉」，选择 / 日期类为「请选择〈标签〉」。标签与 placeholder 一起把「这格填什么」说清楚，不靠外部说明文字。
- 控件高 `controlHeight`、圆角 `borderRadius`；宽度由栅格列宽决定，**不设最小宽、不逐项写死**。
- 按钮：查询为主按钮（solid），重置为次级（outlined）；两者间距 `space/sm`。
- **不做「展开更多筛选」**——真出现塞不下的页面再加，不破坏本型结构。
- 表单体系：筛选表单同样走 `Form` + `Form.Item`（§9.1），它没有必填星号与错误文案，但收值、重置仍交给 `Form`，不手工拼。

> **kit 缺口（画稿限制，非设计意图）**：kit 的 `Select` / `.Selector` / `.Select Item` 都没有 prefix 槽，Figma 稿里用「叠加 label 文本 + 顶开 paddingLeft」等效表达。**代码走 antd 原生 `prefix`，间距由组件自身给出**，不要照抄稿子里那个 paddingLeft。

## 8. 全局交互范式

### 8.1 保存模型（混合）

- **表单类显式保存**（元字段、节点模型、驱动绑定）：编辑产生脏标记，点保存落库；「必需槽位未解析禁止保存」由保存按钮禁用逻辑承载。
- **流程画布即时自动保存**：增删节点、连线、拖动位置即时写入草稿——草稿允许不完整，发布门全量校验兜底。
- 关闭带脏标记的表单页给未保存确认。

### 8.2 撤销 / 重做

画布结构操作支持 `Ctrl+Z / Ctrl+Y`（会话级内存栈，不持久化）；表单类不做 undo（显式保存天然可弃改）。

### 8.3 校验反馈三级

1. **字段级**：失焦即时标红（必填、正则、类型）。
2. **对象级**：点保存时汇总（驱动槽位完整性等）。
3. **流程级**：发布时全局校验面板（六层全跑）。

画布上节点校验问题实时显示角标（如缺驱动输入）。

### 8.4 禁用与原因说明

**被引用禁删的呈现**：删除按钮**禁用**，并以 **Tooltip 说明禁用原因**（如「被 3 个节点模型引用，解除引用后方可删除」）。实现须给按钮套一层可接收事件的包裹元素（[07 §6](07-主题与设计系统.md) 偏离项 7）——HTML `disabled` 元素不派发指针事件，Tooltip 不会触发。

**通则**：凡禁用一个动作，**必须给出禁用原因**，且原因挂在被禁用的控件上（Tooltip），不另起提示区。

**拦截该用禁用还是用卡口型确认框**——按「**能不能提前判定**」分：

| 情形 | 呈现 | 例 |
|---|---|---|
| **点之前就知道会被拦** | **按钮禁用 + Tooltip 说明原因**，点不动 | 被引用禁删、必需槽位未解析禁止保存、无改动时禁用保存 |
| **点之后才知道被拦** | **卡口型确认框**（§4.3），只有取消按钮 | 导入包版本不兼容、云端不可达、落库时才暴露的冲突 |

> 判据是**防患于未然优先**：能在点击前就挡住的，绝不让用户点下去再弹窗告诉他不行。卡口型是兜底，不是省事的替代品。

## 9. 组件约束

### 9.1 控件约束

- **一切表单一律用 `Form` + `Form.Item`**（含筛选表单、编辑抽屉、驱动绑定表单）——必填星号、校验触发、错误文案位置全部交给 Form 体系，不手工拼 label 与错误提示。
- boolean 运行字段用**三态控件**（未设置 / 是 / 否）；空输入保存 = 显式清空（[01 §2.5](01-领域模型与协议.md)）。
- 受阻补值表单**预填快照默认值**作建议（仅建议，保存才落日志）。
- `link` 仅 `https / http / mailto` 渲染为可点击链接，其余纯文本；helpText / description 一律纯文本（[01 §2.6](01-领域模型与协议.md)）。
- 完成度显示格式「完成 3/5 · 跳过 2」，分母不含跳过（[02 §8](02-状态引擎规范.md)）。
- 导入 = 替换工作空间的破坏性确认框，含「已自动备份」提示（[04 §3](04-存储与同步规范.md)）。
- **状态徽章**：底 = tint（色阶第 1 阶）、**文字 = Active（第 7 阶）**、图标 = 基色（第 6 阶）——文字取深阶是无障碍要求（[07 §2.5](07-主题与设计系统.md)）。

### 9.2 自研组件清单

antd 覆盖不了、需自研的组件：条件树构建器、boolean 三态控件、画布节点卡与连线、驱动槽位绑定行、**空态插画**。规格随对应页面设计沉淀（09）。

**空态插画**（全站空态与错误态共用一张）——源文件 [`docs/assets/empty-state.svg`](assets/empty-state.svg)：

- **造型**：一卷空白文档（左侧卷边、纸面留七条白色占位横线与一块方形占位）+ 柔和落影；一条**虚线自纸张右缘引出**（起点**贴住纸缘**，不留空隙），**绕一个小圈后向右上方扬起**，末端为实心箭头。语义为「数据卷走了」。
  > 入口段（纸缘 → 绕圈）须明显短于出口段（绕圈 → 箭头），约 132 : 258。**做法是把绕圈整体靠近纸张，而非缩短起点**——缩起点会让虚线脱开纸缘。
- **尺寸**：**高 160**（宽 215，比例 1.35）。`viewBox` 已裁到可见内容边界，故 160 即真实可见高度。
- **与文案间距** `space/inner`。
- **配色全取 07 §2.4 主色七阶，零新增 token**——插画内用六个 CSS 变量参数化：

  | 变量 | 值 | 来源 | 用途 |
  |---|---|---|---|
  | `--nd-paper-light` | `#D5C6B2` | `colorPrimaryBgHover`（阶 2） | 纸面渐变浅端、翻卷高光 |
  | `--nd-paper` | `#BCA58A` | `colorPrimaryBorder`（阶 3） | 纸面渐变中段 |
  | `--nd-paper-dark` | `#A28869` | `colorPrimaryBorderHover`（阶 4） | 纸面渐变深端、卷边起始 |
  | `--nd-arrow` | `#8A6F52` | `colorPrimary`（阶 6） | 虚线轨迹与箭头、卷边末端 |
  | `--nd-shadow` | `#D5C6B2` | `colorPrimaryBgHover`（阶 2） | 落影（径向渐变 α .48 → .12） |
  | `--nd-detail` | `#FFFFFF` | 白 | 纸面占位横线与方块 |

- **落地方式：全局只替换图，文案逐页给**。`ConfigProvider` 的 `renderEmpty` 在应用根部统一接管，所有吃 `Empty` 的组件一次性换成本插画；**全局不设 `description`**：

  ```tsx
  <ConfigProvider
    theme={flowcanvasTheme}
    renderEmpty={() => (
      <Empty image={<EmptyIllustration />} styles={{ image: { height: 160 } }} />
    )}
  >
  ```

  **文案属页面语义**（含对象名与内联动作），由各页在自己的 `Empty` / `Table.locale.emptyText` 处传 `description` 覆盖。尺寸一律走 `styles.image`。
- **不写进 `@ant-design/icons`**：icon 体系的三条硬假设与本插画全部冲突——单色跟随 `currentColor`、尺寸 1em 随字号、语义是可复用符号。插画作为自研组件放 `components/illustrations/`。
