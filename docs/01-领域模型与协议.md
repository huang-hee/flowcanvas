# 01 · 领域模型与协议

> 文档状态：正式方案 v1.1（2026-08-09 评审定稿；2026-08-18 元字段三分与筛选配置评审，见 00 决策 44–49）
> 依赖：[00-术语表与总览](00-术语表与总览.md)

## 1. 协议原则

1. **zod 为唯一真相源**：所有对象的协议用 zod schema 定义于 `packages/core`，TS 类型经 `z.infer` 推导，运行时校验与静态类型永不漂移。本文档中的 TS 接口是协议的可读投影。
2. **生成 ID 关联，字段键唯一可改**：配置域对象间关联一律使用系统生成 ID（`metaFieldId`、`nodeSchemaId`、`flowId` 等，见 §9）；`fieldKey` 是用户可读、可修改的**字段键**（英文小驼峰，项目内唯一，保存时校验），不承担关联职责，发布时物化进快照供引擎与事件日志使用。`driverCode`、`slotKey` 为内置常量。面向用户的名称为中文且可随时改。
3. **配置域活引用**：配置对象之间通过生成 ID 引用，始终指向最新；固化只发生在发布门（见 [03](03-发布与快照规范.md)）。
4. **JSON 为主格式**：持久化、同步、导出一律 JSON；YAML 仅作为手写配置的导入格式，加载后转为同一对象模型走同一 zod 校验。
5. **禁止文本表达式**：一切「计算描述」（system 槽位、条件）都是结构化对象，由 UI 表单生成、由引擎解释，系统中不存在表达式 parser，不存在 `eval`。

## 2. 元字段 MetaField 与两个伴生对象

元字段是可复用的字段定义，类似数据库字段，只定义字段本身，不决定它属于哪个节点模型。

**元字段三分**（00 决策 44）：字段相关的配置分属三个对象，拆分判据是**改了它，已经存下来的数据要不要跟着动**——

| 对象 | 装什么 | 改了它数据要动吗 | 快照行为 |
|---|---|---|---|
| `MetaField` | 身份、数据类型、类型参数（精度 / 单位 / 枚举选项 / 子项类型）、默认值、帮助文字 | 要（改精度历史值要重新归一，改类型语义全变） | 进快照 |
| `FieldValidateRuleSet` | 校验规则集（§2.1） | 要（改约束会让已存数据变非法） | 进快照 |
| `FieldFilterConfig` | 筛选配置（§2.8） | **不要**（改筛选不影响任何已存数据） | **不进快照，活引用** |

三者均为 1:1 关系，伴生对象随元字段创建、随元字段删除。

```ts
type FieldDataType =
  | "text"        // 文本
  | "multiline"   // 多行文本
  | "number"      // 数字
  | "boolean"     // 布尔
  | "date"        // 日期
  | "datetime"    // 日期时间
  | "enum"        // 枚举
  | "link"        // 链接
  | "file"        // 文件
  | "object"      // 对象（子字段集合）
  | "list";       // 列表

interface MetaField {
  metaFieldId: string;              // 系统生成 ID（如 mf_x7k2），配置域关联一律用它
  fieldKey: string;                 // 字段键：用户可改，项目内唯一（保存时校验），如 title、duration
  name: string;                     // 默认展示名（中文）
  dataType: FieldDataType;
  helpText?: string;
  defaultValue?: unknown;
  inputComponent?: string;          // 输入组件标识，由 UI 层解释
  numberConfig?: NumberConfig;      // dataType = number：精度与单位（§2.7）
  enumOptions?: { value: string; label: string }[];   // dataType = enum
  itemType?: FieldDataType;         // dataType = list：子项类型（含 "object"，此时内部结构在节点组装层组合）
  domain?: string;                  // 字段域（00 决策 48）：协议预留，MVP 校验层仅接受空值，UI 不暴露
  createdAt: string;                // UTC ISO 8601（§2.4）；新建时与 updatedAt 相同
  updatedAt: string;                // 每次保存刷新——列表页「更新时间」列的数据源（09 §2.2）
}
```

元字段保持**原子**：object / list(object) 不在此定义内部结构，内部组合在节点模型层的子组装完成（§3，00 决策 29）。校验规则不在此定义，见 §2.1。

- **字段键可改**（00 决策 31）：关联走 `metaFieldId`，改 `fieldKey` 不断任何引用；唯一性在保存时校验。已发布快照与事件日志中物化的是发布当时的 fieldKey，不受后续改名影响。
- **数据类型随时可改**（00 决策 30）：修改即时反映到引用方草稿，受影响对象走影响提示；非法组合（槽位类型、比较符、默认值）由校验层标红并禁存禁发；执行域因快照隔离永不受影响——与修改 enum 选项同一语义。**改 dataType 会连带使两个伴生对象里的配置失效**（text 的 `maxLength` 对 number 无意义、`contains` 关系对 number 非法），保存前弹影响提示列出失效项，确认后自动清理（09 §2.3）。
- **字段域 `domain`**（00 决策 48）：设想中「通用域」的字段（标题、状态）在所有场景可用，「业务域」的字段（时长、目标）只在对应业务下可用，页面亦带域属性、两边匹配时字段才出现。**协议全量、校验限阶段**——zod 定义好该字段，MVP 校验层仅接受空值，UI 不暴露入口，开放时零迁移。单值，一个字段一个域。

### 2.1 校验规则集 FieldValidateRuleSet

校验规则从元字段中**拆出为独立对象**（00 决策 44），1:1 挂靠元字段：

```ts
interface FieldValidateRuleSet {
  ruleSetId: string;                // 系统生成 ID（如 vrs_x7k2）
  metaFieldId: string;              // 挂靠的元字段，1:1
  rules: ValidationRule[];
  createdAt: string;
  updatedAt: string;
}
```

用户在 UI 里配置出来的校验规则是**数据**，由引擎解释执行，不是代码，也不是 JSON Schema：

```ts
type ValidationRule =
  | { rule: "minLength" | "maxLength"; value: number }     // 文本类
  | { rule: "pattern"; value: string }                     // 正则字符串，编译失败即配置错误
  | { rule: "min" | "max"; value: number }                 // 数字
  | { rule: "minItems" | "maxItems"; value: number }       // 列表
  | { rule: "earliest" | "latest"; value: string }         // 日期类，ISO 字符串
```

- 规则集合按数据类型约束合法组合（zod 层校验）：如 `pattern` 只允许出现在文本类字段上。
- **`required` 不在此枚举中**（00 决策 45）：必填是「这次使用」的约束不是数据本身的属性，唯一出处是 `FieldBinding.required`（§3），字段层根本没有这个选项，不存在优先级问题。
- **校验分两层**（00 决策 45）：本对象放**数据本身的格式约束**（邮箱正则、0–100 范围）——换哪个节点模型都成立；`FieldBinding.validations` 放**这次使用的约束**（必填、这里最多 50 字）。合并规则见 §3。
- **进快照**：改校验会让已存数据变非法，必须冻结在发布当时的状态，否则撞上决策 10「实例不受后续配置修改影响」。

### 2.2 示例：学习任务用到的元字段

| fieldKey | 类型 | 说明 |
|---|---|---|
| `title` | text | 标题，在不同节点模型可覆盖为「任务名称」「内容标题」 |
| `description` | multiline | 描述 |
| `documents` | list(link) | 在线文档列表 |
| `duration` | number | 预计时长（时长即数字，单位在驱动绑定处指定） |
| `done` | boolean | 完成标记（供子组装引用） |
| `taskItems` | list(object) | 待办子任务列表；内部结构在节点模型层子组装（引用 `title`、`done`） |

### 2.3 时长的表示（无 duration 字段类型）

时长不是独立字段类型——**时长即数字**（00 决策 32）：如 `预计时长` 就是 number 字段。结构化时长 `{ value, unit }`（即 `DurationOffset`，§5）仅存在于**驱动槽位与偏移**：

- 槽位类型 `duration`（§4）为槽位专属类型，不出现在 `FieldDataType` 中；
- constant 来源 → `{ value, unit }` 表单；
- field 来源 → 绑定 number 字段：字段挂了时间单位组（§2.7）则**单位自动继承**；未挂组则在绑定处指定（`InputSource.unit` 兜底）；
- 时间计算（如 `due = startAt + duration`）先按单位归一化到分钟。

### 2.4 时间与时区语义

- `datetime` 时间戳（含事件 `occurredAt` / `recordedAt`、重算参数 `now`）一律 **UTC ISO 8601 存储、本地时区渲染**。
- `date` 为无时区日历日（`YYYY-MM-DD`），「已过 / 未到」等判定按**用户本地日历日**解释；跨时区使用同一实例时判定可能相差一天，属已知妥协，不引入字段级时区。

### 2.5 空值与清空归一化

运行字段不存在空串、空白这类「伪值」：UI 保存时按下表把空输入归一化，显式清空落日志为 `field.valueSet` 且 `value: null`（求值规则见 [02 §5.1](02-状态引擎规范.md)）。

| 数据类型 | 空输入处理 |
|---|---|
| text / multiline | trim 后为空 → `null`（清空） |
| number / date / datetime | 输入清空 / 选择器清除 → `null` |
| enum | 选「未选择」→ `null` |
| link / file | 移除 → `null` |
| list | 删光子项 = 值 `[]`，是合法值不是清空（无 null 清空入口）；聚合条件按 §6 空列表语义求值 |
| boolean | 三态控件（未设置 / 是 / 否），「未设置」→ `null`；list / object 内部的 boolean 子项由子项编辑器给明确初值（如新增子任务 `done` 初始 false），无三态 |
| object | 无整体清空，子字段各自按本表归一 |

### 2.6 渲染安全约束

- `link` 值仅当协议为 `https` / `http` / `mailto` 时渲染为可点击链接，其余协议一律按纯文本展示（杜绝 `javascript:` 注入）。
- `helpText`、`description` 及一切用户可配置文案一律纯文本渲染，不支持 HTML / Markdown / 富文本。

### 2.7 数字精度与单位（00 决策 33/34）

```ts
interface NumberConfig {
  precision: number;                // 小数位 0–6，默认 0（整数）
  unit?:
    | { kind: "label"; text: string }                          // 纯标注：仅展示，无机器语义
    | { kind: "grouped"; unitGroupId: string; code: string };  // 挂单位组：引擎可换算
}

interface UnitGroup {
  unitGroupId: string;              // 内置常量，MVP 仅 "time"
  name: string;
  baseUnit: string;                 // 基准单位 code
  units: { code: string; label: string;
           factor: number;         // value_base = value × factor + (offset ?? 0)
           offset?: number }[];    // 温度类 affine 预留，MVP 无温度组
}
```

- **精度即真相**：保存时按 precision **四舍五入**（round half away from zero，规则写死）后才落 `field.valueSet`——所见 = 所存 = 所比；条件树 constant target 按字段 precision 同步归一；zod 以 `multipleOf` 量级校验。
- **单位组内置、不可改**，随代码发布（同驱动方案），发布时把引用到的组固化进快照。MVP 仅「时间」组：minute(1) / hour(60) / day(1440) / week(10080)，基准 minute。
- **换算只在引擎内**：重算时归一到基准单位参与计算；**日志永远存输入原貌**。跨组禁止换算；货币、计数类无换算语义 → 用纯标注。
- 挂时间组的 number 字段绑定 duration 槽位时**单位自动继承**（§2.3）；`InputSource.unit` 降级为未挂组字段的兜底。
- 草稿域修改精度 / 单位 = 语义重释，与改类型同级（影响提示 + 校验兜底）；已发布快照不受影响。

### 2.8 筛选配置 FieldFilterConfig（00 决策 47）

声明**这个字段怎么被筛**，1:1 挂靠元字段。它与校验规则集是两个对象而非一个，根本原因是**快照行为相反**：改校验会让已存数据变非法（必须冻结），改筛选一条数据都不动（应当活引用）。

```ts
interface FieldFilterConfig {
  filterConfigId: string;           // 系统生成 ID（如 ffc_x7k2）
  metaFieldId: string;              // 挂靠的元字段，1:1
  enabled: boolean;                 // 是否启用筛选，默认 false（§2.8.1）
  defaultOperator?: CompareOperator;// 简单筛选栏用的关系；不填则取该 dataType 的内置默认
  optionSource:
    | { kind: "none" }                          // 不配候选值 → 自由输入 / tags
    | { kind: "field" }                         // 用元字段自己的 enumOptions（仅 enum 可选）
    | { kind: "custom"; options: string[] };    // 自定义候选值
  createdAt: string;
  updatedAt: string;
}
```

#### 2.8.1 规则

- **必须显式启用**（`enabled` 默认 `false`）：不启用的字段不出现在任何筛选入口。这是为**服务端索引优化**留的路——只给声明过的字段建索引，同 Algolia `attributesForFaceting` 的取舍。
- **没有 `filterType`**：筛选可用的关系直接跟 `dataType` 走（§6.1 一张表），不存在「筛选类型 ≠ 存储类型」的第二套类型系统。值控件形态由「**当前选中的关系 + 有没有配候选值**」两个维度决定，不按字段固定、也不按关系写死。
- **候选值字段级配一次**：同一字段在不同关系下的可选值不会不同，区别只在单选还是多选。
- **候选值只对 `text` / `multiline` / `enum` 开放**：date / boolean / number / link / file / list 的关系都不需要候选值（number 的「等于某几个预设值」已由 00 决策 46 判定与区间重复，不开）。
- **`{ kind: "field" }` 仅 enum 类型可选**：其余类型没有 `enumOptions` 可继承，只能选 `none` 或 `custom`。enum 字段的 `enumOptions` 为空时该项仍可选，候选值随之为空，待补全 enum 选项后自动生效。
- **`custom.options` 存数组**：UI 输入形态是逗号隔开的纯文本，保存时切分、去空格、去重、去空项后存为数组。
- **不进发布快照，活引用**（发布门的例外，见 [03 §2](03-发布与快照规范.md)）：筛选不产生事实、不参与状态重算，固化它只会让老实例永远用不上后来改好的筛选。
- **内置默认关系**：`text/multiline → contains`、`number → eq`、`date/datetime → between`、`enum → eq`、`boolean → eq`、`link/file → contains`、`list → any`。

#### 2.8.2 两种筛选形态共用一套协议

筛选条件的载体就是 §6 的条件树，不另立结构：

| | 自定义条件 | 简单筛选栏 |
|---|---|---|
| 且 / 或 | 用户选 | 锁死 `and` |
| 嵌套 | 可以 | 只有一层 |
| 关系 | 用户从该类型的关系里选 | 取 `defaultOperator` |
| 字段 | 用户自行组装 | 页面预先摆好 |

简单筛选栏是自定义条件的**受限投影**，不是另一套数据结构。

#### 2.8.3 实施边界

**配置端 UI 进 MVP**（元字段的规则配置二级页，09 §2.6）；**消费端 UI 不进 MVP**——列表筛选栏、「添加筛选项」组装、筛选侧的字段源与值控件全部挂起，协议先行。挂起的原因是**落点未定**（筛选发生在哪一页、筛的每一行是什么），不是组件成本。

> **条件树构建器不在挂起之列**：它因条件驱动的 `condition` 槽位而必须实现（[08 §9.2](08-交互规范.md)），且被要求做成字段源与值渲染可注入，筛选消费端开工时直接复用。

消费端开工时才需要落地的挂起项：筛选项组装状态存 `viewState` 仓、否定类关系「不含未填写」的 UI 补偿提示。

## 3. 节点模型 NodeSchema

节点模型 = 元字段的集合 + 可选的默认驱动绑定。**没有版本字段**——配置对象不做多版本管理（决策 10）。

```ts
interface NodeSchema {
  nodeSchemaId: string;
  name: string;                     // 如「学习任务」「审批节点」
  description?: string;
  fieldBindings: FieldBinding[];
  defaultDriverBinding?: DriverBinding | null;  // 空 = 默认人工生命周期
}

interface FieldBinding {
  metaFieldId: string;              // 活引用元字段（生成 ID 关联）
  displayName?: string;             // 覆盖展示名：同一 title 在此处可叫「任务名称」
  required?: boolean;               // 必填——唯一出处（00 决策 45），字段层无此选项
  defaultValue?: unknown;           // 覆盖默认值
  validations?: ValidationRule[];   // 这次使用的额外约束（00 决策 45），合并规则见下
  order: number;                    // 字段顺序
  runtimeComponent?: string;        // 覆盖执行时输入组件
  itemBindings?: FieldBinding[];    // 仅 object / list(object) 字段：子组装，递归复用本结构
}
```

**子组装规则**（00 决策 29——组合上移到节点组装层）：

1. 子组装只能引用**基础类型**元字段，object / list 类型不得进入子组装——结构性限深两层；
2. 子绑定递归复用 `FieldBinding`，displayName / required / defaultValue / **validations** / order 覆盖同样生效（00 决策 45）——不让 `validations` 递归会造成「必填能覆盖、长度不能覆盖」的分裂；
3. enum 选项与 list(基础类型) 的 `itemType` 留在元字段上——它们是类型参数，不是组合；
4. object / list(object) 不提供整体 defaultValue（元字段与绑定层均禁止），默认值由子字段承担；
5. 子组装为空 → 禁止保存；
6. 同一子组装内不得重复引用同一元字段（保证条件树点路径如 `taskItems.done` 无歧义）。

**同层唯一，跨层不限**（09 §3）：上条规则同样适用于**顶层** `fieldBindings`——同一节点模型的顶层不得两次引用同一元字段，否则发布展平时会物化出两个相同的 `fieldKey`，条件树路径 `title` 将无法确定指谁。但**层与层之间互不干涉**：顶层用了 `title`，`taskItems` 的子组装里仍可再用 `title`（子任务也有标题），因为两者的条件树路径分别是 `title` 与 `taskItems.title`，天然无歧义。

**默认值兜底边界**：`defaultValue`（元字段或此处覆盖）只对**从未写过值**的字段兜底；显式清空（`value: null`）后不回落默认值（见 [02 §5.1](02-状态引擎规范.md)）。

### 3.1 校验的两层合并（00 决策 45）

字段层（`FieldValidateRuleSet.rules`，§2.1）与集合层（`FieldBinding.validations`）**按规则类型合并**：

| 情况 | 结果 |
|---|---|
| 同类规则两层都有 | **集合层覆盖字段层** |
| 只有一层有 | 直接生效 |
| `required` | 只可能来自集合层——字段层没有这个规则 |

```
字段层： pattern 邮箱正则、maxLength 200
集合层： maxLength 50、required
最终：   pattern 邮箱正则 + maxLength 50 + required
```

判据是「**这条规则换一个节点模型还成立吗**」：成立的（邮箱正则、0–100 范围）归字段层，不成立的（必填、这里最多 50 字）归集合层。

## 4. 驱动方案 DriverDefinition

第一版提供三个**内置、可配置、不可脚本扩展**的驱动方案。驱动方案声明输入契约与输出契约，本身不拥有节点字段。

```ts
interface DriverDefinition {
  driverCode: "time" | "condition" | "event";
  name: string;
  inputSlots: DriverInputSlot[];
  outputContract: {
    lifecycles: Lifecycle[];        // 能产出的生命周期状态
    attentions: Attention[];        // 能产出的关注状态
  };
  supportsAutoCompletion: boolean;  // 是否支持 auto 完成模式（阶段三生效）
}

interface DriverInputSlot {
  slotKey: string;
  dataType: FieldDataType | "duration" | "conditionTree" | "eventMatcher";   // duration 为槽位专属类型（§2.3）
  required: boolean;
  allowedSources: ("field" | "system" | "constant")[];
  defaultSource?: InputSource;      // 有默认来源的槽位直接展示默认值，不出现未解析空值
}
```

### 4.1 三个内置驱动方案

| 驱动 | 输入槽位 | 输出契约 | auto 支持 |
|---|---|---|---|
| **时间驱动** `time` | `startAt`(datetime, 必需, 默认 `system(previous.readyAt)`)；`duration`(duration, 必需)；`dueSoonThreshold`(duration, 必需, 默认 `constant(24h)`) | 等待开始 / 进行中；关注：正常 / 即将到期 / 已超时 | 是（到期自动完成，阶段三） |
| **条件驱动** `condition` | `condition`(conditionTree, 必需, 仅 constant) | 等待开始 / 进行中 | 是（条件达成自动完成，阶段三） |
| **事件驱动** `event` | `activateOn`(eventMatcher, 必需, 仅 constant) | 等待开始 / 进行中 | 是（事件到达自动完成，阶段三） |

事件驱动的边界：**应用内事件 + 手动记录事件**（MVP），外部日志导入阶段三；不接收公网 Webhook；关闭期间不驻留，重开后追算。

匹配器协议为 `{ eventTypes: string[]; nodeId?: string }`（结构见 [02 §6.3](02-状态引擎规范.md)）；**MVP 校验层仅放行匹配 `custom.recorded` 自定义事件（不含 `nodeId` 过滤）**，匹配内置事实类型与 `nodeId` 过滤随阶段三外部日志导入开放——协议全量、校验限阶段，同 completionPolicy 模式，零迁移。

## 5. 驱动绑定 DriverBinding

```ts
interface DriverBinding {
  driverCode: string;
  inputBindings: Record<string, InputSource>;   // key = slotKey，必需槽位必须全部出现
  completionPolicy: CompletionPolicy;
}

type InputSource =
  | { kind: "field"; metaFieldId: string;
      unit?: DurationOffset["unit"] }                         // 节点字段；unit 仅 duration 槽位、且字段未挂时间单位组时使用（兜底，§2.7）
  | { kind: "system"; ref: SystemRef; offset?: DurationOffset } // 系统上下文
  | { kind: "constant"; value: unknown };                     // 固定值

type SystemRef =
  | "previous.readyAt"     // 前序组就绪时刻（见 02 §7），取代旧写法 previous.completedAt
  | "run.startedAt"        // 实例开始时刻（开始元节点完成时刻）
  | "node.activatedAt"     // 本节点进入进行中的时刻
  | "now";                 // 重算时刻

interface DurationOffset {
  value: number;                                // 可正可负
  unit: "minute" | "hour" | "day" | "week";
}
```

> **自指禁令（校验层 5）**：system 引用不得让槽位依赖由它自己决定的输出——`startAt` 槽位禁止使用 `node.activatedAt`（activatedAt 由 startAt 推出，重算无定义）。

时间驱动默认绑定示例（三个必需槽位全部解析，无空映射）：

- `startAt ← system(previous.readyAt, +1 day)`（前序组就绪次日）
- `duration ← field(duration, unit: minute)`（number 字段 + 绑定处单位）
- `dueSoonThreshold ← constant(24h)`

### 5.1 完成策略 CompletionPolicy

```ts
type CompletionPolicy =
  | { mode: "manual" }    // 纯手动：人工点完成（默认，MVP 唯一合法值）
  | { mode: "confirm" }   // 达成后待确认：驱动器达成完成条件 → 建议完成提示 → 人工确认（阶段三）
  | { mode: "auto" };     // 达成即完成：驱动器达成条件自动标记完成（阶段三，驱动器须声明支持）
```

协议 v1 携带完整枚举；**MVP 校验层只放行 `manual`**，UI 不暴露另外两个入口，阶段三开放时零迁移。

### 5.2 绑定完整性规则

- 必需槽位缺来源、字段类型与槽位类型不兼容、override 绑定不完整 → **禁止保存和发布**。
- `auto` 模式要求 `DriverDefinition.supportsAutoCompletion = true`（阶段三校验）。

## 6. 条件树

条件是任意组装的布尔结构：默认多条件平铺即 AND，混用运算符时引入组，如 `a | (b & c & d & e)`、`(a | b) & (c | d) & e`。协议不设深度上限，UI 交互见 [09 §3.5](09-页面设计.md)（条件树构建器首现于节点模型页的默认驱动区；原指向 05 §7 流程画布是悬空引用，已修）。

```ts
type ConditionNode = ConditionGroup | Condition;

interface ConditionGroup {
  op: "and" | "or";
  children: ConditionNode[];        // 递归
}

type Condition =
  | { kind: "compare";
      fieldPath: string;            // 配置域存 metaFieldId 路径（UI 按字段键显示），发布固化为 fieldKey 点路径，如 meta.category
      operator: CompareOperator;
      target?: CompareTarget }      // isEmpty / notEmpty 无 target
  | { kind: "aggregate";            // 列表聚合谓词
      fieldPath: string;
      mode: "all" | "any" | "countAtLeast";
      count?: number;               // mode = countAtLeast 时必填
      item: ConditionNode };        // 子项谓词，递归使用本结构

type CompareTarget =
  | unknown                                     // 常量（默认形态）
  | [unknown, unknown]                          // between / notBetween 的区间端点
  | { kind: "relative";                         // 相对时间（00 决策 46），仅 date / datetime
      value: number;                            // 可正可负
      unit: DurationOffset["unit"] };
```

- **`between` / `notBetween` 的 target 是二元组** `[起, 止]`，zod 强制长度为 2 且 `起 ≤ 止`。
- **相对时间**复用 `DurationOffset` 的 `unit` 枚举，`{ value: -7, unit: "day" }` 表示「7 天前」，求值时以重算时刻 `now` 为基准。**协议全量，MVP 不做 UI**——它的控件是一整套预设选项 + 自定义偏移的组合，留到消费端开工时设计。该结构表达不了「本月」这类自然月边界，属已知缺口，同期补。

「子任务全完成」示例：

```json
{ "kind": "aggregate", "fieldPath": "taskItems", "mode": "all",
  "item": { "kind": "compare", "fieldPath": "done", "operator": "eq", "target": true } }
```

**空列表语义**：`all` 对空列表求值为 **false**——刻意偏离数学惯例（空真）：本产品语境下「全部满足」的配置意图是「存在子项且全部满足」，零子项即达成违反直觉。`any` 对空列表自然为 false；`countAtLeast` 由 zod 强制 `count ≥ 1`，空列表恒 false。

### 6.1 比较符矩阵（00 决策 46）

**同一张表同时服务筛选与驱动器条件树**——不存在两套关系语义。zod 层校验非法组合。

**通用关系**：所有数据类型自动可用，不逐类型声明——任何字段都可能没值。

| 关系 | 含义 | 值控件 |
|---|---|---|
| `isEmpty` | 为空 | 无 |
| `notEmpty` | 不为空 | 无 |

> 「空」的定义：对 `list` 是**空数组**（list 的值永不为 `null`，见 §2.5），对其余类型是 `null`。

**类型特有关系**：

| 数据类型 | 合法比较符 | 值控件 |
|---|---|---|
| text / multiline | `eq` `neq` | 配了候选值 → 下拉单选；没配 → 输入框 |
| | `contains` `notContains` | 输入框 |
| | `in` `notIn` | 配了候选值 → 下拉多选；没配 → `tags` 自由输入 |
| number | `eq` `neq` | 数字框 |
| | `gt` `gte` `lt` `lte` | 数字框 |
| | `between` `notBetween` | 两个数字框 |
| boolean | `eq` `neq` | 是 / 否 |
| date / datetime | `eq` | 日期选择（= 那一整天） |
| | `before` `after` | 日期选择 |
| | `between` `notBetween` | 日期范围，**含首含尾** |
| | `passed` `notReached` | 无（与 `now` 比） |
| enum | `eq` `neq` `in` `notIn` | 下拉，单选 / 多选 |
| link / file | `contains` | 输入框 |
| object | 取子字段路径后按子字段类型使用本矩阵 | — |
| list | `all` `any` `countAtLeast` | 子条件构建器 |
| | `lengthGte` `lengthLte` | 数字框 |

**值控件由「关系 + 有没有配候选值」两个维度决定**，不按关系写死——同一个 `eq`，配了候选值是下拉、没配是输入框（00 决策 47）。

#### 6.1.1 `null` 语义（硬约束）

> **一切比较关系（含 `neq` `notContains` `notIn` `notBetween` 等否定类）对 `null` 一律求值为 `false`；判空只能用 `isEmpty` / `notEmpty`。**

这条对状态引擎的重算行为是硬约束，不得由实现自行决定。采用 SQL-92 的三值逻辑，与全部主流关系数据库（MySQL / PostgreSQL / SQL Server / Oracle / SQLite）一致，筛选条件因此可直接翻译成 `WHERE` 子句而不必为每个否定关系包一层 `OR ... IS NULL`——后者会让索引大概率失效，与决策 47 的索引优化取向冲突。

**已知代价**：`eq X` 与 `neq X` 的结果并集**不等于全集**，没填值的记录两边都不在。补偿放在消费端 UI（`neq` 旁标注「不含未填写」，或提供组合关系），MVP 不做。

**对驱动器的正面作用**：条件「`status ≠ 已完成` 时激活下一节点」在三值逻辑下，用户尚未填写 `status` 时条件不成立、节点不会提前激活——正是配置者的本意。

> **与「缺值即受阻」的分工**：在驱动器条件树里，字段缺值优先触发**受阻**（[02 §5.1 步骤 4](02-状态引擎规范.md)），根本走不到比较求值；唯一例外是该字段**仅被 `isEmpty` / `notEmpty` 引用**时不受阻、照常求值。本节的 `null` 规则因此主要作用于**筛选**场景（那里没有受阻概念）以及上述例外情形。

#### 6.1.2 日期边界语义

| 写法 | 含义 |
|---|---|
| `before X` | 时间点 < X 当日 00:00 |
| `after X` | 时间点 ≥ (X + 1 日) 00:00 |
| `eq X` | X 当日 00:00 ≤ 时间点 < (X + 1 日) 00:00 |
| `between [X, Y]` | X 当日 00:00 ≤ 时间点 < (Y + 1 日) 00:00（**含首含尾**） |

`target` 给到**具体时刻**（含时分秒）时按精确时间点比较，不做日历日归整。日历日按用户本地时区解释（§2.4）。

> **不设** `onOrBefore` / `onOrAfter`：「截止到今天（含）」写作 `before 明天`。这是 00 决策 46 的取舍——边界语义本身已经排除了 X 当日，含边界的需求靠挪一天表达。

#### 6.1.3 明确不纳入的关系

`startsWith` / `endsWith`（中文场景价值低，「包含」已覆盖）、`lengthEq`（无真实场景）、number 的 `in` / `notIn`（区间已可表达）、正则匹配（校验侧已有 `pattern`，筛选侧受众过窄）、**跨字段比较**（`target` 只能是常量，不支持 `{ kind: "field" }`——该类需求走业务逻辑，不做配置化）。以上均为纯加法，日后需要时新增不返工。

## 7. 流程定义 FlowDefinition

流程页面负责组合节点和连线，**不保存执行状态**。

```ts
interface FlowDefinition {
  flowId: string;
  name: string;
  description?: string;
  nodes: FlowNode[];
  edges: FlowEdge[];
}

interface FlowNode {
  nodeId: string;
  nodeSchemaId: string;             // 活引用节点模型，不复制字段定义
  label: string;                    // 本节点展示名
  driverMode: "inherit" | "override" | "none";
  driverBinding?: DriverBinding;    // 仅 override 时存在，且必须整套完整（不允许部分合并）
  joinPolicy?: "all" | "any";       // 入边汇聚策略，默认 all；MVP UI 仅暴露 all
  subflow?: SubflowBinding;         // 子流程绑定（阶段二实现，协议先行）
}

interface FlowEdge {
  edgeId: string;
  sourceNodeId: string;
  targetNodeId: string;
  relation: "sequence" | "optional" | "reference";
  label?: string;
}
```

### 7.1 driverMode 三模式

| 模式 | 语义 |
|---|---|
| `inherit` | 使用节点模型的完整默认绑定；节点模型无默认绑定时等价于 `none` |
| `override` | 整套替换 `driverCode + inputBindings + completionPolicy`，不进行部分合并 |
| `none` | 不使用驱动器，默认人工生命周期 |

### 7.2 边关系语义

| 关系 | 阻塞后继 | 计入必经完成度 | 参与前序组 |
|---|---:|---:|---:|
| `sequence` 必经 | 是 | 是 | 是 |
| `optional` 可选 | 否 | 否（计入可选完成度） | 否 |
| `reference` 参考 | 否 | 否 | 否 |

- **前序组** = 某节点全部 `sequence` 入边的源节点集合，按 `joinPolicy` 判定就绪（见 [02 §7](02-状态引擎规范.md)）。
- **参与类别是推导字段**：节点若有任一 `sequence` 入边（或为入口）→ 必经；全部入边为 `optional` → 可选；全部为 `reference` → 参考。编译期推导，不重复存储，模板不可改写。
- 协议预留关系值 `conditional`（条件分支）与 `exception`（异常路径），未排期，MVP 校验层不放行。

### 7.3 开始元节点

- `nodeId` 固定为 `start` 的内置元节点，始终是流程第一个节点，不引用节点模型、无驱动器。
- 执行实例中由人工完成「开始」，其完成时刻即 `run.startedAt`。

### 7.4 子流程绑定（协议先行，阶段二实现）

```ts
interface SubflowBinding {
  flowId: string;                   // 活引用另一条流程定义
  displayMode?: "drilldown";        // MVP-阶段二 固定下钻查看
}
```

- 发布父流程时**递归固化**子流程内容（见 [03 §6](03-发布与快照规范.md)），循环引用与深度上限在发布校验中检测。
- 完成传播：子流程全部必经节点完成 → 父节点出现「子流程已达成」建议，完成动作遵循父节点 completionPolicy（阶段二内即 manual 人工确认）。

## 8. 校验层级

诊断信息必须带**对象路径、字段键 / 对象 ID 与修复建议**。

| 层级 | 内容 | 时机 |
|---|---|---|
| 1 语法 | JSON/YAML 能否解析 | 导入 |
| 2 协议 | zod schema：字段类型、必填、枚举合法值 | 保存、导入 |
| 3 引用 | `metaFieldId` / `nodeSchemaId` / `flowId` / `nodeId` 是否存在；`fieldKey` 项目内唯一；子组装合法（仅基础类型、非空、无重复引用）；`FieldValidateRuleSet` / `FieldFilterConfig` 的 `metaFieldId` 指向存在且**每个元字段至多一条**；`optionSource.kind = "field"` 时宿主必须是 enum 类型 | 保存、发布 |
| 4 图语义 | 重复 ID、自环、孤立节点、入口不可达、必经环 | 流程保存、发布 |
| 5 驱动完整性 | 必需槽位全解析、类型兼容、override 整套完整、条件树比较符合法、system 引用无自指（§5） | 保存、发布 |
| 6 发布级 | 入口存在、子流程递归循环 / 深度上限、completionPolicy 阶段限制 | 仅发布 |

## 9. 标识规则

- 字段键 `fieldKey`：小驼峰英文，项目内唯一（保存时校验），**可修改**——关联不依赖它（§1 原则 2）；`slotKey`、`driverCode` 为内置常量。
- 对象 ID（`metaFieldId`、`nodeSchemaId`、`flowId`、`nodeId`、`runId`、`ruleSetId`、`filterConfigId` 等）：系统生成的前缀短 ID（如 `mf_x7k2`、`ns_x7k2`、`flow_a1b9`、`vrs_x7k2`、`ffc_x7k2`），保证项目内唯一；`nodeId` 禁止包含 `/`——该字符保留给子流程路径前缀命名空间（[03 §6](03-发布与快照规范.md)）。
- 事件 ID 与追加序见 [02 §3](02-状态引擎规范.md)。
