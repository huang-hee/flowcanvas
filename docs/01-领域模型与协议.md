# 01 · 领域模型与协议

> 文档状态：正式方案 v1.0（2026-08-09 评审定稿）
> 依赖：[00-术语表与总览](00-术语表与总览.md)

## 1. 协议原则

1. **zod 为唯一真相源**：所有对象的协议用 zod schema 定义于 `packages/core`，TS 类型经 `z.infer` 推导，运行时校验与静态类型永不漂移。本文档中的 TS 接口是协议的可读投影。
2. **稳定键与展示名分离**：`fieldKey`、`nodeSchemaId`、`driverCode` 等稳定键为英文小驼峰，一经使用不可变更；所有面向用户的名称为中文且可随时改。
3. **配置域活引用**：配置对象之间通过稳定键引用，始终指向最新；固化只发生在发布门（见 [03](03-发布与快照规范.md)）。
4. **JSON 为主格式**：持久化、同步、导出一律 JSON；YAML 仅作为手写配置的导入格式，加载后转为同一对象模型走同一 zod 校验。
5. **禁止文本表达式**：一切「计算描述」（system 槽位、条件）都是结构化对象，由 UI 表单生成、由引擎解释，系统中不存在表达式 parser，不存在 `eval`。

## 2. 元字段 MetaField

元字段是可复用的字段定义，类似数据库字段，只定义字段本身，不决定它属于哪个节点模型。

```ts
type FieldDataType =
  | "text"        // 文本
  | "multiline"   // 多行文本
  | "number"      // 数字
  | "boolean"     // 布尔
  | "date"        // 日期
  | "datetime"    // 日期时间
  | "duration"    // 时长
  | "enum"        // 枚举
  | "link"        // 链接
  | "file"        // 文件
  | "object"      // 对象（子字段集合）
  | "list";       // 列表

interface MetaField {
  fieldKey: string;                 // 稳定键，如 title、duration、taskItems
  name: string;                     // 默认展示名（中文）
  dataType: FieldDataType;
  helpText?: string;
  defaultValue?: unknown;
  inputComponent?: string;          // 输入组件标识，由 UI 层解释
  enumOptions?: { value: string; label: string }[];   // dataType = enum
  itemType?: FieldDataType;         // dataType = list 且子项为基础类型
  itemFields?: MetaField[];         // dataType = list（对象列表）或 object 的子字段
  validations?: ValidationRule[];
}
```

### 2.1 校验规则：自定义声明式结构

用户在 UI 里配置出来的校验规则是**数据**，由引擎解释执行，不是代码，也不是 JSON Schema：

```ts
type ValidationRule =
  | { rule: "required" }
  | { rule: "minLength" | "maxLength"; value: number }     // 文本类
  | { rule: "pattern"; value: string }                     // 正则字符串，编译失败即配置错误
  | { rule: "min" | "max"; value: number }                 // 数字 / 时长
  | { rule: "minItems" | "maxItems"; value: number }       // 列表
  | { rule: "earliest" | "latest"; value: string }         // 日期类，ISO 字符串
```

规则集合按数据类型约束合法组合（zod 层校验）：如 `pattern` 只允许出现在文本类字段上。

### 2.2 示例：学习任务用到的元字段

| fieldKey | 类型 | 说明 |
|---|---|---|
| `title` | text | 标题，在不同节点模型可覆盖为「任务名称」「内容标题」 |
| `description` | multiline | 描述 |
| `documents` | list(link) | 在线文档列表 |
| `duration` | duration | 预计时长 |
| `taskItems` | list(object: `title` text, `done` boolean) | 待办子任务列表 |

## 3. 节点模型 NodeSchema

节点模型 = 元字段的集合 + 可选的默认驱动绑定。**没有版本字段**——配置对象不做多版本管理（决策 10）。

```ts
interface NodeSchema {
  nodeSchemaId: string;
  name: string;                     // 如「学习任务」「审批节点」
  description?: string;
  fieldBindings: FieldBinding[];
  defaultDriverBinding?: DriverBinding | null;  // 空 = 默认人工生命周期
}

interface FieldBinding {
  fieldKey: string;                 // 活引用元字段
  displayName?: string;             // 覆盖展示名：同一 title 在此处可叫「任务名称」
  required?: boolean;               // 覆盖必填
  defaultValue?: unknown;           // 覆盖默认值
  order: number;                    // 字段顺序
  runtimeComponent?: string;        // 覆盖执行时输入组件
}
```

## 4. 驱动方案 DriverDefinition

第一版提供三个**内置、可配置、不可脚本扩展**的驱动方案。驱动方案声明输入契约与输出契约，本身不拥有节点字段。

```ts
interface DriverDefinition {
  driverCode: "time" | "condition" | "event";
  name: string;
  inputSlots: DriverInputSlot[];
  outputContract: {
    lifecycles: Lifecycle[];        // 能产出的生命周期状态
    attentions: Attention[];        // 能产出的关注状态
  };
  supportsAutoCompletion: boolean;  // 是否支持 auto 完成模式（阶段三生效）
}

interface DriverInputSlot {
  slotKey: string;
  dataType: FieldDataType | "conditionTree" | "eventMatcher";
  required: boolean;
  allowedSources: ("field" | "system" | "constant")[];
  defaultSource?: InputSource;      // 有默认来源的槽位直接展示默认值，不出现未解析空值
}
```

### 4.1 三个内置驱动方案

| 驱动 | 输入槽位 | 输出契约 | auto 支持 |
|---|---|---|---|
| **时间驱动** `time` | `startAt`(datetime, 必需, 默认 `system(previous.readyAt)`)；`duration`(duration, 必需)；`dueSoonThreshold`(duration, 必需, 默认 `constant(24h)`) | 等待开始 / 进行中；关注：正常 / 即将到期 / 已超时 | 是（到期自动完成，阶段三） |
| **条件驱动** `condition` | `condition`(conditionTree, 必需, 仅 constant) | 等待开始 / 进行中 | 是（条件达成自动完成，阶段三） |
| **事件驱动** `event` | `activateOn`(eventMatcher, 必需, 仅 constant) | 等待开始 / 进行中 | 是（事件到达自动完成，阶段三） |

事件驱动的边界：**应用内事件 + 手动记录事件**（MVP），外部日志导入阶段三；不接收公网 Webhook；关闭期间不驻留，重开后追算。

## 5. 驱动绑定 DriverBinding

```ts
interface DriverBinding {
  driverCode: string;
  inputBindings: Record<string, InputSource>;   // key = slotKey，必需槽位必须全部出现
  completionPolicy: CompletionPolicy;
}

type InputSource =
  | { kind: "field"; fieldKey: string }                       // 节点字段
  | { kind: "system"; ref: SystemRef; offset?: DurationOffset } // 系统上下文
  | { kind: "constant"; value: unknown };                     // 固定值

type SystemRef =
  | "previous.readyAt"     // 前序组就绪时刻（见 02 §7），取代旧写法 previous.completedAt
  | "run.startedAt"        // 实例开始时刻（开始元节点完成时刻）
  | "node.activatedAt"     // 本节点进入进行中的时刻
  | "now";                 // 重算时刻

interface DurationOffset {
  value: number;                                // 可正可负
  unit: "minute" | "hour" | "day" | "week";
}
```

时间驱动默认绑定示例（三个必需槽位全部解析，无空映射）：

- `startAt ← system(previous.readyAt, +1 day)`（前序组就绪次日）
- `duration ← field(duration)`
- `dueSoonThreshold ← constant(24h)`

### 5.1 完成策略 CompletionPolicy

```ts
type CompletionPolicy =
  | { mode: "manual" }    // 纯手动：人工点完成（默认，MVP 唯一合法值）
  | { mode: "confirm" }   // 达成后待确认：驱动器达成完成条件 → 建议完成提示 → 人工确认（阶段三）
  | { mode: "auto" };     // 达成即完成：驱动器达成条件自动标记完成（阶段三，驱动器须声明支持）
```

协议 v1 携带完整枚举；**MVP 校验层只放行 `manual`**，UI 不暴露另外两个入口，阶段三开放时零迁移。

### 5.2 绑定完整性规则

- 必需槽位缺来源、字段类型与槽位类型不兼容、override 绑定不完整 → **禁止保存和发布**。
- `auto` 模式要求 `DriverDefinition.supportsAutoCompletion = true`（阶段三校验）。

## 6. 条件树

条件是任意组装的布尔结构：默认多条件平铺即 AND，混用运算符时引入组，如 `a | (b & c & d & e)`、`(a | b) & (c | d) & e`。协议不设深度上限，UI 交互见 [05 §7](05-产品规格.md)。

```ts
type ConditionNode = ConditionGroup | Condition;

interface ConditionGroup {
  op: "and" | "or";
  children: ConditionNode[];        // 递归
}

type Condition =
  | { kind: "compare";
      fieldPath: string;            // fieldKey，object 子字段用点路径，如 meta.category
      operator: CompareOperator;
      target?: unknown }            // isEmpty / notEmpty 无 target
  | { kind: "aggregate";            // 列表聚合谓词
      fieldPath: string;
      mode: "all" | "any" | "countAtLeast";
      count?: number;               // mode = countAtLeast 时必填
      item: ConditionNode };        // 子项谓词，递归使用本结构
```

「子任务全完成」示例：

```json
{ "kind": "aggregate", "fieldPath": "taskItems", "mode": "all",
  "item": { "kind": "compare", "fieldPath": "done", "operator": "eq", "target": true } }
```

### 6.1 比较符矩阵

按元字段数据类型约束合法比较符（zod 层校验非法组合）：

| 数据类型 | 合法比较符 |
|---|---|
| text / multiline | `eq` `neq` `contains` `isEmpty` `notEmpty` |
| number / duration | `eq` `neq` `gt` `gte` `lt` `lte` |
| boolean | `eq` |
| date / datetime | `before` `after` `eq`；对 now 比较：`passed`（已过）`notReached`（未到） |
| enum | `eq` `neq` `in`（属于集合） |
| link / file | `isEmpty` `notEmpty` |
| object | 取子字段路径后按子字段类型使用本矩阵 |
| list | 聚合谓词 `all` / `any` / `countAtLeast`；长度用 `lengthGte` / `lengthLte` |

## 7. 流程定义 FlowDefinition

流程页面负责组合节点和连线，**不保存执行状态**。

```ts
interface FlowDefinition {
  flowId: string;
  name: string;
  description?: string;
  nodes: FlowNode[];
  edges: FlowEdge[];
}

interface FlowNode {
  nodeId: string;
  nodeSchemaId: string;             // 活引用节点模型，不复制字段定义
  label: string;                    // 本节点展示名
  driverMode: "inherit" | "override" | "none";
  driverBinding?: DriverBinding;    // 仅 override 时存在，且必须整套完整（不允许部分合并）
  joinPolicy?: "all" | "any";       // 入边汇聚策略，默认 all；MVP UI 仅暴露 all
  subflow?: SubflowBinding;         // 子流程绑定（阶段二实现，协议先行）
}

interface FlowEdge {
  edgeId: string;
  sourceNodeId: string;
  targetNodeId: string;
  relation: "sequence" | "optional" | "reference";
  label?: string;
}
```

### 7.1 driverMode 三模式

| 模式 | 语义 |
|---|---|
| `inherit` | 使用节点模型的完整默认绑定；节点模型无默认绑定时等价于 `none` |
| `override` | 整套替换 `driverCode + inputBindings + completionPolicy`，不进行部分合并 |
| `none` | 不使用驱动器，默认人工生命周期 |

### 7.2 边关系语义

| 关系 | 阻塞后继 | 计入必经完成度 | 参与前序组 |
|---|---:|---:|---:|
| `sequence` 必经 | 是 | 是 | 是 |
| `optional` 可选 | 否 | 否（计入可选完成度） | 否 |
| `reference` 参考 | 否 | 否 | 否 |

- **前序组** = 某节点全部 `sequence` 入边的源节点集合，按 `joinPolicy` 判定就绪（见 [02 §7](02-状态引擎规范.md)）。
- **参与类别是推导字段**：节点若有任一 `sequence` 入边（或为入口）→ 必经；全部入边为 `optional` → 可选；全部为 `reference` → 参考。编译期推导，不重复存储，模板不可改写。
- 协议预留关系值 `conditional`（条件分支）与 `exception`（异常路径），未排期，MVP 校验层不放行。

### 7.3 开始元节点

- `nodeId` 固定为 `start` 的内置元节点，始终是流程第一个节点，不引用节点模型、无驱动器。
- 执行实例中由人工完成「开始」，其完成时刻即 `run.startedAt`。

### 7.4 子流程绑定（协议先行，阶段二实现）

```ts
interface SubflowBinding {
  flowId: string;                   // 活引用另一条流程定义
  displayMode?: "drilldown";        // MVP-阶段二 固定下钻查看
}
```

- 发布父流程时**递归固化**子流程内容（见 [03 §6](03-发布与快照规范.md)），循环引用与深度上限在发布校验中检测。
- 完成传播：子流程全部必经节点完成 → 父节点出现「子流程已达成」建议，完成动作遵循父节点 completionPolicy（阶段二内即 manual 人工确认）。

## 8. 校验层级

诊断信息必须带**对象路径、稳定键与修复建议**。

| 层级 | 内容 | 时机 |
|---|---|---|
| 1 语法 | JSON/YAML 能否解析 | 导入 |
| 2 协议 | zod schema：字段类型、必填、枚举合法值 | 保存、导入 |
| 3 引用 | `fieldKey` / `nodeSchemaId` / `flowId` / `nodeId` 是否存在 | 保存、发布 |
| 4 图语义 | 重复 ID、自环、孤立节点、入口不可达、必经环 | 流程保存、发布 |
| 5 驱动完整性 | 必需槽位全解析、类型兼容、override 整套完整、条件树比较符合法 | 保存、发布 |
| 6 发布级 | 入口存在、子流程递归循环 / 深度上限、completionPolicy 阶段限制 | 仅发布 |

## 9. 标识规则

- 稳定键（`fieldKey`、`slotKey`、`driverCode`）：小驼峰英文，创建后不可改。
- 对象 ID（`nodeSchemaId`、`flowId`、`nodeId`、`runId` 等）：系统生成的前缀短 ID（如 `ns_x7k2`、`flow_a1b9`），保证项目内唯一。
- 事件 ID 与追加序见 [02 §3](02-状态引擎规范.md)。
