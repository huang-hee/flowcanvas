# 06 · 实施计划

> 文档状态：正式方案 v1.0（2026-08-09 评审定稿）
> 依赖：全部前置文档。

## 1. 代码结构（monorepo）

pnpm workspaces：

```text
flowcanvas/
├── packages/
│   └── core/                 # 零浏览器依赖，可独立测试
│       ├── schema/           # zod 协议：MetaField / NodeSchema / Driver* / Flow* / Event / .flowpack 信封
│       ├── engine/           # recompute 纯函数、驱动器计算、条件树求值、前序组解析、完成度统计
│       ├── publish/          # 发布校验、递归固化、contentHash
│       ├── diagnostics/      # 六层校验与诊断信息（对象路径 + 修复建议）
│       └── ports/            # StorageAdapter / SyncProvider 接口定义
├── apps/
│   └── web/                  # React SPA：配置中心 + 执行页
│       ├── adapters/         # IndexedDBAdapter、GoogleDriveProvider（阶段二）
│       ├── canvas/           # React Flow 封装（画布库数据结构不出此目录）
│       └── …
└── docs/
```

技术栈：React + TypeScript + Vite + React Flow 封装 + zustand + IndexedDB。跨端预选 webview 壳路线（Capacitor/Tauri 阶段三选型时查官方文档再定）；`core` 保持零浏览器依赖，存储与同步全部走 `ports/` 适配器接口。

## 2. 阶段划分

### 阶段一 · 本地闭环（覆盖验收 1–12）

按依赖顺序：

1. monorepo 骨架 + CI（lint / typecheck / test）。
2. `core/schema`：全部 zod 协议 + 协议测试。
3. `core/engine`：事件模型 → recompute → 驱动器计算（时间/条件/事件）→ 前序组 → 完成度；**确定性与追算测试先行**。
4. `core/publish` + `core/diagnostics`：六层校验、递归固化（子流程校验规则就位，UI 阶段二）。
5. `apps/web` 骨架 + IndexedDBAdapter。
6. 配置中心：元字段页 → 节点模型页（四步驱动编辑）→ 驱动方案页 → 流程页面（画布）→ 配置总览页。
7. 发布流程 + 执行实例页（含时间模拟、缺值受阻补值、手动记录事件、撤销操作）。
8. `.flowpack` 导出/导入。

### 阶段二 · 同步与子流程（覆盖验收 13–14）

1. **前置查证**：Drive v3 条件写入实测、GIS 纯前端授权、appDataFolder 限制（[04 §8](04-存储与同步规范.md)）。
2. GoogleDriveProvider + 同步状态机 + SyncBaseline + 冲突三选一 UI。
3. 子流程：绑定 UI、发布递归固化、执行页下钻、完成建议传播。

### 阶段三 · 扩展（未逐项排期）

- `confirm` / `auto` 完成模式（校验放行 + 达成判定接入 + 建议完成交互）。
- 外部事件日志导入（JSON 格式定稿 + 去重规则）。
- 多视图渲染器（roadmap / 时间轴等，按需求择取）。
- webview 壳跨端（Capacitor/Tauri 选型）与移动端适配。
- 线上化分享链接（取代已砍掉的独立 HTML 导出）。
- 候补：`joinPolicy: any` UI、嵌套汇聚组、条件分支/异常边、基于日志的冲突智能合并、checkpoint。

## 3. MVP 验收标准（评审定稿）

1. 可创建元字段（覆盖全部数据类型）并组装节点模型，展示名可覆盖。
2. 配置域活引用：改元字段即时反映到节点模型与流程草稿，且有影响提示。
3. 节点模型可绑定默认驱动（时间 / 条件 / 事件 / 无）；必需槽位未完整解析时禁止保存。
4. 画布可视化编排：建节点、连线（必经/可选/参考）、`inherit / override / none` 三模式，override 必须整套配置。
5. 条件驱动支持任意组装的条件树（and/or 混用）。
6. `joinPolicy: all` 多前序汇聚正确；`previous` 解析为前序组就绪时刻。
7. 发布校验全绿才能发布；FlowVersion 完全自包含；发布后改配置不影响已有实例。
8. 从快照创建实例；生命周期六态 + 关注状态正确；三权分立成立；**MVP 内完成一律人工**。
9. 一切状态变化走事件日志；**关闭重开后的追算结果与持续在线完全一致**（确定性验证）。
10. 缺字段值 → 受阻 + 指明缺失字段 + 补值后重算恢复，无静默降级。
11. 时间驱动可模拟正常 / 临期 / 超时三态。
12. `.flowpack` 单文件导出，导入后完整恢复项目（含日志）。
13. Drive 同步：上传 / 下载 / 分叉检测进冲突三选一，永不静默覆盖。（阶段二）
14. 子流程：节点引用另一流程、发布时递归固化、下钻查看、完成传播。（阶段二）

## 4. 测试策略

| 测试层 | 重点 | 位置 |
|---|---|---|
| 协议测试 | zod schema 字段、默认值、非法组合（比较符矩阵、阶段限制） | core/schema |
| 条件树求值 | and/or 任意组装、聚合谓词、缺值行为 | core/engine |
| 图语义 | 重复 ID、自环、孤立、不可达、必经环、joinPolicy | core/diagnostics |
| 状态引擎确定性 | 同（快照, 日志, now）同输出；**追算 = 在线**（分段推进 now 与一次性推进结果一致）；撤销回退传播 | core/engine |
| 驱动器计算 | 时间三态与关注状态、条件激活、事件匹配、previous 解析 | core/engine |
| 发布与固化 | 六层校验、inherit 展开、递归固化、contentHash 稳定性、循环/深度拒绝 | core/publish |
| 存储往返 | `.flowpack` 导出→导入等价；IndexedDB 读写；投影缓存丢弃重建 | apps/web |
| 同步契约 | 上传/下载/分叉判定/冲突三选一/授权过期（Provider 用假实现测状态机） | apps/web |
| 视觉回归 | 关键页面不同状态截图（配置总览、画布、执行页三态模拟） | apps/web |

## 5. 性能预算

- 目标规模：单流程 ≤ 300 节点，单实例日志 ≤ 10,000 条。
- 全量重算目标 < 50ms（内存内纯计算）；周期 tick 60s；超预算再启用 checkpoint 扩展点（[02 §3.2](02-状态引擎规范.md)），不提前优化。
- 画布大图：React Flow 按视口渲染能力评估放在阶段三多视图时一并处理。

## 6. 风险清单

| 风险 | 缓解 |
|---|---|
| Drive v3 条件写入不支持（未确认） | 两级安全线已设计降级路径（[04 §5](04-存储与同步规范.md)）；阶段二第一件事就是实测 |
| 事件溯源纪律被破坏（直接改状态字段的诱惑） | core 不导出任何状态写入口，只导出「追加事实」API；code review 守门 |
| 条件组构建器交互复杂度 | 交互规格已定（[05 §7](05-产品规格.md)）；先实现数据层与人类可读预览，UI 迭代 |
| React Flow 版本/API 假设失效 | 实施前查官方文档（全局规约）；画布库数据结构封死在 `apps/web/canvas` 内 |
| 纯前端 OAuth 流程变化 | 阶段二前置查证项；同步失败不影响本地功能 |
